## Результаты по кандидатам

### ST14-001 — клавиатурный ввод в UI активирует игровые действия — **CONFIRMED_FIXED**

- Префикс (статика): ~24 sticky-действия опрашивались в _PhysicsProcess
  безусловно (гейты !_isOverUI только у cast/attack/defend/cycle/hotbar);
  GuiGetFocusOwner — 0 вызовов в game/src; набор имени сейва с E/B/J/K/H/
  T/V/цифрами запускал медитацию/окна/экипировку/техники (SaveLoadMenu.
  _newSlotEdit без focus-менеджмента).
- Фикс: InputAdapter._PhysicsProcess — фактический фокус Godot
  (`GuiGetFocusOwner()`; LineEdit/TextEdit/CodeEdit/SpinBox) глушит ВСЕ
  игровые sticky + движение + хотбар ( PushFrame-нулевка и ранний return);
  мышь не тронута. Проверка — фокус, не положение мыши (поле держит фокус
  при уходе курсора — сценарий §3.5 задания).
- Постфикс: A1 фокус→глушение ✓; A2a V-медитация 0 событий ✓; A2b B не
  открыл окно ✓; A2c E без скрытых взаимодействий ✓; A3 контроль — после
  снятия фокуса B открывает инвентарь ✓.

### ST14-002 — рассогласованы проверки модального состояния — **CONFIRMED_FIXED**

- Префикс (статика): три списка расходились — AnyModalWindowOpen (12 окон),
  локальный modalOpen в _UnhandledInput (без charger и saveLoadMenu —
  утечка зума/кликов), список SetOverUI (без charger — атака/каст/хотбар

  не зависит только от Time.IsPaused).
- Постфикс: B — 9 окон (inventory/characterSheet/quest/eventLog/hotkeys/
  techniqueBook/cultivation/saveLoad/charger) × (AnyModal ∧ WorldMouseBlocked)
  ✓✓; базовая линия (все закрыты → оба false) ✓.

### ST14-003 — Esc закрывает не фактически верхнее окно — **CONFIRMED_FIXED (ядро)**

- Префикс (статика): жёсткая if/else-цепочка идентификаторов (hotkeys→…→
  inventory ПОСЛЕДНИМ): при T открытом поверх B Esc бил по книге (нижней),
  инвентарь висел. «Паузная» часть кандидата опровергнута пре-верификацией
  (централизованный HandleModalResumeOnClose) — подтверждена регрессией C4.
- Фикс: стек фактического порядка открытия (`_modalOpenSeq` по времени;
  UpdateModalStack каждый HandleStickyInput): Esc → (1) попапы инвентаря
  (CloseTopmostPopup — правило 2026-09-09 сохранено), (2) верхнее окно
  стека, (3) пауза — только при пустом стеке. Закрытия — те же
  централизованные пути (INP-1); UX-дизайн не менялся молча — правило
  «верхнее закрывается первым» прямо следует из формулировки задания
  («порядок закрытия окон и вложенных попапов клавишей Esc»); случай
  равноприоритетных НЕЗАВИСИМЫХ окон стеком не возникает (порядок всегда
  определён временем открытия).
- Постфикс: C1 T→B: Esc закрыл B, книга жива ✓; C2 второй Esc — книга ✓;
  C3 B→T: первым закрыт T, вторым B ✓ (оба порядка — верхний первый);
  C4 инвариант: T (игровой путь, клавиша) поверх пред-существующей паузы →
  Esc-закрытие НЕ сняло паузу (снапшот _wasPausedBeforeInventory) ✓.

### ST14-004 — переходы диалога оставляют неконсистентный UI/паузу — **DISPROVED (как дефект) + edge FIXED**

- Пре-верификация: все выходы уже унифицированы (Phase 2: Esc/выбор/торговля
  → EndDialogue → DialogueEndedEvent → гейтовый resume; typewriter полный
  сброс). Дефекта НЕТ — пере-скоуп в регресс-покрытие.
- Латентный edge (единственный реальный хвост): GoToNode на несуществующий
  узел молча оставлял старый текст («призрачный» узел). Фикс: диагностика +
  честный EndDialogue (окно закрывается, DialogueEndedEvent, резюм —
  централизованный гейт).
- Постфикс: F1 полный игровой путь (MapNpcDialogue + DialogueDebugOpen:
  старт ✓, окно открыто ✓); F2 переход на ghost_node → окно закрыто,
  DialogueEnded +1 ✓. Базовые переходы диалога покрыты DIALOGUE-симом
  (не дублировались).

### ST14-005 — E попадает в неправильный контекст — **CONFIRMED_FIXED (ядро)**

- Префикс (статика): E-цепочка гейтилась только на trade/loot/dialogue →
  E поверх меню сейвов/зарядника/листов запускал скрытые обыск/разговор/
  подбор. Подозрение дублей опровергнуто пре-верификацией (однокадровый
  sticky, единственный читатель).
- Фикс: `else if (AnyModalWindowOpen())`-гейт после легитимных веток
  trade/loot/dialogue (E над планировочными окнами съедается модальностью).
- Постфикс: D1 E при открытом меню сейвов — диалог/обыск не открылись ✓;
  D2 контроль — меню закрыто, предикаты пускают E к миру ✓. Приоритет
  «труп-vs-NPC» и позитивные пути покрыты LOOT/QUEST-симами (не дублировались).

### ST14-006 — потеря/возврат фокуса приложения — **CONFIRMED_FIXED (контракт) / OS-путь — NOT TESTED (физический)**

- Префикс (статика): обработки потери фокуса не существовало ВООБЩЕ (0
  переопределений _Notification; ActionRelease только в тест-симах);
  уязвимы held-состояния (move/run/ЛКМ/ПКМ/_rmbHoldDuration) — одно-кадровые
  sticky залипать не могут (опровергнуто пре-верификацией).
- Фикс: `NotificationApplicationFocusOut` → release ВСЕХ игровых действий
  (41 action — иначе опрос следующего кадра снова видит «нажатые» клавиши
  и held-стейт переживает потерю фокуса) + немедленный нулевой кадр
  (движение/бег/ПКМ-длительность сброшены в тот же тик).
- Постфикс: E1 held активен (move≠0, run=true) ✓; E2 после QaSimulateFocusLoss
  (клавиши ЕЩЁ зажаты) — move=(0,0), run=false ✓; E3 контроль — новое
  нажатие двигает (после возврата фокуса действие только по актуальному
  вводу) ✓. **Реальный OS-путь (alt-tab) headless невоспроизводим —
  физический PT-U06; статус OS-части: NOT TESTED до плейтеста владельца.**

# Чекпоинт R10 — SlotId-адресность инвентаря (TOCTOU-защита)

**Дата:** 2026-09-09 (сессия R10, восстановление после обрыва)
**Коммит:** `756fd79` (push: 12e28e2..756fd79, HEAD == origin/main)

## Контекст

Внешнее ревью №1 (ChatGPT-агент) нашло TOCTOU в адресации кучек инвентаря:
UI захватывал **индекс слота** при рендере/открытии диалога, а действовал по
нему позже — за это время инвентарь мог мутировать (индекс дрейфует), и
фолбэк `DropItemOnGround(itemId)` удалял **ВСЕ** кучки предмета
(деструктивная потеря).

Обрыв сессии: код был готов (7 файлов, 415 вставок), но не закоммичен.
Восстановлено из рабочего дерева, верифицировано, закоммичено, запушено.

## Реализация

- `InventorySlot` (Structs.cs): `SlotId` (Guid) — стабильная идентичность
  кучки; конструктор без SlotId = создание (новый Guid), со SlotId =
  модификация (идентичность сохраняется); `WithCount()`.
- `IInventoryService`/`InventoryService`: `FindSlotIndexBySlotId`,
  `TrySplitSlot(slotId, expectedItemId, moveCount)`,
  `TryRemoveFromSlot(slotId, expectedItemId, count)` — отказ при
  исчезновении/подмене кучки, деструктивный фолбэк запрещён.
- Мутации стака (`TryAddItem` заполнение/слияние, `RemoveItem` частичное
  изъятие, `TrySplitSlot`) — через `WithCount` (SlotId переживает мутации).
- UI: drag-data несёт `slot_id` (Guid-string); `TrashDropZone` при
  отсутствии slot_id → ОТКАЗ (лог, не выброс всего предмета);
  `SplitStackDialog`/`ItemContextMenu` действуют по SlotId+ItemId.
- Stale-сценарии → тост «Стак изменился — операция отменена».

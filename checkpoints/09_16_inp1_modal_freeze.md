# INP-1 — модальная пауза: bg-click-закрытие инвентаря замораживало мир

**Дата:** 2026-09-16
**Источник:** баг-репорт пользователя (локальное тестирование сборки `1537c5e`):
«если открыть инвентарь и потом его закрыть — перестаёт работать любое
движение!!! Ни клавиши, ни мышь не реагируют, персонаж стоит на месте».

## Диагноз (P0, game-breaking)

Цепочка:

1. B → `GameWorldController` (GWC) инвентарь-хендлер: `Toggle()` → окно
   открыто → `_wasPausedBeforeInventory = false; Time.Pause()`.
2. Пользователь закрывает окно **кликом по тёмному фону** — самый
   естественный путь: `InventoryWindow.OnBackgroundClick`
   (InventoryWindow.cs:230) → `Toggle()` **внутри окна, мимо GWC**.
   `Time.Resume()` не вызывается никем.
3. `Time.IsPaused` висит `true` навсегда → `HandleFreeMovement` выходит на
   первой же проверке (GameWorldController.cs, «Check if paused — no
   movement when paused») → **ни WASD, ни click-to-move** (мышь ставит
   `_mouseTarget`, но движение к цели — в том же замороженном цикле).
4. Тот же скрытый путь закрытия у `CharacterSheetWindow` (C,
   CharacterSheetWindow.cs:170) — тот же фриз.

Сопутствующий дефект той же семьи (латентный, stacked-окна): открытие
второго окна поверх первого **перезаписывало** снапшот
`_wasPausedBeforeInventory` (уже `true` — пауза от первого окна), и после
закрытия обоих миров оставался заморожен (диалог поверх инвентаря и любые
комбинации). Гвард-комментарий R13-audit P2-2 закрывал только пару
«B + LootWindow», не весь стек.

## Фикс (паттерн R13-audit P1-2 «Closed-событие — единая точка»)

Файлы: `GameWorldController.cs`, `InventoryWindow.cs`,
`CharacterSheetWindow.cs`.

1. **Closed-события у окон с внутренними путями закрытия**
   (`public event Action? Closed;`, fire в `Toggle()` на закрытии —
   единственной мутации видимости; `_Ready`-инициализация не считается).
   GWC подписывается при создании: `_inventoryWindow.Closed +=
   HandleModalResumeOnClose;` (и для char sheet). Побег из окна ЛЮБЫМ
   путём (B/Esc/фон) доходит до одной точки.
2. **Центральные хелперы GWC** (заменили 15+ разрозненных inline-блоков):
   - `AnyModalWindowOpen()` — все 9 модальных окон (6 по `Visible`:
     инвентарь/лист/квесты/журнал/справка/книга техник; 3 по `IsOpen`:
     обыск/лавка/диалог; Культивация K сознательно НЕ входит — не паузит);
   - `HandleModalPauseOnOpen(bool otherModalAlreadyOpen)` — пауза при
     открытии; **снапшот «мир был запаузен вне окон» только при входе
     ПЕРВОГО окна стека** (открытие поверх — флаг не трогает);
   - `HandleModalResumeOnClose()` — **резюм только когда стек опустел** и
     пауза ставилась ради окон; идемпотентен (Closed-событие + inline-ветка
     клавиши на одном закрытии — двойной вызов безопасен).
3. **Esc-каскад**: + ветка «лист персонажа» (раньше Esc под C-окном снимал
   паузу — окно висело поверх бегущего мира); финальная ветка паузы теперь
   гейтится `!AnyModalWindowOpen()` вместо проверки одного инвентаря
   (раньше Esc под Q/J/F1/T снимал паузу под висящим окном).
4. **modalOpen в `_UnhandledInput`**: + окна квестов (Q) и журнала (J) —
   утечка колеса зума при непрокручиваемом списке.
5. `DialogueDebugOpen` (QA-путь) переведён на хелперы.

Покрытые пути открытия/закрытия: B/C/E/F1/J/Q/T (toggle), Esc-каскад
(10 веток), E→обыск, E→диалог (+Advance), TradeOpened/TradeClosedEvent,
DialogueEndedEvent, CorpseRemovedEvent→OnLootWindowClosed, bg-click
(инвентарь/лист персонажа), PageUp/PageDown (аварийный резюм — сохранён).

## Семантика после фикса (инварианты)

- Время на паузе ⇔ (стек модальных окон непуст) ∨ (явная пауза игрока Esc).
- Esc-пауза при открытых окнах НЕ снимается (сначала каскад закрывает окна).
- Снятие паузы игрока Esc'ом сохраняется при открытии/закрытии окон поверх.
- QA-симы (ContextMenu/TrashDrop зовут `win.Toggle()` напрямую): Closed
  стреляет, но `HandleModalResumeOnClose` в headless-контексте без паузы —
  no-op (гварды `Time is { IsPaused: true }`).

- Полная регрессия 15 симов через `tools/qa_regression.sh`

  (стек); Esc-пауза→B→bg-click (пауза игрока сохраняется).

## Остаток (не-INP, осознанно)

- Каскад Esc не включает Культивацию (K) — окно не паузит, закрывается
  K/bg-click; Esc под ним переключает паузу (задокументировано).
- F5/F9 по-прежнему отключены (Q8) — отдельное решение о включении
  быстрого сейва после стабилизации R17-системы (см. R17-чекпоинт).

## Контекст

Архитектура игры — Hub-and-Spoke: единственный канал межмодульного
взаимодействия — центральная шина из двух каналов:

- **EventBus** (`IPublisher<T>` / `ISubscriber<T>`, readonly struct-события,
  zero-GC) — 163 контракта в `Core/Messaging/Contracts/` (27 файлов-групп);
- **DI-контейнер** (`ContainerBuilder` / `IResolver`, `[Inject]`,
  `ResolveAll`) — 160 регистрация/запросов.

До сих пор полнота шины проверялась только аудитами вручную (находки вида
«событие публикуется, но никто не слушает»). Прочитан контекст: START_PROMPT
(§6 чекпоинты, §8 worklog), docs_v2 (архитектура Core, EventBus, DI),
примеры аудиторских находок в bugs.json.

## Решения

- **Снимок, не живой анализ** — директива владельца: карта обновляется
  только по требованию. Генератор в git, `--check` закрывает риск дрейфа;
  снимок коммитится вместе с кодом игры.
- **busMap — опциональное поле API** — отсутствие bus_map.json не роняет
  портал (ok не зависит) — та же деградация, что у bugs/status.
- **QA-харнессы исключены из продакшн-проверок полноты** — иначе
  тестовые слушатели маскируют «осиротевшие» события (событие считается
  потреблённым, хотя в проде его никто не слушает).
- **Панель вкладок скроллится, а не переносится** — 4 вкладки в 390px не
  помещаются даже без бейджей; горизонтальный свайп-скролл — стандартный
  паттерн, высота строк стабильна.

## Найденные проблемы (содержимое снимка — к сведению владельца)

- 9 событий подписаны, но не публикуются (все — input/UI-адаптеры:
  InputActionEvent, InputKeyEvent, LoadRequestedEvent, SaveRequestedEvent,
  UIInteract/Pause/Resume/StateChangeRequest, CultivationWindowToggle) —
  вероятно, публикуются Godot-стороной вне поля статического анализа;
  стоит сверить вручную.
- 38 событий публикуются без продакшн-подписчиков (уходят «в пустоту»);
- 5 сервисов зарегистрированы, но не запрашиваются (мёртвые регистры);
- 21 контракт объявлен, но не используется (ни pub, ни sub);
- 0 неразрешённых DI-требований, 0 сообщений вне Core-контрактов — чисто.

## Следующие шаги

- Владелец просматривает списки «проверки полноты» на вкладке — кандидаты
  в реестр bugs.json (осиротевшие события/сервисы);
- После любых правок кода игры: `python3 tools/gen_bus_map.py --check`

- Restore-проверка не требуется: каркас восстанавливается

## Итерация 2 (2026-10-21 11:30 UTC): каталог контрактов + всплывающие сводки

**Директива владельца:** «нет всплывающих окон или подменю с контрактами на
шину, что отдаёт и что запрашивает — только количественные значения. Хочу
видеть глубже этот набор данных».

Проблема: дефолтный вид вкладки — сводка хаба (каналы с суммарными числами);
панель с именами открывалась только кликом по узлу, но до каталога самой
шины (163 контракта / 160 сервисов) не было никакой детализации.

### Что сделано

- **`bus-catalog.tsx`** (новый компонент, хаб-вид панели): поимённый каталог
  ВСЕХ контрактов — режимы «События» (165: 144 в обороте + 21 мёртвый) и
  «Сервисы» (201 имя: регистрации, конфиги, self, резолв по конкретному
  типу, ResolveAll-коллекции). Каждая строка: имя + → кто кладёт в шину
  (файлы в подсказках) + ← кто забирает. Проблемные кверху: красный «нет
  издателя» (9), янтарный «нет прод-подписчиков» (38, флаг «только
  QA-слушатели»), серый «мёртвый контракт» (21), «мёртвый регистр» (5).
  Чип «только проблемы», поиск (по имени И по участникам), счётчик
  «показано N из M». Агрегация на клиенте из nodes[]+checks[] снимка —
  формат bus_map.json НЕ менялся.
- **Всплывающая сводка на схеме** (`bus-diagram.tsx`): наведение на узел —
  popup с именами контрактов (→ Publish/→ Register/← Subscribe/← Resolve,
  по 4 имени + «+N»), позиционирование по scale (ResizeObserver), флип
  сверху/снизу, clamp по краям; a11y-подпись узлов сохранена через
  aria-label (нативный <title> убран — не двоить тултипы).
- **Терминологическая честность** (каталог сервисов): строки с 0
  by-name-потребителей, не помеченные генератором как мёртвые, показывают
  «потребляется косвенно (ResolveAll / по типу)» вместо «никто не снимает» —
  генератор's unconsumed-проверка авторитетна (пример: AnimalSpawnPhase
  собирается через ResolveAll<ISceneAssemblyPhase>).
- **Фикс шапки на 390px**: кластер бейджей (сборка+«обновлено», 416px) —
  убран shrink-0, добавлены min-w-0+flex-wrap+justify-end: бейджи
  переносятся внутри кластера, документ не тянет по горизонтали.

поиск «Damage» → 4 строки, «NPC» → по участникам (AttitudeChangedEvent

### Решения

- Агрегация на клиенте, а не в генераторе — снимок «по требованию» не
  деградирует: каталог строится из уже собранных nodes/checks, нулевой
  дрейф-риск между форматом и UI.
- Ранжирование «проблемы кверху» вместо фильтра по умолчанию — владелец
  видит здоровье шины сразу, здоровая масса не мешает (поиск/чип для фокуса).

## Результаты по сценариям канона (ST11-001..007)

### ST11-001 — P1 ПОДТВЕРЖДЁН и исправлен (A1-A4)
Префикс: `RequestPlayerRespawn` передавал дефицит красной HP в `HealPart`
(70/30-сплит): голова после возрождения 35/50, торс 73/100; частично
леченная vital-часть меняла исход `PlayerService.Revive()` (голова >0 →
vital-восстановление не запускалось). Норма DEATH_AND_LOOT §4.2 «полное
лечение до RedHP=max». Фикс: доменный путь полного восстановления
`IBodyService.HealPartToFullRed` (100% в красную HP, ампутации не трогает —
их контракт ReattachPart); GWC использует его. Постфикс A1: все
неампутированные части RedHP=max, PlayerReviveEvent ровно 1; A3:
ампутация некритической части сохраняется (не приживляется молча).

### ST11-002 — P1 ПОДТВЕРЖДЁН и исправлен (B1-B4)
Префикс: `BodyService` — singleton без `IWorldResettable` (B1 FAIL);
`WorldDomainResetCoordinator.ResetAll` (34 домена) не трогал тело — Torso
0/100 и ампутация переживали «New Game» (B2/B3 FAIL). Фикс:
`BodyService : IWorldResettable` — `ResetWorld()` ПЕРЕСОЗДАЁТ тело из
конфигурации последней `Initialize` (морфология/материал/размер/Vitality,
+`_lastVitality`), чистит `LastDamageSourceId`, NPC-тела, реген-аккумулятор —
не зависит от повторного `BodyModule.Start()` (P1-10 resume его не зовёт);
`SeveredDebuffSystem : IWorldResettable` чистит `_activeDebuffs`.
Постфикс: B1-B4 PASS (тело свежее после ResetAll, повторный цикл ×2
безопасен, дебаффы/блокировки чисты).

### ST11-003 — P2 ПОДТВЕРЖДЁН и исправлен (C1-C6)
Префикс: Initialize клал ВСЕ отсутствующие по морфологии типы в
`_severedParts`, `IsSlotBlocked` блокировал по любой части обратного
маппинга → **гуманоид терял WeaponMain** (отсутствует RightWing!),
гарпия не могла держать оружие крыльями; 32 расхождения матрицы.
Фикс: набор `_morphologyMissingParts` (отдельно от реальных ампутаций) +
перегрузка `BodySlotMapping.IsSlotBlocked(slot, severed, morphologyMissing)`:
отсутствующая по морфологии часть НЕ блокирует слот, разрешённый
альтернативной анатомией; реальная ампутация блокирует; слот без анатомии
вовсе закрыт (BD-23: змея — без оружия); слоты без телесного маппинга
(Amulet/Ring/Belt) — не телесный гейт. Постфикс: матрица
10 морфологий × все слоты = 0 расхождений; паук (хелицеры/педипальпы),
гарпия (крылья-манипуляция), змея — по канону; ампутация хелицер
блокирует только WeaponMain, приживление возвращает.

### ST11-004 — GAP (D1-D3, решение за владельцем)
`HealthRegen` (HoT) лечит ТОЛЬКО торс (`BodyModule.OnBuffTicked` →
`HealPart(Torso)`, TODO P1-08 в коде). Пассивная регенерация (D1/D2 PASS)
лечит красную HP всех неампутированных частей, ампутированные исключены.
Спецификация распределения HoT по частям отсутствует → GAP: решение о
распределении (торс-только / пропорционально ранам / приоритет vital) —
за владельцем. Поведение НЕ переписывалось.

### ST11-005 — GAP (E1/E2, предложение владельцу)
Смерть = Head|Heart (BODY_SYSTEM §5.3.1, R20). Гуманоид: голова→0 = мёртв
(E1 PASS — единое правило тел работает). Amorphous (ghost/elemental:
Core+Essence, без Head/Heart): Core red 0/100 → `IsEntityAlive` = TRUE —
бесформенная сущность переживает разрушение ядра. Спецификация фатальность
Core не определяет (IsVital ≠ смертность — прецедент R20: торс).
Предложение: (а) считать IsVital-часть без Head/Heart (Core) фатальной,
либо (б) зафиксировать бессмертие духа документом. Правка без решения
владельца не производилась.

### ST11-006 — проверен (F1-F5 PASS)
Round-trip `CaptureState/RestoreState`: точное восстановление red/black/
state включая ампутацию (SetHP 0/0 → Severed по MaxBlackHP>0), второй
round-trip стабилен; неизвестный partType — по-записный пропуск без
исключения; отрицательные/завышенные HP клампятся `BodyPart.SetHP` в
[0;Max]; неполный блок поверх СВЕЖЕГО тела (порядок LoadGame: ResetAll →
RestoreState, работает благодаря ST11-002-фиксу) = свежая часть, раны
прошлого мира не протекают (F5). Примечание: журнал пропуска повреждённых
записей тела уже информативен (морфология-мисматч), по-записная диагностика
partType — улучшение на будущее.

### ST11-007 — ПОДТВЕРЖДЁН и исправлен (G1-G5)
Префикс: (1) приживление части не снимало блокировку слота НИКОГДА
(EquipmentService не был подписан на BodyPartReattachedEvent — G3 FAIL);
(2) LoadGame: RestoreState блока body не публикует событий →
`_blockedSlots` пуст и ампутационные дебаффы игрока пропадали при
загрузке (G4 FAIL: тело ампутировано — слот свободен, штрафа нет).
База работает (G1/G2 PASS в префиксе): авто-съём ровно один,
EquipmentBlockedEvent=1, предмет в инвентаре, дубликат события — без
дубля). Фикс: `EquipmentService.OnBodyPartReattached` (пересчёт
`_blockedSlots` по фактическому телу — слот остаётся закрытым только при
другой ампутации на нём) + `IPostLoadSync` на `EquipmentService`
(пересборка блокировок по восстановленному телу через Core-контракт
`IBodyService.GetBlockedSlotsForPart`, без ссылки на Modules.Body) +
`IPostLoadSync` на `SeveredDebuffSystem` (повторное применение
ампутационных дебаффов игрока, идемпотентно) + идемпотентный guard
`OnPartSevered`. События при RestoreState сознательно НЕ публикуются
(иначе авто-съём создавал бы дюпы между восстановлением блоков).
Постфикс G1-G5 PASS; LoadGame: нога ампутирована, слот Legs заблокирован,
дебафф активен, щит 1/1 (без дюпа).

# Чекпоинт: R14 — правило восполнения населения (§2.4)

**Дата:** 2026-09-10 09:10 UTC
**Сессия:** cloud-agent (Z.ai Code), продолжение R13-VERIFICATION-0910
**Тип:** fix (дизайн-правило по прямому запросу пользователя)

## Контекст

DEATH_AND_LOOT.md §2.4 (введено в R13) описывал `ReinforcementTick`: каждые
45 игровых секунд при живых NPC < 60% целевого населения спавнился новый NPC.
Пользователь признал это НЕКОРРЕКТНЫМ по своей логике мира:

> «Восполнение населения — не должно работать в рамках сессии. Пока
> персонаж в локации, в ней не генерируются новые NPC, кроме случая
> прихода каравана, нападения на локацию или другого ивент события.
> Естественное восстановление NPC происходит только при отсутствии
> персонажа в поселении (он в другом поселении или на карте мира)».

Документация проекта это правило уже содержит (пользователь прав):
TRANSITION_SYSTEM.md §5.3 «таймер памяти» + §11.1: NPC — полу-персистентны,
«возврат» через 1 игровой день ПОСЛЕ ухода игрока. Код R13 противоречил
докам → по workflow §3.3 «код ≠ доки = баг» → фикс кода + синхронизация.

## Что сделано

1. **NPCSpawnCompositionService**: удалён периодический `ReinforcementTick`
   (+ константы 45с/60%-порог); добавлена ивент-точка входа
   `TrySpawnEventNpc(NPCEventSpawnReason)` — причины Caravan/Raid/Event,
   спавн walkable ≥12 тайлов от игрока, сид от seq+времени. QA-счётчик
   `ReinforcementCount` → `EventSpawnCount`. `GenerateStartup` (путь
   «естественного восстановления» при сборке локации) не изменён.
2. **NPCModule.Tick**: вызов ReinforcementTick удалён (комментарий R14).
3. **NPCModuleServices / HumanNPCSpawnPhase**: комментарии обновлены.
4. **LootSimDebug step7** перевёрнут: (a) население ниже порога НЕ
   восполняется за время ожидания; (b) ивент-спаун Caravan работает.
5. **docs_v2 синхронизированы**: DEATH_AND_LOOT §2.4 (переписан: 3 правила —
   нет в сессии / ивенты как исключение / восстановление при отсутствии),
   MODULE_STRUCTURE §2.7 (описание сервиса), TESTING_RULES §0.1 (LOOT-хук).

## Решения

- Ивент-спаун оставлен как ЯВНАЯ точка входа (TrySpawnEventNpc) — под будущий
  event-pipeline/GROUP_SYSTEM (караваны §3.5, набеги). Тиками не вызывается.
- «Естественное восстановление» = (пере)сборка локации (GenerateStartup),
  т.к. TryTravel — заглушка (travel-pipeline будущая фаза): физического
  «выйти → вернуться» в сессии ещё нет. Механизм «таймера памяти отсутствия»
  (1 игровой день, TRANSITION §5.3) — будет с travel-pipeline.
- Чекпоинт R13 и worklog-история НЕ правятся (append-only).

## Найденные проблемы

- Популяция в текущем билде теперь может быть «выбита подчистую» до пустой
  локации в рамках сессии — это соответствует задумке пользователя
  (необратимость, full-loot честен), не баг.

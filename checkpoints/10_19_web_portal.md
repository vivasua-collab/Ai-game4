# Чекпоинт: Веб-портал «Карта проекта Ai-game4» (каркас + данные + восстановление)

**Дата:** 2026-10-19
**Сессия:** main Z.ai Code; субагент 10-19-portal (full-stack)
**Тип:** implementation (инфраструктура портала)
**Требование владельца:** простой web-портал в DEV-окружении с быстрым
восстановлением после отката песочницы: «каркас и подгружаемые данные по
этапам; применили простой скрипт — восстановили текущее состояние».

---

## Контекст

Карта проекта (итерации 1–3, `project_map.json`: 29 треков / 183 этапа / 8 вех)
была создана как ТЗ-ядро портала «звуковые дорожки». Директива 19.10: портал
реализовать в существующем Next.js DEV-окружении платформы (порт 3000,
единственный пользовательский маршрут `/`), устойчивый к сбросам песочницы.

## Архитектура: тонкий каркас + толстые данные (git)

- **Каркас** (≈17 файлов) живёт в песочнице `my-project/src/...` — сбрасывается
  при откате.
- **Всё ценное — в git-репо**: `aigame4/portal/` — данные (JSON), зеркало
  исходников (skeleton/), скрипты восстановления.
- Портал читает данные в рантайме (fs, абсолютные пути, `Cache-Control:
  no-store`) — обновление состояния = правка JSON, без пересборки/деплоя.

```
aigame4/portal/
├── README.md              архитектура + регламент обновления/восстановления
├── data/
│   ├── bugs.json          реестр находок аудита (12 пунктов, волны 1–3)
│   └── status.json        снимок состояния (headline, focus, next, build)
├── skeleton/src/...       зеркало каркаса (пути от корня my-project)
├── restore_portal.sh      ВОССТАНОВЛЕНИЕ после отката (идемпотентный)
└── publish_skeleton.sh    актуализация skeleton после правок каркаса
```

Канон карты — `docs/docs_v2/00_overview/project_map.json` (портал читает его
напрямую; дублей нет — единственный источник правды сохранён).

## Реализация

- **API** `GET /api/portal`: читает 3 JSON (карта, реестр, статус), каждый в
  try/catch; ответ `{ok, project, milestones, tracks, bugs, status, errors[]}`.
  Без БД/prisma/кэша.
- **Страница `/`**: sticky-шапка (headline, бейдж сборки, «обновлено»),
  KPI-полоса (треков/этапов/счётчики статусов/общий прогресс — вычисляются на
  клиенте из tracks), дорожка вех M0–M7 (сегменты + tooltip), tabs:
  «Дорожки» (группы A–D; дорожка-строка: шкала этапов-сегментов по статусам,
  флаг DoD, tooltip, Collapsible-раскрытие списка этапов с пруфами) ·
  «Реестр аудита» (карточки: severity/type/status/wave, анализ/план
  Collapsible, прогресс-бар, history-таймлайн; фильтры по волне/статусу) ·
  «Статус» (снимок: плейтест-блок, сборка, фокус, next).
- Стиль: xianxia на тёмном (zinc-950, amber-акценты, stone-текст), рус UI,
  shadcn/ui, без синих/индиго. Sticky-футер (`min-h-screen flex flex-col` +
  `mt-auto` + safe-area): репо, источники данных, команда восстановления.
- Состояния: skeleton-загрузка, error-алерт с «Повторить»; responsive
  (mobile-first, шкалы компакт-режим).

## Восстановление после отката (процедура)

1. `bash cold_start.sh` — окружение (dotnet/Godot/NuGet); в конец встроен
   безопасный вызов `restore_portal.sh` (if -f … || true).
2. `bash aigame4/portal/restore_portal.sh` — каркас: skeleton →
   my-project/src (cp -a, идемпотентно), проверка порта 3000 (подсказка
   запуска, сам не стартует), саммари источников данных.
3. Данные отдельного восстановления не требуют — они в git-репо.

**Проверено в бою:** во время работы 10-19-fix-b песочница сбросилась —
cold_start.sh восстановил окружение, включая вызов restore_portal.sh. Отдельный
тест restore-скрипта main-агентом: 17 файлов скопированы, HTTP 200.

## Оперативное обновление состояния (регламент)

- Статусы багов/этапов/фокус: правка `portal/data/{bugs,status}.json` → портал
  показывает новое состояние при обновлении страницы (no-store). Волна 1
  отразилась в рантайме без правок кода (включая появление GAP-009).
- Правки каркаса: `publish_skeleton.sh` → коммит.
- Карта: `project_map.json` + `python3 tools/gen_project_map_md.py`
  (генератор создан и валидирован дифом по старому дашборду; `--check` —
  детектор дрейфа). Прогресс-формула кодифицирована по конвенции итерации 2.

## Решения

- Skeleton в git-репо (а не git в my-project): my-project не переживает откат,
  git-репо — переживает (GitHub). Скрипт — единственная процедура
  восстановления, встроена в cold_start.
- README портала фиксирует конвенции реестра (type/severity/status/fix_wave/
  track_ref/history) — портал и будущие сессии опираются на них.
- Генератор MD закоммичен: дашборд перестал быть ручным артефактом.

## Найденные проблемы

- Песочница убивает фоновые процессы по завершении вызова (nohup+setsid не
  выживают) — регрессия запускается чанками в foreground; dev-сервер
  платформенный, переживает.
- Каталог репо: фактический путь `my-project/Ai-game4`, симлинк `aigame4` →
  туда; restore-скрипт ищет оба имени (устойчивость к пересозданию симлинка).

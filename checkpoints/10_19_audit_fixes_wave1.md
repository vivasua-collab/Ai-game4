## BUG-001 — каст-эффекты техник 4 типов (P1) → verified

**Корень** (`PlayerTechniqueCaster.FireTechnique`): Sensory/Support/Curse —
общая ветка «Схематично» = пустой успех (тост+визуал без эффекта); Poison —
вообще без кейса, падал в default «Тип техники не поддерживается» ПОСЛЕ
списания Ци/кулдауна/мастерства. Генератор невиновен (все 4 типа корректно
создаются). Раньше игрок мог получить технику, которая ничего не делает.

**Фикс** (10-19-fix-a, без новых модулей/контрактов/полей модели — всё через
существующий IBuffService, id подобраны под MapBuffIdToType):
- Poison → DoT на цель: 6с × 6 тиков, тик `BaseDamage/6 × potency`;
- Curse → дебафф цели: −15% атаки 8с (масштаб от potency, пол 50‰);
- Sensory → бафф себе: +20% урона 10с (StatType.Damage — единственная
  потребляемая атакующая стата пайплайна);
- Support → самолечение `BaseDamage/2` (вдвое слабее Healing), гейт «Тело не ранено»;
- гейты цели Poison/Curse до траты Ци («Цель исчезла») + RefundUse при отказе.

**QA:** COMBAT_SIM +шаг 3m «bug001» (полный путь: генерация → изучение →
зарядка → аура → выпуск ×4 типа + ассерты). Пруфы: бафф 0→200‰, дебафф
0→−150‰, DoT 3 тика 27 урона (HP 500→482), лечение +27 (HP 466→493).

## GAP-001 — экран смерти игрока (P1) → verified

**Было:** смерть → технический респавн через 3с без какого-либо экрана.

**Стало** (10-19-fix-b): `Adapter/UI/DeathScreenOverlay.cs` (новый, 310 строк):
вуаль FullRect (MouseFilter=Stop — блокирует клики в мир), пергаментная панель
«☠ Вы пали…» + причина смерти (`PlayerDeathEvent.Cause`) + «Последний удар»
(кэш DamageAppliedEvent → имя NPC/зверя) + уровень культивации + кнопка
«Возродиться». ZIndex=50 (над HUD/окнами, ниже QA-панелей). Таймер 3с удалён —
респавн строго по кнопке через делегат `GWC.RequestPlayerRespawn` (тело флоу
1:1, без дублирования). `PlayerReviveEvent` → защитное скрытие.

**QA:** RespawnSimDebug +шаг 4: честная смерть `ApplyDamage(Head)` → оверлей
в дереве/виден/блокирует/причина «Голова разрушена (0 % HP)» → 3.6с игрок
мёртв (авто-респавна нет) → SimulateRespawnPressForQa → IsAlive=true, позиция
центр, оверлей скрыт.

**Остаток этапа player-s5 (→ in_progress):** потери при смерти и выбор места
возрождения — не реализованы.

## VER-001 — эффекты формаций Barrier/Trap (P2) → verified

Вердикты (FormationShotSimDebug +шаги 4a–4d):
- **Amplification** — работает: Buff(Damage, +0.2..0.6) → DamageService слой
  3b; замер 220‰ на L1.
- **Barrier** — работал частично: щит Ци кастеру (QiBufferActivateRequestEvent)
  был, но Shield-эффекты не агрегировались в статбонусы → Defense-пулл всегда
  получал 0. **Починено**: FormationEffects.Initialize агрегирует Shield по
  TargetStat со знаком «+»; теперь Defense 250‰ на L1, снятие при деактивации
  честное.
- **Trap** — КРУПНЫЙ РАЗРЫВ, не реализовывал (не моя зона/баланс): Control
  (Freeze/Slow) генерируется, но 0 потребителей; zone-триггера нет; даже
  применённый slow-дебафф не влияет на движение (NPCMovementService —
  конфиг-константы, GWC speedMult = терраин+экипировка+вес;
  StatModifierChangedEvent публикуется без подписчиков). Оформлена **новая
  находка GAP-009** в реестре (волна 3, оценка ~75–90 строк, 3 звена).

## Решения

- Реестр находок = данные портала (`portal/data/bugs.json`): статусы
  new→…→verified, волны 1–3, история по пунктам — процесс исправления
  наблюдаем на портале.
- Эффекты волны 1 — минимальные и честные (переиспользование существующих
  механизмов), баланс под L1: не ломают плейтест владельца (вечер 19.10).
- Trap не чинился «на месте»: баланс-чувствительный механизм (замедление
  врагов меняет всю боевую динамику) + чужие зоны (NPC-движение) → волна 3.

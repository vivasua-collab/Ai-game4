## Контекст

Репорт 20.09 №5 оставался последним незакрытым пунктом: «две валюты, обмен».
Аудит R21-C предлагал курс 1:10. Пользователь 2026-09-20 задал канон
заново и изменил масштаб:

- **Курс: 1 духовный камень = 100 золота** (НЕ 1:10 — ранняя идея не канон).
- **«Неча смертным владеть камнями»** — камни Ци только у культиваторов.
- Смертная экономика — **дальние планы** (вместе со «скрытой жизнью мира»),
  сейчас только заготовки (стабы) + документация.

## Что сделано

- `Core/Data/EconomyConstants.cs` — канон-числа: GoldPerSpiritStone=100,
  StoneBuyMarkupPermil=1200, StoneSellPermil=500 (спред зеркалит TradeConfig),
  CanHoldSpiritStones(CultivationLevel) — правило смертных.
- `Core/Interfaces/ICurrencyExchangeService.cs` — интерфейс стаба +
  readonly struct ExchangeQuote(Gold, Stones, RatePermil).
- `Modules/Trade/CurrencyExchangeService.cs` — чистая математика котировок
  (Permil.Apply, без кошелька и проводки), DI-регистрация в
  TradeModuleServices.
- Документация: `docs/docs_v2/06_player/ECONOMY_SYSTEM.md` (новый, полный
  спек: курс, правила владения, лор, статус стабов, план внедрения);
  TRADE_SYSTEM.md §8.1 закрыт + ссылка в шапке; README docs_v2 — реестр.
- Сборка: 0 ошибок.

## Решения

- Курс как `const int` в EconomyConstants — единственная точка правды. —
  менять числа только по указанию пользователя.
- Стаб без золотого кошелька: `ICurrencyService`/сейв-формат НЕ тронуты —
  нулевой риск регрессии сейвов. Кошелёк золота + проводка — будущий эпизод.
- Спред обмена = товарный спред (1200/500‰) — симметрия экономики,
  переиспользование балансовых констант.

## Найденные проблемы

- Расхождение курса R21-C (1:10) vs указания пользователя (1:100) —
  разрешено в пользу пользователя, задокументировано в ECONOMY_SYSTEM §2.

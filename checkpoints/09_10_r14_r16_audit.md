### Найдено и исправлено

**P2-1 (критично для «меню → NewGame/LoadGame», SPAWN): double-spawn и
«призраки» — NPC-домен переживал пересборку мира.**
- Фазы сборки и доменные сервисы NPC — DI-синглтоны на весь процесс.

  LoadGame оставлял NPC, которых нет в сейве.

     для трэкинговых + per-entity очистка восстановленных из сейва:
     провайдеры тела/Ци/экипировки, баффы, якоря, отношения, реестр; включая
     мёртвых, которых GetAllNPCIds не возвращает — через GetAllStates()) +
     CorpseService.ResetWorld (RemoveInternal → CorpseRemovedEvent на каждый:
     рендер-маркеры и открытое окно обыска корректно очищаются; счётчик ID
     перезапускается) + NPCGroupService.ResetWorld (+интерфейс
     INPCGroupService: реестр групп + членство + счётчик ID).

**P2-2 (Save/Load UX): восстановленные из сейва NPC дрейфовали к углу карты.**

## 3. R16-аудит (боевой ИИ NPC)

### Найдено и исправлено

**P1-1 (критично, лок боевой подсистемы): незавершённый каст переживал
EndCombat.**
- До R16 EndCombat вне резолва атаки был недостижим (MaxCombatDuration=0).
  R16 добавил AbandonCombat (бегство/leash по инициативе NPC из
  NPCModule.Tick) → бой может завершиться ПОСЕРЕДИ чужого каста. UpdateTimer
  гейтится !_isInCombat → каст никогда не резолвится; гейт _isCasting
  отклоняет ВСЕ новые атаки; анти-лок EnemyTurnTimeout отключён условием
  !_isCasting → перманентный лок боевой подсистемы до пересборки локации.
- **Фикс:** EndCombat гасит каст (_isCasting=false, _pendingTechnique=default)
  с диагностическим логом.

**P2-1: проводка NPCDefenseSelector в реальном бою не была покрыта QA.**
- Детерминированные кейсы селектора тестировались напрямую, но проводка
  (вызов в BuildAndExecuteDamageRequest) могла регрессировать молча (дефект
  D4 мог вернуться). Счётчики успешных защит зависят от RNG-ролла.
- **Фикс:** CombatService.LastNpcDefenseSelected (QA-геттер, экспорт на
  КАЖДОЙ атаке по NPC-защитнику — без RNG-зависимости); CombatAISimDebug
  тест 3 проверяет проводку: None после тестов 1–2 = регрессия.

**P2-2: тест 2 «двусторонний бой» мог проходить впустую.**
- Fallback FindAnyNpc (миролюбивый NPC) → Fleeing без единого удара по
  игроку → twoWayOk выполнялся по AIState-ветке без урона по NPC.
- **Фикс:** урон по NPC обязателен в любой ветке + WARN при вырождении.

**P3-1: мёртвый метод NPCCombatAdapter.ApplyDamage** (0 вызователей; урон
NPC идёт через DamageAppliedEvent → OnDamageApplied). Удалён.

**P3-2: рассинхрон стойки игрока после боя.**
- CombatService.EndCombat сбрасывает свою _lastPlayerDefense, но
  адаптерский CurrentDefenseStance жил дальше → G-цикл нового боя шёл от
  «призрачной» стойки, PlayerModule гейтил действия по рассинхрону.
- **Фикс:** PlayerCombatAdapter.OnCombatEnded → CurrentDefenseStance=None.

**P3-3: пустые подписки PlayerCombatAdapter** (OnCombatStarted/
OnDamageApplied — пустые обработчики с ложными комментариями «handled by
PlayerService»; PlayerService на эти события не подписан). Удалены.

## 7. Ключевые решения

- Сброс NPC-домена — ДВЕ точки (фаза 0 для NewGame + LoadGame до
  RestoreState), а не одна: фазы на Load идут после восстановления —
  сброс в фазе вытер бы загруженных NPC. Дублирование осознанное.
- CorpseService.ResetWorld публикует CorpseRemovedEvent на каждый труп
  (а не молча Clear) — рендер-маркеры и открытое окно обыска (R13-аудит
  P1-1: окно закрывается именно по этому событию) корректно чистятся.
- Морфологический фильтр задублирован (генерация + рендер) — defense-in-
  depth против старых сейвов и будущих путей экипировки.
- Живой QA на ПК (бой/G-стойка/бегство/leash) остаётся за пользователем —
  headless покрывает логику, не органолептику.

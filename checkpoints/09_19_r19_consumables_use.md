# R19 «Потребляемые ресурсы»: читаемость ПКМ-меню + «Использовать» с маршрутизацией по типам

**Дата:** 2026-09-19 (эпизод 5, ~19:05–20:05 МСК)
**Запрос пользователя:** «начинаем паралельную работу над потребляемыми ресурсами.
Я поднял лекарство, у меня нет пояса, должна быть возможность потребить его по
правой кнопке… 1. Сделать более выраженный фон этого подокна, не читается текст.
2. Добавить кнопку "Использовать", эффект которой будет зависеть от
характеристик объекта и возможности его использования. Кроме лекарств у нас
еще будут растения, свитки, еда — маршрутизация использования и эффекты
должны зависеть от типа объекта. Проведи аудит этой части кода, возможно есть
реализованные функции но не внедрены. Так как для пыли хаотичного Ци уже есть
возможность использования.» (скриншоты: ПКМ-меню лекарства и кристаллов Ци).

## 1. Аудит (до правок) — гипотеза пользователя подтверждена

| Находка | Детали | Статус до R19 |

| `BeltService.ApplyEffect` | heal (распределение по самым повреждённым частям) + qi_restore РЕАЛИЗОВАНЫ | работали ТОЛЬКО через пояс (хотбар 3-9). Без пояса — расходник потребить нельзя |
| `InventoryWindow.TryUseQiStone` | поглощение Ци + риск хаоса | только ItemCategory.QiStone |
| ПКМ-кнопка «Использовать» | `ItemContextMenu` | только для камней Ци (жёсткое условие категории) |
| Кейс-баг ключей эффектов | `ItemGeneratorService.GenerateConsumableForLevel` пишет `EffectType="Heal"` (заглавная), потребители switch-ят по `"heal"` | сгенерированные «Лекарство уровня N» НЕ ЛЕЧИЛИ даже через пояс; меню показывало сырой ключ «Heal +15» (на скриншоте пользователя: «Неал +15») |
| Баг данных стартовых расходников | `StartingGearPhase`: тапл несёт `(effect, value)`, но в `ItemData` писалось только `Value=value` (стоимость!), Effects НЕ заполнялись | стартовые пилюли/ягоды — «пустые» (без эффектов) |
| **Корневой баг нечитаемости** | `ItemContextMenu._panel = new Panel{ CustomMinimumSize(400,0) }` БЕЗ контейнера и БЕЗ якорей: высота панели = **0** → StyleBox-фон физически не рисовался (полоса 0 px); контент (VBox с FullRect-якорями) рендерился «ниже» панели прямо на тёмном бекдропе | текст «плавал» без подложки: скриншоты пользователя — фон `#3c3120`, текст `#7f7f7f`, контраст ~2.9:1. Кнопки были видны (у Button своя min-height от текста) — отсюда «кнопки видны, фона нет» |

## 2. Что сделано

### 2.1. IItemUseService — единая маршрутизация по типу (новое ядро)
- `Core/Interfaces/IItemUseService.cs`: `GetUseInfo(item)` (usable + label +
  reason), `TryUseFromInventory(slotId, expectedItemId)` (слот-адресно, R10
  P1-SlotId), `ApplyEffects(item)` (без списания — для пояса).
- `Modules/Inventory/ItemUseService.cs`: маршрутизация — камни Ци → поглощение
  (+10% риск −10% MaxHP хаос, перенесено из InventoryWindow), Consumable heal →
  распределение по повреждённым частям (перенесено из BeltService), qi_restore →
  AddQi, `material`/неизвестные ключи → не используется. **Нормализация ключей
  эффектов в нижний регистр в одном месте** (фикс кейс-бага). Тосты от сервиса.
- DI: `InventoryModuleServices.Register` → `IItemUseService, ItemUseService`.

### 2.2. ПКМ-меню: фон + кнопка «Использовать»
- `ItemContextMenu`: `Panel` (высота 0!) → **`PanelContainer`** (авторазмер по
  контенту) + явный `AddThemeStyleboxOverride("panel", …)` (прецедент всех окон
  проекта): непрозрачный `ParchmentBase`, рамка `AccentGold` 3px, скругление 6.
- Бекдроп 0.25 → **0.45** (выраженное отделение панели от инвентаря позади).
- Описание: `InkBlack` 13px (было `InkFaded` 12px). Значения характеристик —
  ограничение ширины для переноса (CustomMinimumSize).
- Кнопка «⚡ Использовать» — первичное действие, отдельной строкой во всю
  ширину, показывается по `GetUseInfo(item).Usable`; tooltip = описание
  действия (напр. «Поглотить Ци камня (1 шт.): +1024 ед. · хаос: 10% риск»).
  Разделить/Выбросить — второй строкой (как было).
- Отображение эффектов: кейс-нормализация («Heal» → «Лечение»).

### 2.3. Интеграция
- `InventoryWindow`: `[Inject] IItemUseService`; `TryUseItem(slotId, itemId)`
  (публичный путь ПКМ-кнопки, Refresh + doll refresh); `TryUseQiStone` —
  обёртка над сервисом (первая кучка itemId, исторический контракт этапа 7);
  мёртвый `ApplyChaoticDamage` удалён; IQiService/IBodyService окну больше
  не нужны (всё в сервисе).
- `BeltService.Use`: применение эффектов → ДЕЛЕГИРОВАНИЕ `IItemUseService`
  (та же точка правды; приватный ApplyEffect удалён; IQiService/IBodyService
  инжекты убраны). События ConsumableUsedEvent — по нормализованным ключам
  только для применённых эффектов (внешних потребителей события нет — проверено).
- `StartingGearPhase`: расходники получили **Effects в данных** (баг: effect из
  тапла игнорировался, value шёл в стоимость) + живые описания + стоимость —
  отдельное поле туапла (cost).

### 2.4. QA: CONTEXT-сим 11 → 15 шагов

## 4. Замечания / риски

- Belt-использование (клавиши 3-9) с реальным предметом QA-прогоном не
  покрывалось и раньше; поведение изменено (нормализация ключей, события
  только по применённым эффектам) — риск низкий (делегирование в
  протестированный сервис), но при первом живом тесте пояса — присмотреть.
- Qi-буфер: поглощение камня при полном буфере даёт «+0 Ци» (кап MaxQi) —
  это прежнее поведение, теперь честно видно в тосте. Канальное поглощение
  (QiRemaining) — будущая фаза (заложено в QiStoneData).
- Растения/еда/свитки: маршрутизация расширяема — новые ключи эффектов
  (satiation и др.) добавляются в ItemUseService.ApplyEffects + GetUseInfo;
  свитки техник — через книгу техник (T), не через «Использовать».

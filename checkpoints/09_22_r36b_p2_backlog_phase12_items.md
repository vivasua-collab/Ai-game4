## §2. Реализованные фиксы

### P2-33 — CurrencyService: saturating-арифметика
- `Add(int)`: long-промежуток + клэмп в int.MaxValue — баланс НЕ может
  стать отрицательным из-за переполнения (копится до представимого
  максимума; int остаётся — ЗАПРЕТ 3.9).
- `SetBalance(int)`: Math.Clamp(value, 0, int.MaxValue).

### P2-34 — TradeService: long-промежуток в тотале
- TryBuy: `long totalLong = (long)unitPrice * buyCount` → totalLong >
  int.MaxValue → честный Fail(«Слишком дорогая сделка») ДО списания/
  движения предметов (заплатить больше int.MaxValue непредставимо).
- TrySell: long-произведение → насыщение до int.MaxValue + предупреждение
  (предметы уже изъяты — контракт изъятие-до-оплаты; платим представимый
  максимум, а не молча 0 и не минус). TradeCompletedEvent тотал — int.

### P2-35 — InventoryService.RestoreState: валидация каждого слота
Гейты до конструирования слота (невалидный → skip + счётчик + итог в лог):
1. itemId непуст; 2. count > 0; 3. Enum.IsDefined(ItemCategory);
4. Enum.IsDefined(ItemRarity); 5. ItemId существует в IItemDatabaseService;
6. count ≤ maxStack предмета (MaxStack>0 ? MaxStack : 1).
`_itemDatabase == null` → гейты 5/6 пропускаются (не бывает в игре).
Отрицательный count больше не попадает в _itemCountCache.

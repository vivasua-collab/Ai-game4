# Чекпоинт: анализ перехода с ходовой модели боя на систему скорости атаки (attack speed)

**Дата:** 2026-09-19 (позже дня сессии; задача из NEXT работы 2026-09-19 эпизод 3)
**Сессия:** текущая (запрос пользователя: «анализ системы ходов в бою — уход от
"ходов" к скорости атаки оружия»)
**Тип:** audit — анализ БЕЗ изменений кода (read-only, код не менялся,
коммитов не делалось)

---

## Контекст

Запрос пользователя (дословный смысл): «я хочу избавиться от схемы ходов,
потому что по логике, пока волк укусит меня один раз, я его могу стукнуть два
раза. Для этого у оружия, ещё на стадии проектирования, я закладывал скорость
атаки (обратно пропорциональную количеству ударов за тик), возможно она не
попала в документацию, потому необходима большая и аккуратная правка физической
боевки».

Проверено: скорость атаки **была заложена** в проектирование оружия
(`WeaponBaseClass.AttackSpeedFactor`), **попала в урон** как компенсация
(«быстрое — легче, медленное — больнее»), но **НЕ попала** ни в предмет
(EquipmentData), ни в боевую логику, ни в COMBAT_SYSTEM.md. Подробности ниже.

### 1.4. Итоговая механика «волк vs игрок» сегодня

Игрок бьёт волка → ход передаётся волку (`CombatService.cs:885`) → волк кусает
(2-тиковый кулдаун, ход его) → ход возвращается игроку. **Строгое чередование
1:1 независимо от оружия** — ровно то, на что жалуется пользователь. Кулдауны
источников фактически маскируются чередованием (реют отклонения с бэкоффом
0.4с: `PlayerCombatAdapter.cs:173-180`).

## 3. Проект решения: модель готовности атаки (readiness)

### 3.1. Ядро модели

- Каждый участник боя имеет **готовность** `readinessPermil` (int, ЗАПРЕТ 3.9).
- Каждый игровой тик (в `CombatService.UpdateTimer` — игровые тики, пауза
  замораживает честно): `readiness += attackSpeedPermil`.
- Атака принимается только при `readiness ≥ 1000` («замах готов»); после
  принятия `readiness −= 1000` (остаток сохраняется — плавные каденции).
- **attackSpeedPermil** = базовая скорость оружия × AGI-фактор §8.2 ×
  (1000 + Σ% бонусы) / 1000, где:
  - оружие: из нового геттера `IEquipmentDataProvider.GetAttackSpeedPermil`
    (WeaponMain; кулаки = 1000);
  - AGI: `1000 × (1 + AGI × 0.01)` (существующая формула §8.2 как множитель
    скорости, инверсия текущей формулы длительности);
  - бонусы: StatBonus `"attackSpeed"` (§7.1) + баффы StatType.AttackSpeed
    (софт-капы 750/1200 уже в Constants) — сложение процентов, клэмп.
- **Животные:** скорость вида вместо кулдауна: волк/олень 500‰ (ровно
  сегодняшний темп 1 укус/2 тика), кролик 0. Кулдаун-поля удаляются.
- **Инициатива:** `StartCombat` ставит readiness инициатора = 1000, защитника
  = 0 → «кто начал — тот бьёт первым» сохраняется без ходов.
- Пример (Normal, 1 тик = 1с): волк 500‰/тик → укус раз в 2 тика; игрок с
  мечом (1000 × 1.1 AGI) → 1.1 удара/тик → **2.2 удара за укус волка**;
  кинжал 1430‰ → 2.86; двуруч 825‰ → 0.93 (реже волка, но больнее на 12.5%).
  Точно запрошенный эффект.

### 3.3. Контракты (CombatContracts.cs)

Обязательных новых событий НЕТ (readiness — серверное состояние, темп
регулируется гейтом приёма интента). Минимальные правки:
- `ICombatService` + `int GetReadinessPermil(string entityId)` (HUD/QA),
  возможно `bool IsAttackReady(string)`; CurrentStage — deprecated-семантика.
- `CombatConfig`: −EnemyTurnTimeoutSec, +AttackThresholdPermil=1000 (и
  опц. отладочные множители).
- AttackIntentEvent/AttackRejectedEvent — без изменений (Reason-строка
  «не готов» уже влезает).

### 3.4. Порядок действий в тике (важно для детерминизма)

CombatModule тикает РАНЬШЕ NPC/Animal (§1.2) → к началу тика готовность
начислена, интенты NPC/зверей приходят после начисления. Игрок публикует
интенты межтиково (кадры) — гейт готовности честно отклонит/примет. При
готовности обоих в одном тике порядок = порядок модулей (детерминировано).

## 5. План миграции (3 эпизода + опциональный 4-й)

### Эпизод 1 — данные + ядро готовности (Combat)
1. `EquipmentData` + `AttackSpeedPermil` (int, default 1000; для старых
   предметов-сейвов fallback 1000 — паттерн WeaponClassId R15).
2. `EquipmentGenerator.GenerateWeaponCore`: копировать фактор класса
   (×1000, округление). `LevelBoundaries` — новое поле в bounds (для QA-границ).
3. `IEquipmentDataProvider` + `EquipmentDataProvider`: GetAttackSpeedPermil
   (WeaponMain + StatBonus "attackSpeed" % + клэмп).
4. `CombatService`: readiness-словарь (2 участника), начисление в
   UpdateTimer, гейт готовности вместо гейта хода, инициатива при
   StartCombat, удалить SetTurnOwner/EnemyTurnTimeout/передачи хода;
   `GetReadinessPermil`. **Сохранить**: гейт участника, гейт каста, stale-cast
   в EndCombat, всё в BuildAndExecuteDamageRequest кроме :885.
5. `CombatConfig`: −EnemyTurnTimeoutSec, +AttackThresholdPermil.
6. `ICombatService`: +геттеры; де-факто PlayerTurn/EnemyTurn вне употребления.
   Объём: ~5 файлов, ~250 строк. Риск: средний (самый редактируемый файл
   проекта; регресс пайплайна мал — он не ходозависим).

## 6. Инварианты, которые НЕЛЬЗЯ сломать (чек-лист миграции)

1. **Списания Ци/Qi**: зарядка техник тиками (fill-модель), QiCost в
   TechniqueUsedEvent, Qi-щит 25% при стойке Shield (единожды) — все не
   ходозависимы, НЕ трогать.
2. **DoT-тики** (Burn/Bleed/Poison через BuffTickProcessor → DamageAppliedEvent
   «dot:») — ходо-независимы; боевой темп не должен влиять.
3. **Leash/disengage**: NPCAIService leash 15 тайлов, AnimalService de-aggro 5,
   AbandonCombat → EndCombat(Flee) — сохранить как есть.
4. **Смерть по правилу тел**: IsFatalHit ИЛИ IsEntityAlive/дренаж — не трогать.
5. **Модальная пауза**: тики гейтятся GameBoot._PhysicsProcess (IsPaused) —
   readiness в игровых тиках замораживается с миром автоматически (лучше
   сегодняшнего двойного часа: кулдаун игрока сейчас тикает в реальном
   времени даже при паузе — латентный рассинхрон уходит сам).
6. **Zero-GC рендереров**: readiness — int промилле, словарь на 2 участника,
   ноль аллокаций в steady-state; события — readonly struct без изменений.
7. **Транзакция стрел** (списание только по Accepted) и гейты LOS — не трогать.
8. **Гашение stale-каста в EndCombat** (P1-1 R16) — сохранить обязательно.
9. **Детерминизм**: ICombatRng, порядок модулей в тике, отсутствие
   Random.Shared в новых путях.
10. **Сейвы**: CombatService не ISaveable (состояние боя не персистится);
    AnimalSaveEntry.CombatCooldownTicks оставить в структуре сейва для
    обратной совместимости.
11. **1v1-гейт участника** и PlayerIdResolver-алиасы — не трогать.
12. **Прерывание каста уроном** (C11, CombatService:241-250) — не трогать.

## 7. Точки риска (ранжирование)

1. **CombatService.cs** — самый плотно редактируемый файл (история фиксов в
   шапке); правка ходов задевает 5 мест (гейт :471, передача :885, защита
   :921, таймаут :966, инициатива :277) — каждое с комментарием-обоснованием,
   комментарии обновить, а не удалять историю.
2. **COMBAT_SIM фаза 3e** — ассертирует именно ходовую семантику; без
   переделки регресс будет красным (это фича теста, не баг).
3. **Спам AttackRejectedEvent** при зажатом Space: адаптер обязан гейтить по
   готовности ДО публикации (pull-геттер), rejection — только страховка.
4. **Двойной час уходит не весь**: замахи-анимации/кулдауны UI (GWC) —
   кадровые; сверить, что HUD-индикатор читает readiness (game-time), иначе
   индикатор будет врать на fast/quick.
5. **NPC-интенты каждый тик** (вместо кулдауна) — рост шума событий при
   неготовности; вариант: NPC шлёт интент только при IsAttackReady(npc)
   (pull в NPCModule) — молча и без лишних событий.
6. **AnimalService — ISaveable**: смена поляCombatCooldownTicks → скорость
   вида требует бережности к сейв-совместимости (поле оставить, по умолчанию
   для старых сейвов скорость вида из SpeciesRegistry).


допустимый диапазон `SizeClass` (Tiny..Colossal, 0..6). Повреждённое
значение (999, отрицательное, 47) даёт невалидный enum-тег, который далее
распространяется по расчётам (множители HP/урона, слоты морфологии). Морфология
и материал при том же RestoreState проверяются на соответствие текущим

## Остаточный кандидат №2: ST12-003res — потеря дробного остатка таймера тиков

**Статус статического чтения:** подтвержден firsthand (аудит-сессия
2026-10-23 13:05 UTC, HEAD 26ade93).

**Место:** `game/src/Modules/Buff/BuffTickProcessor.cs:45-61`:

```csharp
buff.TickTimer -= deltaTime;
if (buff.TickTimer > 0f) return false;
float elapsed = -buff.TickTimer;
int dueTicks = (int)(elapsed / buff.TickInterval) + 1;
if (dueTicks > MaxCatchUpTicks) dueTicks = MaxCatchUpTicks;
// BF-I04 (сохранён): синхронизация с сеткой интервалов — без дрифта.
buff.TickTimer = buff.TickInterval;
```

Основной фикс ST12-003 (догоняющие тики с потолком MaxCatchUpTicks=5)
работает для deltaTime, кратного интервалу. Но при неравных шагах
пересечённый дробный остаток отбрасывается: `TickTimer` сбрасывается на
ПОЛНЫЙ `TickInterval` независимо от величины пересечения. Пример:
TickInterval=1с, шаги по 0.6с → тики срабатывают на 2-м, 4-м, 6-м... шаге,
но каждый раз теряется 0.2с накопленного времени — фактическая частота
тиков дрейфует вниз относительно сетки. Существующий тест «10 × 0.5с»
проходит именно потому, что шаги выравниваются с интервалом. Комментарий
«без дрифта» (:60) верен только для кратных шагов.

**Требуется от кодера (follow-up, расширение Stage12-сима):**

1. Добавить в `Stage12ProgressionTruthSimDebug` сценарий неравномерных
   шагов: например, TickInterval=1с и последовательность шагов
   0.6с × 10 (и вторую: чередование 0.7с/0.5с), сравнить число и моменты
   тиков с покадровым эталоном эквивалентного суммарного времени.
2. Ожидаемое поведение: сохранение дробного остатка, например
   `buff.TickTimer = buff.TickInterval - (elapsed % buff.TickInterval)`
   (с учётом потолка MaxCatchUpTicks — остаток после отбрасывания долга
   тоже должен быть корректным); частота тиков при неравных шагах
   соответствует сетке с точностью до одного шага.
3. Префикс-лог на текущем коде, постфикс после фикса, логи:
   `checkpoints/10_23_stage12_tick_remainder_followup_prefix.log` /
   `..._postfix.log` (или расширение существующих логов Этапа-12).
4. Полная регрессия после фикса; отдельный коммит с пометкой
   `ST12-003res (followup)` — не смешивать с Этапом-13/14.
5. Аккуратность: не сломать основной кейс ST12-003 (5 шагов по 1с ==
   1 шаг 5с по числу тиков) и анти-всплеск (долгий hitch не выстреливает
   сотни тиков).

**Статус в реестре до выполнения:** NOT TESTED (остаточный кандидат);
после — по факту теста.

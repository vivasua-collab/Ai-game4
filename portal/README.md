# Portal — веб-портал «Карта проекта Ai-game4»

Простой веб-портал для визуализации состояния проекта: дорожки-треки карты
проекта, реестр находок аудита (процесс исправления багов), снимок текущего
статуса. Живёт в DEV-окружении платформы Z.ai (Next.js, порт 3000, маршрут `/`).

## Архитектура: тонкий каркас + толстые данные (git)

Принцип устойчивости к откатам окружения: **всё ценное — в git-репозитории,
приложение — тонкая читалка**.

```
aigame4/portal/                     ← ЭТО в git → переживает любой откат
├── data/
│   ├── bugs.json                   ← реестр находок аудита (ведёт main-агент)
│   ├── status.json                 ← снимок состояния (фокус, next, build)
│   └── bus_map.json                ← снимок центральной шины (ПО ТРЕБОВАНИЮ:
│                                      python3 tools/gen_bus_map.py)
├── skeleton/                       ← зеркало исходников портала
│   └── src/app/...                 (пути от корня my-project)
├── restore_portal.sh               ← ВОССТАНОВЛЕНИЕ после отката (одна команда)
└── publish_skeleton.sh             ← актуализация skeleton после правок портала
```

Канонический источник данных карты: `docs/docs_v2/00_overview/project_map.json`
(29 треков / 183 этапа / 8 вех). Реестр багов: `portal/data/bugs.json`
(31 находка, волны исправления 1–3). Снимок шины: `portal/data/bus_map.json`
(23 узла: 17 модулей + Entry + 5 Adapter/QA; 163 контракта EventBus, 160
сервисов DI). Портал читает файлы в рантайме — без БД, без миграций, без
дублирования.

## Восстановление после отката окружения

Полная последовательность (после сброса песочницы):

```bash
bash cold_start.sh                      # 1. окружение: dotnet, Godot, NuGet
                                        #    (в конец встроен вызов restore_portal.sh)
bash portal/restore_portal.sh           # 2. каркас портала: skeleton → my-project/src
```

`restore_portal.sh` (идемпотентный, безопасный):
1. проверяет наличие `my-project` и репозитория `aigame4` (иначе — инструкция);
2. копирует `skeleton/` поверх `my-project/src/...` (создаёт каталоги);
3. проверяет dev-сервер на порту 3000 (если не отвечает — печатает команду запуска);
4. печатает саммари: источники данных, статус копирования, что проверять.

Данные подгружаются порталом из git-репозитория в рантайме — отдельного
«восстановления данных» не требуется: они уже в `aigame4/`.

## Регламент оперативного обновления портала

Обновляет **main-агент Z.ai Code** (без правок кода приложения):

- **Изменились статусы багов/этапов/фокуса** → правка `portal/data/bugs.json` /
  `status.json` → портал показывает новое состояние при обновлении страницы
  (API отдаёт `Cache-Control: no-store`).
- **Изменился исходник портала** → правка в `my-project/src/...` → затем
  `bash portal/publish_skeleton.sh` (копия в skeleton) → коммит.
- **Карта проекта** (треки/этапы) → правка `project_map.json` + перегенерация
  `PROJECT_MAP.md` (`python3 tools/gen_project_map_md.py`) — по регламенту
  в конце каждого R-раунда.
- **Карта шины** (вкладка «Схема шины») → ТОЛЬКО ПО ТРЕБОВАНИЮ (директива
  владельца 21.10): правки кода игры → `python3 tools/gen_bus_map.py` →
  коммит `bus_map.json` вместе с кодом. Дрейф-детектор:
  `python3 tools/gen_bus_map.py --check` (≠0 — карта устарела).
  Карта отвечает на вопрос «всё ли публикуется/забирается с шины»: 6 сверок
  (издатели↔подписчики, регистрации↔запросы, мёртвые контракты).

## Пункты реестра — конвенции

- `type`: `bug` (сломано) / `gap` (фича отсутствует) / `verify` (верифицировать);
- `status`: new → analyzing → planned → in_progress → fixed → verified
  (или deferred);
- `fix_wave`: 1 — текущая сессия, 2 — ближайшие, 3 — дизайн-этап / M6+;
- `track_ref` — привязка к этапу/треку `project_map.json` (кросс-ссылка на
  портале);
- `history[]` — таймлайн работы по пункту (даты + события) — не удалять.

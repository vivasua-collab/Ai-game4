# Горячие клавиши (Hotkeys)

> **Назначение:** Движко-независимая спецификация горячих клавиш. Полный список действий, привязка к клавишам, контексты срабатывания, механика sticky-флагов.
>
> **Связанные документы:** `UI_DESIGN.md`, `06_player/INVENTORY_SYSTEM.md`, `01_architecture/DI_AND_EVENTBUS.md`, `05_data/SAVE_SYSTEM.md`.
>
> **Синхронизировано с кодом:** 2026-09-06 (аудит): V = медитация, Z = каст, X = цикл техник,
> K = окно Культивации, F1 = справка, F2 = чит-меню, PageUp/Down = скорость времени,
> хотбар 1/2 = режимы боя. R / M / N / ` / F5-F9 — не реализованы или отключены (см. §2.4).

---

## 1. Принципы

1. **Канонический набор:** F5, F9, Esc, E, B, R, X, F — обязательный минимум. Дополнительные клавиши (WASD, 1–9, мышь) — для управления игрой.
2. **3-слойная архитектура ввода:** Hardware → InputService (state) → ActionResolver (intent) → Module (execution).
3. **Sticky-флаги:** Одноразовые нажатия сохраняются в InputService как «sticky» до конца кадра; считываются и сбрасываются модулем.
4. **Действие зависит от контекста:** одна и та же клавиша может иметь разный эффект в зависимости от текущего UI-состояния (например, Esc закрывает окно если открыто, иначе — пауза).
5. **WASD отменяет click-to-move:** при активном клик-перемещении нажатие WASD сбрасывает цель.

## 4. Контекстно-зависимые действия

### 4.1. Принцип

Одна клавиша может иметь разный эффект в зависимости от:
1. Текущего UI-состояния (HUD / Inventory / Journal / Pause / Dialogue).
2. Объекта под курсором / рядом с игроком.
3. Состояния игрока (в бою / в покое / в движении).

### 4.2. Примеры

| Клавиша | UI: HUD | UI: Inventory | UI: Dialogue |
|---------|---------|---------------|--------------|
| **Esc** | Открыть Pause Menu | Закрыть Inventory | Закрыть Dialogue |
| **E** | Взаимодействие с миром | (не используется) | Подтвердить реплику |
| **B** | Открыть Inventory | Закрыть Inventory | (не используется) |
| **Space** | Атака | (не используется) | Пропустить строку диалога |
| **1–9** | Выбор слота хотбара | (не используется) | Выбор реплики 1–9 |

## 5. Архитектура ввода (3 слоя)

### 5.1. Слой 1: Hardware → InputAdapter

Опрашивает keyboard + mouse на каждом кадре. Преобразует «сырой» ввод в структуру `InputFrameData`:

```
InputFrameData:
├── moveDirection: Vector2       # WASD/стрелки, нормализованная
├── isRun: bool                  # Shift удерживается
├── isLmbPressed: bool           # ЛКМ в этом кадре
├── isRmbPressed: bool           # ПКМ в этом кадре
├── rmbHoldDuration: float       # Длительность удержания ПКМ (для контекстного меню)
├── mouseWorldPos: Vector2       # Мировая позиция курсора (в промилле)
├── isOverUI: bool               # Курсор над UI
├── hotbarSlot: int?             # Выбранный слот 1–9 (null если не нажат)
├── stickyKeys: HashSet<KeyCode> # Одноразовые нажатия (E, B, R, X, F, F5, F9, Esc, J, T, C, Q, M, N)
└── frame: long                  # Номер кадра (для валидации sticky)
```

> `InputFrameData` — `readonly struct` (zero-GC). См. `01_architecture/PERFORMANCE_STRATEGY.md`.

### 5.2. Слой 2: InputService

Хранит состояние ввода, доступное модулям. Разделяет:
- **Удерживаемые состояния** (moveDirection, isRun, isLmbDown) — актуальны до конца кадра.
- **Sticky-флаги** (IsInteractPressed, IsInventoryPressed, IsRestPressed, ...) — одноразовые, считываются и сбрасываются в конце кадра методом `ResetFrameFlags()`.

### 5.3. Слой 3: ActionResolver → Module

Каждый модуль имеет свой `Tick()` и читает из InputService нужные ему флаги. Логика разрешения намерений:

```
PlayerModule.Tick():
  1. Если IsInventoryPressed → toggle UI state (Inventory)
  2. Если IsInteractPressed → InteractionService.TryInteract()
  3. Если IsRestPressed → открыть окно отдыха
  4. Если IsAttackPressed → CombatService.ExecuteAttack()
  5. WASD → PlayerService.ProcessMovement()
  6. HotbarSlot != null → HotbarService.SelectSlot()
  7. RMB long → ContextMenuUI.Show()
  8. ResetFrameFlags()  ← сброс sticky-флагов в конце кадра
```

## 6. Sticky-флаги

### 6.1. Принцип

Sticky-флаг — это одноразовый сигнал «клавиша была нажата в этом кадре». Устанавливается в InputAdapter, считывается в Module.Tick(), сбрасывается в `ResetFrameFlags()`.

### 6.2. Зачем

- **Предсказуемость:** модули гарантированно видят нажатие, даже если оно длилось <1 кадра.
- **Изоляция:** модули не опрашивают keyboard напрямую — только InputService.
- **Тестируемость:** в headless-тестах можно напрямую установить sticky-флаг и проверить реакцию модуля.

### 6.3. Список sticky-флагов

| Флаг | Клавиша | Кто обрабатывает |
|------|---------|------------------|
| IsInteractPressed | E | InteractionService |
| IsInventoryPressed | B | PlayerModule → UIService |
| IsRestPressed | R | — (мёртвая проводка, см. §2.4) |
| IsSpecialActionPressed | X | цикл выбора техники |
| IsHarvestPressed | F | HarvestService |
| IsAttackPressed | Space / ЛКМ | CombatAdapter (подавляется при открытом UI/диалоге) |
| IsDefendPressed | K (если есть) | CombatAdapter |
| IsMeditatePressed | V | MeditationService (M занят world_map) |
| IsSaveRequested | F5 | SaveModule (⚠️ отключено, Q8) |
| IsLoadRequested | F9 | SaveModule (⚠️ отключено, Q8) |
| IsEscapePressed | Esc | UIService (close/pause) |
| IsJournalPressed | J | UIService (EventLogWindow) |
| IsTechniquesPressed | T | UIService (TechniqueBookWindow) |
| IsCharacterSheetPressed | C | UIService (CharacterSheetWindow) |
| IsQuestLogPressed | Q | UIService (QuestWindow) |
| IsMapPressed | M (alt: карта) | — (мёртвая проводка, см. §2.4) |
| IsCastTechniquePressed | Z | PlayerTechniqueCaster |
| IsCultivationWindowPressed | K | UIService (CultivationWindow) |
| IsHelpHotkeysPressed | F1 | UIService (HotkeysWindow) |
| IsCheatMenuPressed | F2 | CheatPanel (DEBUG; гейт CheatsEnabled) |
| IsTimeSpeedUpPressed / IsTimeSpeedDownPressed | PageUp / PageDown | TimeService (скорость) |
| IsWeaponMeleePressed / IsWeaponRangedPressed | 1 / 2 | CombatAdapter (режимы боя) |
| IsInputLogPressed | ` / F1 | — (мёртвая проводка; F1 занят справкой) |
| HotbarSlotSelected | Shift+1–9 | BeltService (пояс); 3–9 без Shift — техники (TechniqueSlotService) |

## 7. Контекстное меню (RMB long)

### 7.1. Принцип

Долгое удержание правой кнопки мыши (≥ 300 мс) открывает контекстное меню для объекта под курсором.

### 7.2. Поведение

- **В Inventory (на предмете):** меню действий — Экипировать / Снять / Использовать / В духовное хранилище / В кольцо хранения / Разделить стек / Выбросить / Подробнее.
- **В мире (на NPC):** меню взаимодействий — Заговорить / Атаковать / Осмотреть / (в зависимости от отношения).
- **В мире (на объекте):** меню действий — Осмотреть / Взаимодействовать / (специфичные действия).

### 7.3. Реализация

InputAdapter измеряет длительность удержания RMB:
- Если длительность < 300 мс → `TrackingTargetEvent` (короткий клик = трекинг).
- Если длительность ≥ 300 мс → `ContextMenuRequestedEvent` (длинный клик = меню).

## 8. Хотбар (1–9)

### 8.1. Структура (актуально с S4, 2026-09-04)

9 слотов внизу экрана в два ряда: основной ряд + ряд пояса (BeltSlotRow):

| Слот | Содержимое | Активация |
|------|-----------|------------|
| 1 | Режим ближнего боя (кулаки/меч) | Клавиша 1 — переключить режим |
| 2 | Режим дальнего боя (лук/арбалет) | Клавиша 2 — переключить режим (нужно дальнобойное оружие) |
| 3–9 | Техники из назначенных слотов (CultivationWindow) | Клавиша 3–9 или клик по слоту — каст; оверлей кулдауна + Qi-гейт + рамка цвета стихии |
| Shift+1–9 | Пояс (расходники) | Использовать предмет из слота пояса |

### 8.2. Информативность слотов (S4)

- Кулдаун: цифры секунд + затемняющий «занавес» поверх слота.
- Qi-гейт: слот «заморожен» (полупрозрачный), если не хватает Ци.
- Рамка цвета стихии техники (ELEMENTS_SYSTEM).
- Тултипы слотов (имя / стоимость Ци / кулдаун).

### 8.3. История изменения семантики

Изначально (v1 спецификация): 1=WeaponMain, 2=WeaponOff, 3–9 универсальные drag&drop.
Фактически (этапы внедрения ЦИ + Phase 8 p2 + S4): 1/2 стали режимами боя, 3–9 — слотами техник, пояс — отдельным рядом (Shift+1–9). Drag&drop переназначение слотов 3–9 — в планах.

## 9. Отключение ввода

### 9.1. Принцип

В определённых UI-состояниях игровой ввод отключается (например, открыто окно инвентаря → нельзя ходить).

### 9.2. Правила

| UI-состояние | Движение | Атака | Взаимодействие | Хотбар | Save/Load |
|--------------|----------|-------|----------------|--------|-----------|
| HUD (игра) | ✅ | ✅ | ✅ | ✅ | ✅ |
| Inventory | ❌ | ❌ | ❌ | ❌ | ✅ |
| Journal | ❌ | ❌ | ❌ | ❌ | ✅ |
| Pause Menu | ❌ | ❌ | ❌ | ❌ | ✅ |
| Dialogue | ❌ | ❌ | ✅ (только подтверждение) | ❌ | ✅ |
| Loading | ❌ | ❌ | ❌ | ❌ | ❌ |

### 9.3. Исключения

- **B (Inventory):** всегда работает, даже когда остальные клавиши заблокированы (кроме Loading).
- **Esc:** всегда работает (для выхода из любого UI).
- **F5/F9:** всегда работают (кроме Loading), чтобы можно было сохранить/загрузить из любого UI-состояния.

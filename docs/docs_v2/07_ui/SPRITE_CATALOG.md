## 2. Форматы спрайтов

| Тип | Размер | PPU | Filter | Alpha | Источник |
|------|--------|-----|--------|-------|----------|
| Terrain (процедурный) | 64×64 | 32 | Point | Сплошная заливка | Код (Perlin noise) |
| Objects (PNG) | 64×64 | 32 | Point | Прозрачный фон | Asset pipeline |
| Player (PNG) | 128×128 | 64 | Bilinear | RGBA с прозрачностью | Asset pipeline |
| Player Fallback | 64×64 | 64 | Bilinear | RGBA | Код (процедурный) |
| Effects (PNG) | 64×64 | 32 | Bilinear | RGBA | Asset pipeline |
| UI icons (PNG) | 32×32 | 32 | Bilinear | RGBA | Asset pipeline |

### 2.1. Почему PPU=32 для тайлов и PPU=64 для персонажей

- **Тайлы 64×64 @ PPU=32** = 2 мировых единицы на тайл. Это даёт достаточно детализации на близкой камере и компактный размер текстур.
- **Персонажи 128×128 @ PPU=64** = 2 мировых единицы на персонажа. Персонаж занимает 1×1 тайл по габаритам, но спрайт больше (с полями для анимации/экипировки).
- Одинаковый «мировой размер» (2 ед.) для тайла и персонажа упрощает логику коллизий и пути.

### 2.2. Почему FilterMode.Point для тайлов

Point-фильтрация даёт чёткие пиксельные границы, без размытия. Это критично для тайлов — субпиксельное смешивание с соседями даёт видимые швы (белая сетка).

Для персонажей и эффектов используется Bilinear — сглаживание краёв спрайта.

### Анимация эффектов через sprite-swap

Эффекты не используют скелетную анимацию. Вместо этого применяется **sprite-swap**:

- Каждый эффект — последовательность из N кадров (4–8).
- Кадры переключаются по таймеру (частота 10–15 FPS).
- После последнего кадра эффект удаляется (или зацикливается, для持续性).

Преимущества:
- Простота (нет скелета, нет rigging).
- Предсказуемая производительность (1 draw call на эффект).
- Лёгкая замена кадров.

## 15. Процедурная генерация спрайтов

### 15.1. Принцип

Тайлы terrain и object-tiles — **процедурные**: не хранятся как PNG-файлы, а генерируются кодом в рантайме (или при сборке ассетов).

Алгоритм:
1. Выбрать базовый цвет для типа тайла (например, зелёный для Grass).
2. Заполнить весь тайл 64×64 этим цветом.
3. Применить Perlin noise для вариации яркости/цвета в пределах тайла.
4. (Опционально) наложить декоративные элементы (трещины, пятна, блики).
5. Создать спрайт с PPU=32, FilterMode=Point, alphaIsTransparency=true.

### 15.2. Преимущества

- **Минимальный размер дистрибутива:** тайлы не занимают место на диске.
- **Бесшовность:** процедурные тайлы не имеют субпиксельных зазоров (в отличие от PNG через asset pipeline).
- **Детерминированность:** один и тот же seed → один и тот же результат.
- **Вариативность:** Perlin noise даёт уникальный паттерн для каждого тайла.

### 15.3. Недостатки

- **CPU-затраты при генерации:** одноразовая, при загрузке (или при сборке).
- **Ограниченная художественность:** процедурные спрайты — простые текстуры, не «арт».

## 16. Зеркалирование спрайтов (Mirroring)

### 16.1. Принцип

В игре персонажи имеют только 2 направления взгляда — вправо и влево. Вместо создания отдельных спрайтов для каждого направления используется зеркалирование одного спрайта.

```
Один спрайт (направо) → Зеркалирование по оси X → Направо/Налево
```

### 16.2. Преимущества

- Экономия места (1 спрайт вместо 2+).
- Простота анимации.
- Согласованность визуала.

### 16.3. Способы реализации

| Способ | Описание | Плюсы | Минусы |
|--------|----------|-------|--------|
| `flipX` флаг рендерера | Рендерер отзеркаливает спрайт | Не затрагивает дочерние объекты | Работает только для одного спрайта |
| Scale X = -1 на узле | Узел отзеркаливается целиком | Зеркалит всю группу (с экипировкой) | Дочерние объекты тоже зеркалятся |

### 16.4. Нюанс с дочерними объектами

При `scaleX = -1` на узле персонажа, все дочерние объекты тоже зеркалятся. Это создаёт проблемы:
- Орбитальное оружие зеркалится вместе с персонажем (нежелательно — оружие должно оставаться в правильной ориентации).
- Эффекты частиц отражаются.
- UI-элементы поверх персонажа отражаются.

**Решение: Independent Scale Compensation**

Для дочерних объектов, которые НЕ должны зеркалиться, применяется компенсация: их `scaleX` устанавливается в `-1`, если родитель отзеркален. Это «отменяет» зеркалирование для конкретного ребёнка.

```
// Псевдокод
if (parent.scaleX < 0) {
    child.scaleX = -childOriginalScaleX;
} else {
    child.scaleX = childOriginalScaleX;
}
```

## 17. Анимация через sprite-swap

### 17.1. Принцип

В игре **не используется** скелетная анимация (Animator, rigging). Все анимации — **sprite-swap**: последовательная смена спрайтов на одном рендерере.

### 17.2. Применения

- **Анимации эффектов:** 12 combat effect спрайтов используются как кадры анимации.
- **Орбитальное оружие:** 8 спрайтов = 8 направлений вращения.
- **Ходьба/покой персонажа:** (планируется) последовательность спрайтов.
- **Прорыв культивации:** вспышка-эффект.

### 17.3. Параметры

| Параметр | Значение |
|----------|----------|
| Частота кадров | 10–15 FPS (настраивается) |
| Зацикливание | Да для ходьбы/покоя; Нет для эффектов (один цикл) |
| Хранение кадров | Массив ссылок на спрайты (без атласов) |

### 17.4. Преимущества

- Минимум кода (нет скелета, нет rigging).
- Лёгкое добавление новых анимаций (просто добавить кадры).
- Предсказуемая производительность (1 draw call на анимируемый объект).

## 19. Fallback-генерация

Если PNG-спрайт не найден или не загрузился, используется **программный fallback**:

- Для персонажа: процедурный силуэт (гуманоид 64×64 с базовой заливкой).
- Для NPC: процедурный гуманоид с цветовым кодированием по роли.
- Для тайлов: процедурная заливка (как в основной генерации).
- Для эффектов: цветной круг с пульсацией.

Это гарантирует, что игра не крашится при отсутствии ассетов и остаётся играбельной.

## 20. Хранение и именование

### 20.1. Структура каталогов (логическая)

```
sprites/
├── tiles/             # terrain_*, obj_*
├── characters/
│   ├── player/        # player_variant*
│   └── npc/           # npc_*
├── equipment/         # weapon_*, armor_*
│   ├── icons/         # 128×128 для инвентаря/дропа
│   └── equipped/      # overlay-спрайты (планируется)
├── items/             # consumable_*, material_*
├── elements/          # element_*
├── techniques/        # technique_*
├── cultivation/       # cultivation_*
├── combat/
│   ├── effects/       # effect_*
│   └── orbital/       # orbital_*
└── ui/                # ui_*
```

### 20.2. Именование

- snake_case.
- Префикс категории: `terrain_`, `obj_`, `player_`, `npc_`, `weapon_`, `armor_`, `consumable_`, `material_`, `element_`, `technique_`, `cultivation_`, `effect_`, `orbital_`, `ui_`.
- Суффикс материала/уровня: `_iron`, `_spirit`, `_jade`, `_wood`, `_cloth`, `_leather`.

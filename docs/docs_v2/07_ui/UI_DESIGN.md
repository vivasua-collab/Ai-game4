# UI Дизайн

> **Назначение:** Движко-независимая спецификация UI: тема, целевое разрешение, слои компоновки, 22 UI Views, паттерн UI Builder, рендеринг текста. Без привязки к конкретному UI-фреймворку движка.
>
> **Связанные документы:** `RENDER_LAYERS.md`, `SPRITE_CATALOG.md`, `HOTKEYS.md`, `06_player/INVENTORY_SYSTEM.md`, `01_architecture/PERFORMANCE_STRATEGY.md`.

---

## 1. Принципы

1. **Concept over implementation.** Документ описывает, что UI делает и как выглядит, а не какие конкретно ноды/компоненты движка используются.
2. **Целевое разрешение — 1920×1080.** Используется масштабирование с сохранением пропорций. Текст и элементы задаются в промилле от целевого разрешения (integer math, без float drift).
3. **Тема — «Древний Пергамент».** Единая визуальная стилистика для всех внутриигровых UI.
4. **Unicode-глифы вместо эмодзи** для индикаторов, иконок категорий, маркеров прогресса.
5. **UI Builder pattern.** UI собирается из декларативного описания (тема + данные) в коде, без ручной сборки в редакторе. Это обеспечивает воспроизводимость и git-совместимость.
6. **Шрифты — OS fallback chain.** Используется системный шрифт с поддержкой кириллицы + fallback на встроенный шрифт с глифами для Unicode-символов.

## 3. Unicode-глифы

Вместо эмодзи используются Unicode-символы — они отображаются любым TTF-шрифтом и не требуют отдельных ассетов.

| Глиф | U+    | Назначение |
|------|-------|------------|
| `◆` | U+25C6 | Заполненный ромб — категория «Персонажи», важные записи |
| `◇` | U+25C7 | Пустой ромб — категория «Локации» |
| `○` | U+25CB | Пустой круг — не открыто, нейтральное |
| `◉` | U+25C9 | Заполненный круг с точкой — здоровая часть тела |
| `◐` | U+25D0 | Полукруг — повреждено |
| `◑` | U+25D1 | Полукруг (другая сторона) — изуродовано |
| `◒` | U+25D2 | Полукруг снизу — парализовано |
| `◓` | U+25D3 | Полукруг сверху — критическое |
| `★` | U+2605 | Звезда — категория «Техники», редкость, избранное |
| `☆` | U+2606 | Пустая звезда — не избранное |
| `✓` | U+2713 | Галочка — открыто, выполнено |
| `✗` | U+2717 | Крестик — не выполнено, запрещено |
| `▰` | U+25B0 | Заполненный параллелограмм — категория «Предметы» |
| `▱` | U+25B1 | Пустой параллелограмм — категория «Заметки» |
| `●` | U+25CF | Точка-маркер списка |
| `■` | U+25A0 | Квадрат — заглушка слота |
| `□` | U+25A1 | Пустой квадрат — слот |
| `▲` `▼` | U+25B2/3 | Стрелки прокрутки |
| `◄` `►` | U+25C4/BA | Стрелки навигации |
| `─` | U+2500 | Горизонтальная линия-разделитель |
| `│` | U+2502 | Вертикальная линия |
| `┌` `┐` `└` `┘` | U+250C/10/14/18 | Углы рамок |

> Полный набор глифов должен поддерживаться выбранным шрифтом. Если глиф отсутствует — fallback на `□` (пустой квадрат) или `?`.

## 4. Целевое разрешение и масштабирование

### 4.1. Целевое разрешение

- **Native:** 1920×1080 (16:9).
- **Минимальное поддерживаемое:** 1280×720.
- **Масштабирование:** proportional, с сохранением aspect ratio. UI не растягивается под нестандартные пропорции — по бокам чёрные полосы.

### 4.2. Per-mille sizing

Все размеры UI-элементов задаются в **промилле** (‰) от целевого разрешения, не в пикселях и не в относительных единицах.

```
panelWidth_ppm  = 800   // 800‰ от 1920 = 1536 px
panelHeight_ppm = 600   // 600‰ от 1080 = 648 px
fontSize_ppm    = 18    // 18‰ от 1080 = 19.44 → 19 px (округление)
```

- Используется integer math, без float drift.
- Один и тот же UI-код работает на 1080p, 1440p, 4K — масштаб пересчитывается.
- Округление всегда в меньшую сторону (`floor`), чтобы не превышать границы панелей.

### 4.3. Reference DPI

- **Reference DPI:** 96 (стандартный desktop).
- На высоком DPI (4K мониторы) UI масштабируется автоматически через per-mille.
- Не используется независимое от плотности масштабирование (вроде dp/sp) — per-mille достаточно.

## 5. Слои компоновки UI (3 sub-layers)

UI корня состоит из трёх подуровней, отображаемых сверху вниз (от дальнего к ближнему):

```
┌─────────────────────────────────────────────┐
│  FloatingLayer (tooltips, drag-preview,     │  ← Самый верхний
│  context menus, notifications)              │
├─────────────────────────────────────────────┤
│  WindowLayer (инвентарь, журнал, пауза,     │
│  диалоги, меню)                             │
├─────────────────────────────────────────────┤
│  HudLayer (полосы HP/Ци/Stamina, мини-карта,│  ← Самый нижний (над миром)
│  хотбар, индикаторы)                        │
└─────────────────────────────────────────────┘
```

| Слой | Назначение | Свойства |
|------|------------|----------|
| **HudLayer** | Постоянно видимые элементы (HUD) | Не блокирует ввод в игровой мир (кроме хотбара); всегда активен |
| **WindowLayer** | Модальные/немодальные окна | Блокирует часть ввода; только одно окно активно (кроме случая multi-window для лута) |
| **FloatingLayer** | Tooltip, drag-preview, контекстное меню, тосты | Самый верхний; не блокирует ввод, но перехватывает hover/click по своим элементам |

> Все три слоя рендерятся на render layer **UI** (см. `RENDER_LAYERS.md`). Внутри слоя порядок определяется z-порядком компоновки.

|---|----------------|------------|---------|

### 6.4. Дополнительные (не входят в 22)

- **Pause Menu** — отдельное окно (сохранить/загрузить/настройки/выйти). Открывается по Esc (когда нет открытых окон).
- **Settings** — настройки игры.

## 7. UI Builder Pattern

### 7.1. Принцип

UI не собирается вручную в визуальном редакторе. Вместо этого используется **декларативный UI Builder**: код читает статическое описание UI-элемента (тема + данные) и инстанцирует соответствующие визуальные элементы.

> Это движко-нейтральный паттерн, эквивалентный UIFactory/Theme из предыдущей итерации, но без привязки к конкретному движку. В Godot это может быть Control + Theme + инстанцирование сцен; в MonoGame — собственный UI-toolkit.

### 7.2. Структура описания UI-элемента

Каждый UI-элемент описывается структурой:

```
UIElementDescriptor:
├── type: enum (Panel / Button / Label / Image / Slot / ProgressBar / ...)
├── id: string                          # для темизации и поиска
├── rect: RectPpm                       # позиция и размер в промилле
├── themeKey: string                    # ключ в теме «Древний Пергамент»
├── children: List<UIElementDescriptor> # иерархия
└── bindings: List<Binding>             # привязки к данным/событиям
```

### 7.3. Роль UI Builder

```
[Конфигурация UI (тема + дескрипторы)]
            │
            ▼
[UI Builder]
    │
    ├── Создаёт визуальные элементы по дескриптору
    ├── Применяет тему (цвета, шрифты, отступы)
    ├── Привязывает данные (data binding)
    └── Привязывает события (event binding)
            │
            ▼
[UI Tree (движко-специфичные ноды)]
```

### 7.4. Преимущества

1. **Воспроизводимость** — UI собирается из кода, а не из бинарного файла сцены. Это упрощает AI-агентный цикл (см. `09_workflow/AI_DEVELOPMENT_WORKFLOW.md`).
2. **Git-совместимость** — изменения UI видны как diff в исходниках, а не в бинарниках.
3. **Тестируемость** — UI-дескрипторы можно валидировать в headless-тестах (без рендера).
4. **Портабельность** — при смене движка меняется только UI Builder, не дескрипторы.

### 7.5. Тема как ресурс данных

Тема «Древний Пергамент» хранится как ресурс данных (JSON/текстовый ресурс) с полями:
- `colors` — палитра (HEX-строки).
- `fonts` — имена шрифтов и размеры (в промилле).
- `spacing` — отступы (в промилле).
- `borders` — толщина и стиль рамок.
- `icons` — mapping идентификаторов на Unicode-глифы или пути к ассетам.

В Godot это может быть `.tres` Theme-ресурс; в MonoGame — JSON-конфиг. В обоих случаях — текстовый, git-friendly.

## 8. Текстовый рендеринг

### 8.1. Шрифты

| Категория | Назначение | Источник |
|-----------|------------|----------|
| Primary | Основной текст UI (кириллица + латиница) | OS font with Cyrillic support (DejaVu Sans, Noto Sans, системный) |
| Fallback | Unicode-глифы (◆ ○ ★ ✓ ◇ ▰ и т. д.) | Встроенный TTF-шрифт с покрытием U+2500–U+25FF, U+2600–U+26FF |
| Monospace | Числа, таблицы, код | OS monospace (DejaVu Sans Mono, Consolas) |

### 8.2. Цепочка fallback

```
Primary (кириллица + латиница)
    ↓ если глиф отсутствует
Fallback (Unicode-глифы)
    ↓ если глиф отсутствует
□ (стандартный заменитель, U+25A1)
```

### 8.3. Размеры шрифтов

| Роль | Размер (‰ от высоты) | На 1080p |
|------|----------------------|----------|
| Title | 28 | ~30 px |
| Header | 22 | ~24 px |
| Body | 18 | ~19 px |
| Caption | 14 | ~15 px |
| Tiny (numbers, hints) | 12 | ~13 px |

### 8.4. Особенности

- Текст рендерится с anti-aliasing.
- Не используется SDF-текст (избыточно для 2D-игры с фиксированным разрешением).
- Поддерживается RTL? — Нет. Кириллица/латиница — LTR.
- Поддерживается перенос строк? — Да, по словам, с учётом ширины контейнера.

## 9. Layout-контейнеры

> Эти термины движко-нейтральны; в конкретном движке могут называться иначе.

| Контейнер | Назначение |
|-----------|------------|
| `Panel` | Прямоугольная область с фоном и рамкой. Базовый контейнер. |
| `Stack (Vertical)` | Вертикальная компоновка детей сверху вниз. |
| `Stack (Horizontal)` | Горизонтальная компоновка детей слева направо. |
| `Grid` | Регулярная сетка N×M ячеек (для слотов инвентаря, хотбара). |
| `Wrap` | Пото­ковая компоновка с переносом (для тегов, иконок). |
| `Scroll Area` | Область с прокруткой, содержит один ребёнок-контент. |
| `Overlay` | Дети накладываются друг на друга (z-order по индексу). |
| `Tabs` | Контейнер вкладок: TabsList + несколько TabsContent. |

### 9.1. Динамический размер контента

- `AutoSize` — размер контейнера подстраивается под содержимое (для тултипов).
- `Fill` — элемент заполняет доступное пространство родителя.
- `Fixed (Ppm)` — фиксированный размер в промилле.

## 12. Адаптивность и доступность

### 12.1. Адаптивность

UI рассчитан на десктоп (1920×1080). Адаптация под ультраширокие мониторы (21:9, 32:9) — через чёрные полосы по бокам (UI не растягивается).

### 12.2. Доступность

- Минимальный контраст текста: 4.5:1 (WCAG AA).
- Размер шрифта Body ≥ 18 px на 1080p.
- Все действия дублируются горячими клавишами (см. `HOTKEYS.md`).
- Цветовая индикация дублируется глифами (для дальтоников): например, редкость обозначается и цветом рамки, и количеством звёздочек `★`.

## 13. Анимации UI

| Анимация | Применение | Длительность |
|----------|------------|--------------|
| Fade-in / Fade-out | Открытие/закрытие панелей | 0.15 с |
| Scale-in | Появление тултипа | 0.10 с |
| Pulse | Критическое состояние (HP, статуса) | 1.0 с цикл |
| Highlight | Подсветка валидного/невалидного слота при drag | мгновенно |
| Slide | Появление тоста-уведомления | 0.20 с |
| Shimmer | Длительная операция (открытие складки) | 1.5–2.0 с |

> Все анимации UI — короткие (≤ 0.3 с), чтобы не задерживать игрока.

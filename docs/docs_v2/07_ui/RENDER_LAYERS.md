# Render Layers (слои рендеринга 2D)

> **Назначение:** Движко-независимая спецификация порядка рендеринга 2D-объектов. 6 слоёв (Default, Background, Terrain, Objects, Player, UI), порядок отрисовки, управление кодом.
>
> **Связанные документы:** `UI_DESIGN.md`, `SPRITE_CATALOG.md`, `03_world/TILE_SYSTEM.md`.

---

## 1. Принцип

2D-рендерер отрисовывает спрайты **снизу вверх**: слой с меньшим индексом рисуется **позади**, слой с большим индексом — **поверх**. Внутри одного слоя порядок определяется числовым `orderInLayer` (меньше = позади).

```
Камера (ортографическая, 2D)
  │
  ▼ Порядок рендеринга (позади → впереди):

  ┌─────────────────────────────────────────────────────┐
  │  [0] Default     — fallback (НЕ используется)        │
  │  [1] Background  — фоновые декорации, параллакс      │
  │  [2] Terrain     — поверхность (травa, вода, лава)   │
  │  [3] Objects     — деревья, камни, ресурсы, дроп     │
  │  [4] Player      — игрок и его тень                  │
  │  [5] UI          — UI в мировом пространстве         │
  └─────────────────────────────────────────────────────┘

  layerID = индекс слоя (0,1,2,3,4,5) — ДЕТЕРМИНИРОВАННО
```

> Идентификатор каждого слоя = его индекс. Это гарантирует одинаковый порядок на любой машине и в любом движке.

---

## 2. Зачем 6 слоёв

| Слой | Индекс | Назначение |
|------|--------|------------|
| Default | 0 | Зарезервирован как fallback; **запрещён для использования** |
| Background | 1 | Фоновые параллакс-слои, небо, далёкие горы |
| Terrain | 2 | Поверхность земли/воды/лавы (тайлмапы) |
| Objects | 3 | Деревья, камни, ресурсы, дроп, объекты окружения |
| Player | 4 | Игрок и его тень |
| UI | 5 | UI-элементы в мировом пространстве (внутриигровые floating-text, формация-preview) |

> 6 слоёв достаточно для всех нужд 2D top-down игры. Больше слоёв = больше сложности без выгоды.

---

## 3. Подробное описание слоёв

### 3.1. Слой [0] Default — ❌ ЗАПРЕЩЁН

Используется только как fallback движка: если рендереру не назначен слой, он попадает на Default и рендерится в неопределённом порядке.

> **Правило:** Любой визуальный объект должен иметь явно назначенный слой из списка [1..5]. Объекты на Default — баг. При обнаружении — немедленно назначить корректный слой.

### 3.2. Слой [1] Background — фоновые декорации

| Объект | orderInLayer | Примечание |
|--------|-------------|------------|
| Параллакс-слой 1 (далёкие горы) | 0 | Самый дальний |
| Параллакс-слой 2 (облака) | 1 | |
| Параллакс-слой 3 (ближний фон) | 2 | |
| Небо | 0 | Заливка |

> Зарезервирован для фоновых параллакс-слоёв. В v1 может быть пустым.

### 3.3. Слой [2] Terrain — поверхность

| Объект | orderInLayer | Описание |
|--------|-------------|----------|
| TerrainTilemap | 0 | Базовые тайлы: Grass, Dirt, Stone, Water, Sand, Snow, Ice, Lava, Void |
| Sub-overlay (опционально) | 1 | Декоративные элементы на тайлах (трещины, пятна) |

Тайлы поверхности — **процедурные спрайты** 64×64 @ PPU=32, FilterMode=Point (см. `SPRITE_CATALOG.md`).

### 3.4. Слой [3] Objects — объекты окружения

| Объект | orderInLayer | Описание |
|--------|-------------|----------|
| ObjectTilemap (базовый) | 0 | Стационарные объекты-тайлы (стены, двери) |
| OverlayTilemap | 10 | Декоративный overlay (ковры, разметка) |
| Herb (собираемое) | 1 | Травы |
| Bush | 2 | Кусты |
| Rock_Small / Rock_Medium | 3 | Камни |
| OreVein (рудная жила) | 4 | Доступно для добычи |
| Tree (Oak/Pine/Birch) | 5 | Деревья |
| Resource pickups | 5 | Подбираемые ресурсы в мире |
| Drop items | 5 | Выкинутые/выпавшие предметы |

#### Y-сортировка

> **Принцип:** Внутри слоя Objects порядок рендеринга должен зависеть от Y-позиции объекта, а не от типа. Это решает проблему «все деревья рисуются поверх всех камней».

```
orderInLayer = baseForObjectType + (-Y_position × Y_SORT_FACTOR)
```

Где `Y_SORT_FACTOR` — коэффициент (обычно 10), `baseForObjectType` — смещение по типу объекта (1 для трав, 5 для деревьев).

Пример: дерево на Y=5 и камень на Y=10 — камень рисуется поверх дерева, т. к. он «ближе к камере».

### 3.5. Слой [4] Player — игрок

| Объект | orderInLayer | Описание |
|--------|-------------|----------|
| Player Shadow | -1 | Тень под игроком (рисуется первой) |
| Player Visual | 0 | Базовый спрайт игрока 128×128 @ PPU=64 |
| Equipped layers | 1..N | Надетая экипировка как overlay-спрайты |
| Orbital weapons | 10 | Оружие на орбите вокруг игрока |
| Player effects | 20 | Аура Ци, эффекты медитации/прорыва |

> **Fallback:** Если слой Player недоступен (по какой-то причине), рендерер переводит игрока на слой Objects с `orderInLayer = 100` — гарантированно поверх terrain и большинства объектов.

### 3.6. Слой [5] UI — UI в мировом пространстве

| Объект | orderInLayer | Описание |
|--------|-------------|----------|
| Formation preview | 1000 | Предпросмотр формации в мире |
| Floating damage text | 1500 | Всплывающие числа урона/исцеления |
| Harvest feedback | 100 | Индикатор собранного ресурса |
| World-space tooltips | 2000 | Подсказки над объектами в мире |

> **Не путать** с экранным UI (HUD/Windows/Tooltips) — те рендерятся отдельным экранным UI-слоем (см. `UI_DESIGN.md` §5). Слой UI здесь — для **мирового** UI, привязанного к мировым координатам.

## 4. Управление слоями кодом

### 4.1. Источник истины — код

Список слоёв и их порядок определяются **в коде**, а не в визуальных настройках проекта. Это обеспечивает:
- Воспроизводимость на любой машине (не зависит от настроек редактора).
- Git-совместимость (настройки — текстовый код).
- AI-агентный цикл (AI может редактировать код, не открывая редактор).

### 4.2. Константа слоёв

```
REQUIRED_RENDER_LAYERS = [
  "Default",     // 0
  "Background",  // 1
  "Terrain",     // 2
  "Objects",     // 3
  "Player",      // 4
  "UI"           // 5
]
```

Индекс в массиве = `layerID` = `orderInLayer` группы.

### 4.3. Назначение слоя рендереру

| Тип объекта | Слой | orderInLayer |
|-------------|------|--------------|
| Terrain Tilemap | `Terrain` | 0 |
| Objects Tilemap | `Objects` | 0 |
| Overlay Tilemap | `Objects` | 10 |
| Player Sprite | `Player` | 0 |
| Player Shadow | `Player` | -1 |
| Harvestable Sprite | `Objects` | по типу (1–5) |
| Resource/Drop Sprite | `Objects` | 5 |
| Formation Preview Sprite | `UI` | 1000 |
| Floating Text | `UI` | 1500 |

## 5. Детерминизм

### 5.1. Принцип

Идентификатор каждого слоя = его индекс в массиве `REQUIRED_RENDER_LAYERS`. Это **детерминированно**:

| Индекс | Имя слоя | layerID |
|--------|----------|---------|
| 0 | Default | 0 |
| 1 | Background | 1 |
| 2 | Terrain | 2 |
| 3 | Objects | 3 |
| 4 | Player | 4 |
| 5 | UI | 5 |

### 5.2. Зачем это важно

В движках слои часто идентифицируются строкой + внутренним числовым ID. Если этот ID генерируется случайно (или зависит от порядка создания), порядок рендеринга может отличаться на разных машинах даже при одинаковых именах слоёв.

Жёсткая привязка `layerID = индекс` гарантирует:
- Один и тот же порядок на любой машине.
- Воспроизводимость багов и тестов.
- Корректность headless-тестов (см. `09_workflow/TESTING_RULES.md`).

## 6. Проверка и диагностика

### 6.1. Уровни диагностики

Рендер-пайплайн предоставляет 9 уровней логирования для диагностики проблем со слоями:

| Уровень | Что проверяет |
|---------|---------------|
| L1 | Существование всех 6 слоёв |
| L2 | Состояние тайлмапов: слой, order, кол-во тайлов |
| L3 | Состояние импорта спрайтов: PPU, alphaIsTransparency |
| L4 | Кол-во отрисованных terrain/object тайлов |
| L5 | Состояние Player Sprite: слой, шейдер |
| L6 | Состояние harvestable-спрайтов: слой, order |
| L7 | Состояние камеры: ortho, position, size |
| L8 | Состояние освещения (если применимо) |
| **L9** | **Полный аудит всех рендереров: порядок слоёв, обнаружение объектов на Default, проверка видимости Player** |

### 6.2. Типичные баги

| Баг | Симптом | Причина | Решение |
|-----|---------|---------|---------|
| Объект на Default | Объект рисуется поверх всех слоёв | Рендереру не назначен слой | Назначить корректный слой из [1..5] |
| Terrain поверх Player | Игрок не виден за тайлами | Слой Player имеет индекс < Terrain | Проверить `REQUIRED_RENDER_LAYERS` порядок |
| Объекты поверх UI | UI не виден | Слой UI имеет индекс < Objects | Проверить `REQUIRED_RENDER_LAYERS` порядок |
| Деревья поверх всех камней | Все деревья рисуются поверх всех камней | Нет Y-сортировки, только по типу | Внедрить Y-сортировку (см. §3.4) |
| Белая сетка между тайлами | Видимые зазоры между тайлами terrain | PNG-спрайты через pipeline с субпиксельными зазорами | Использовать процедурные спрайты 64×64 @ PPU=32, FilterMode=Point |

# Процедурные спрайты (Procedural Sprites)

> **Назначение:** Движко-независимая спецификация принципа процедурной генерации спрайтов в рантайме. Все спрайты в игре рисуются кодом через Image API, без PNG-ассетов.
>
> **Связанные документы:** [RENDER_LAYERS.md](./RENDER_LAYERS.md), [UI_DESIGN.md](./UI_DESIGN.md), [GROUND_ITEM_SYSTEM.md §5](../06_player/GROUND_ITEM_SYSTEM.md), [ANIMALS.md §6](../04_entities/ANIMALS.md), [EQUIPMENT_SYSTEM.md](../06_player/EQUIPMENT_SYSTEM.md).

---

## 1. Принцип

### 1.1. Runtime-генерация
- Все спрайты в игре **рисуются кодом в рантайме** через Image API (Canvas / Image / Draw calls движка).
- PNG/JPG/WebP-ассеты в проекте отсутствуют (для placeholder-фазы разработки).
- Это позволяет быстро итерировать дизайн без участия художника.

### 1.2. Заменяемость
- Процедурные спрайты — **placeholder**. В будущем заменяются на нарисованные художниками PNG-спрайты.
- Контракт рендеринга (URL/ID спрайта по ключу) сохраняется — замена ассетов не требует правок в игровом коде.

---

## 2. Кэширование

### 2.1. Принцип
- Спрайт создаётся **один раз** при первом запросе по ключу (например, `wolf`, `npc_guard`, `ground_item_weapon`).
- Созданный Image кэшируется и переиспользуется всеми экземплярами.
- Все экземпляры волка используют один и тот же Image.

### 2.2. Ключ кэша
- Для сущностей с ролями/видами — ключ = `<category>:<role_or_species>`.
- Для экипировки — ключ = `equip:<slot>:<rarity>` (без материала/грейда, т.к. цвет редкости красится отдельно).
- Для предметов на земле — ключ = `ground:<category>`.

### 2.3. Производительность
- Создание Image относительно дёшево, но не бесплатно.
- Кэш предотвращает повторные генерации при каждом кадре.
- См. [PERFORMANCE_STRATEGY.md](../01_architecture/PERFORMANCE_STRATEGY.md).

## 4. Технические принципы генерации

### 4.1. Слои рисования
Процедурный спрайт обычно состоит из нескольких слоёв:
1. **Силуэт** (базовая форма + цвет).
2. **Детали** (черты лица, одежда, оружие).
3. **Индикатор роли/категории** (символ в углу).
4. **Цветовая маркировка** (редкость/состояние).

### 4.2. Детерминированность
- Все случайные элементы (позиция деталей, оттенки) используют `SeededRandom` с фиксированным seed.
- Одинаковый seed → одинаковый спрайт (важно для воспроизводимости и тестов).

### 4.3. NEAREST texture filter
- Для пиксельной чёткости используется фильтр `NEAREST` (а не `LINEAR`).
- См. [PERFORMANCE_STRATEGY.md](../01_architecture/PERFORMANCE_STRATEGY.md) — `textures/canvas_textures/default_texture_filter=0`.

## 5. План миграции на PNG

Процедурные спрайты — временная мера. План замены:

1. Художник рисует PNG-ассет для каждой категории.
2. PNG кладётся в `assets/sprites/<category>/<key>.png`.
3. Спрайт-провайдер переключается на загрузку PNG (с тем же ключом кэша).
4. Менять ничего в игровом коде не требуется — контракт по ключу сохраняется.

> См. [SPRITE_PIPELINE.md](./SPRITE_PIPELINE.md) и [SPRITE_CATALOG.md](./SPRITE_CATALOG.md) для плана ассетов.

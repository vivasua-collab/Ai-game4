## 1. Принцип

Торговля — обмен предметами с NPC-торговцами за **духовные камни** (валюта). Торговец — NPC с ролью `Merchant` (диспозиция мирная). Вход в лавку — через диалог: реплика «Покажи товары» является sentinel-командой открытия.

- **Валюта:** духовные камни (`int`, ЗАПРЕТ 3.9 — целочисленная арифметика). Лор: «твёрдое» Ци, расходник (LORE_SYSTEM §9.2).
- **Стартовый баланс игрока:** 50 камней (TradeConfig.StartStones).
- **Модуль:** `Modules/Trade` — 17-й модуль (event-driven, без per-tick работы). Регистрация между Interaction и UI (GameLifetimeScope).

## 2. Контракты (Core/Messaging/Contracts/TradeContracts.cs)

| Событие | Направление | Семантика |
|---|---|---|
| `TradeRequestedEvent(NpcId)` | DialogueService → TradeModule | Диалог просит открыть лавку (sentinel-реплика) |
| `TradeOpenedEvent(NpcId)` | TradeService → UI | Лавка открыта |
| `TradeClosedEvent` | TradeService → GameWorldController | Лавка закрыта (единая точка резюма тиков) |
| `TradeCompletedEvent(NpcId, ItemId, Count, IsPurchase, Price)` | TradeService → UI/журнал | Сделка совершена |
| `TradeFailedEvent(Reason)` | TradeService → UI | Сделка отклонена (нет камней / нет предмета) |
| `CurrencyChangedEvent(Balance)` | CurrencyService → UI | Баланс изменился |

> **Порядок критичен:** `EndDialogue` публикуется ДО `TradeRequestedEvent` — иначе resume диалога наложится на паузу лавки.

## 3. Ассортимент мерчанта (сток)

Генерируется при первом обращении, **детерминированно** от `npcId` (FNV-1a → seeded random):

| Категория | Кол-во видов | Уровни/размеры |
|---|---|---|
| Оружие | 1–2 | генератор «Матрёшка», L1–3 |
| Броня | 1–2 | генератор «Матрёшка», L1–3 |
| Расходники | 3–4 вида | стеки по 2–5 шт. |
| Материалы | 1 вид | стек 3–8 шт. |

> Лор-оговорка (аудит 2026-09-06): ресток/первичная генерация стока пока не объяснена законом сохранения материи — закрыть при разработке экономики (караваны/добыча торговца).

## 4. Ценообразование (Permil)

| Операция | Формула | Конфиг |
|---|---|---|
| Покупка игроком | `базовая Value × 1200‰` (×1.2) | `MarkupPermil` |
| Продажа игроком | `базовая Value × 500‰` (×0.5) | `SellPermil` |

Все расчёты целочисленные. Цены фиксируются по предмету (GetBuyPrice/GetSellPrice).

## 5. UI: TradeWindow «Лавка торговца»

- Окно 900×600, центрированное, модальное (пауза тиков).
- Вкладки **Товары / Инвентарь**; ЛКМ = купить/продать 1 шт., Shift+ЛКМ = 5 шт.; Esc — закрыть.
- **UX (S6, 2026-09-06):**
  - Пометка «не хватает камней»: тусклое имя (alpha 0.55) + красная цена; снимается автоматически при пополнении баланса (подписка CurrencyChanged → RefreshAll).
  - Тултип строки: имя + описание + редкость + цена за 1 шт. + предупреждение «⚠ Не хватает духовных камней».
  - Hover-подсветка строк (Modulate-тинт).
  - Футер честно упоминает Esc.

## 6. Интеграция

- **Диалог:** merchant-реплика с sentinel-действием `open_trade` → `TradeRequestedEvent`.
- **Инвентарь:** покупка → `IInventoryService.TryAddItem`; продажа → `TryRemoveItem`.
- **ItemDatabase:** резолв itemId → ItemData (описания/редкость/Value для тултипов и цен).
- **HUD:** баланс камней в шапке лавки (+ подписка CurrencyChangedEvent для мгновенного обновления).

## 8. Открытые вопросы

1. **Экономика камней Ци:** духовные камни одновременно валюта и расходник Ци — курс/конвертация не специфицированы.
2. **Ресток:** условия обновления ассортимента (сезон? событие? поставки?).
3. **Динамика цен:** отношение NPC (attitude) пока не влияет на MarkupPermil — потенциальная связка с NPCRelationshipService.
4. **Ограничение веса/объёма покупки** — не реализовано.

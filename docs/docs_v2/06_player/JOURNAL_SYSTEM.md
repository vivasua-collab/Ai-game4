# Система журнала (Journal System)

> **Назначение:** Движко-независимая спецификация журнала игрока. Описывает типы записей, фильтры, прогресс заполнения, точки открытия и UI-представление.
>
> **Связанные документы:** `08_content/LORE_SYSTEM.md`, `04_entities/FACTION_SYSTEM.md`, `07_ui/UI_DESIGN.md`, `05_data/SAVE_SYSTEM.md`.

---

## 1. Обзор

Журнал хранит информацию, собранную игроком во время игры:

- Записи о персонажах (NPC, враги).
- Информация о локациях.
- Изученные техники.
- Открытые элементы лора.
- Прогресс квестов.
- Собственные заметки игрока.

Журнал — это **модуль-наблюдатель**: подписывается на события других систем (встреча с NPC, посещение локации, изучение техники, нахождение предмета) и автоматически открывает соответствующие записи. Не инжектит сервисы других модулей.

Открытие/закрытие окна журнала — горячая клавиша **J** (см. `07_ui/HOTKEYS.md`).

## 2. Категории журнала (8)

| Категория | Описание | Иконка-глиф |
|-----------|----------|-------------|
| `Characters` | Персонажи (NPC, враги) | ◆ |
| `Locations` | Локации и области | ◇ |
| `Techniques` | Изученные техники | ★ |
| `Creatures` | Существа и монстры | ◯ |
| `Items` | Редкие предметы | ▰ |
| `Lore` | История мира | ✓ (или лор-глиф) |
| `Factions` | Фракции и секты | ◆ |
| `Notes` | Заметки игрока | ▱ |

> Используются Unicode-глифы (см. `07_ui/UI_DESIGN.md` §3 «Тема Древний Пергамент»), не эмодзи — для единообразия со стилистикой UI.

## 3. Структура записи (JournalEntry)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Уникальный идентификатор записи |
| `title` | string | Название |
| `category` | JournalCategory | Категория |
| `rarity` | EntryRarity | Редкость записи |
| `description` | string | Краткое описание (открывается сразу) |
| `extendedDescription` | string | Полное описание (открывается при прогрессе ≥ 100%) |
| `isDiscovered` | bool | Открыта ли запись |
| `discoveryDate` | DateTime (игровое) | Дата открытия в игровом календаре |
| `discoveryLocation` | string | Локация открытия |
| `completionLevel` | int (0–100) | Прогресс заполнения записи, % |
| `unlockedFacts` | List<string> | Открытые факты (список ID) |
| `relatedEntries` | List<string> | ID связанных записей |
| `tags` | List<string> | Теги для поиска |
| `icon` | string | Иконка (Unicode-глиф или путь к ассету) |
| `categoryColor` | Color | Цвет категории |

---

## 4. Подтип: LoreEntry (запись лора)

Расширяет `JournalEntry` дополнительными полями:

| Поле | Тип | Описание |
|------|-----|----------|
| `era` | string | Эра/период (см. `08_content/LORE_SYSTEM.md`) |
| `keyFigures` | List<string> | Ключевые фигуры |
| `locations` | List<string> | Упомянутые локации |
| `events` | List<string> | Связанные события |
| `hiddenText` | string | Текст, открывающийся при выполнении условия |
| `unlockCondition` | string | Условие открытия скрытого текста |

---

## 5. Подтип: PlayerNote (заметка игрока)

Игрок может создавать собственные заметки:

| Поле | Тип | Описание |
|------|-----|----------|
| `createdDate` | DateTime | Дата создания (игровое время) |
| `lastModifiedDate` | DateTime | Дата последнего изменения |

Заметка наследует `JournalEntry` (категория `Notes`). Игрок может редактировать текст, переименовывать, удалять.

## 6. Редкость записей (6 уровней)

| Редкость | Цвет рамки | Назначение |
|----------|------------|------------|
| Common | Серый | Обычные записи |
| Uncommon | Зелёный | Необычные находки |
| Rare | Синий | Редкие объекты |
| Epic | Фиолетовый | Эпические события |
| Legendary | Золотой | Легендарные личности/места |
| Mythic | Красный | Мифические истины мира |

> 6 уровней редкости соответствуют системе редкости предметов (см. `INVENTORY_SYSTEM.md` §2.4).

## 7. Механика открытия и прогресса

### 7.1. Открытие записи

При первом срабатывании триггера запись становится видимой (`isDiscovered = true`) с базовым прогрессом `completionLevel = 10%`.

Если запись уже открыта — повторный триггер увеличивает прогресс на фиксированное значение (обычно +10%).

### 7.2. Добавление фактов

При добавлении нового факта к записи:
- Если факт ещё не открыт — добавить в `unlockedFacts`.
- Прогресс записи увеличивается на +15%.

### 7.3. Полное заполнение

При `completionLevel ≥ 100%`:
- Открывается `extendedDescription`.
- Срабатывает событие «запись завершена» (для ачивок, лора).
- Запись помечается как завершённая в UI (зелёная галочка ✓).

## 8. Точки открытия (триггеры)

| Событие | Действие |
|---------|----------|
| Встреча с NPC (в радиусе взаимодействия) | `DiscoverEntry("npc_" + npcId)` |
| Посещение локации (вход в зону) | `DiscoverEntry("location_" + locId)` |
| Изучение техники | `DiscoverEntry("technique_" + techId)` |
| Убийство существа (первое) | `DiscoverEntry("creature_" + mobId)` |
| Находка предмета (первая) | `DiscoverEntry("item_" + itemId)` |
| Прогресс квеста | `AddFact(entryId, "quest_fact_N")` |
| Разговор с NPC (ключевой диалог) | `AddFact(entryId, "dialog_fact_N")` |
| Открытие фракции | `DiscoverEntry("faction_" + factionId)` |
| Открытие элемента лора (через свиток/артефакт) | `DiscoverEntry("lore_" + loreId)` |

---

## 9. Связанные записи

Каждая запись может иметь список `relatedEntries` (ID связанных). В UI отображаются только те связанные записи, которые уже открыты у игрока. Это позволяет:
- Подталкивать игрока к исследованию (видны «намёки» на связанные темы).
- Не спойлерить неоткрытые темы.

---

## 10. Поиск

Журнал поддерживает два типа поиска:

1. **По тегу** — `SearchByTag(tag)` возвращает все открытые записи с указанным тегом.
2. **По тексту** — `SearchByText(query)` ищет совпадения в `title` и `description` (case-insensitive), только среди открытых записей.

## 12. Сохранение

Журнал сохраняется через стандартный механизм сохранений (см. `05_data/SAVE_SYSTEM.md`).

### Структура JournalSaveData

```
JournalSaveData:
├── discoveredEntries: List<string>     # ID открытых записей
├── completionData: Dictionary<string, int>      # completionLevel по ID
└── factsData: Dictionary<string, List<string>>  # unlockedFacts по ID
```

Сохраняются только прогресс и факты. Содержимое записей (`description`, `extendedDescription`, `icon`, ...) хранится в статических данных конфигурации и не дублируется в сейв.

---

## 13. Статистика

Журнал предоставляет статистику для UI и достижений:

| Метрика | Метод |
|---------|-------|
| Общий прогресс | `GetOverallProgress()` → `discovered / total` |
| Прогресс по категории | `GetCategoryProgress(category)` → `discovered_in_category / total_in_category` |
| Кол-во открытых/всего | `GetEntryCount()` → `(discovered, total)` |

# Система AI NPC

> **Раздел:** Сущности мира — AI
> **Статус:** Концептуальная спецификация (дизайн-документ)
> **Самостоятельный документ:** не требует иных файлов для понимания.
>
> Этот документ описывает **архитектуру AI NPC**: трёхуровневую нервную систему, Behavior Tree, FSM (15 состояний), систему угроз, систему навигации. Все алгоритмы описаны как **чистый C# модуль** без зависимости от движка.

---

## 1. Назначение

Система AI управляет поведением NPC, их реакциями и взаимодействиями с миром и игроком. Цели:
1. **Живой мир** — NPC ведут себя естественно и предсказуемо.
2. **Разнообразие** — разные типы NPC имеют разное поведение.
3. **Производительность** — AI не должен тормозить игру (100+ NPC одновременно).
4. **Масштабируемость** — легко добавлять новые поведения.

> **Архитектурный принцип:** Весь AI — **чистый C# код** (без движковых типов). Запускается на worker thread (sim-поток), взаимодействует с другими модулями через **шину событий**.

---

## 2. Трёхуровневая нервная система

Архитектура вдохновлена **биологической нервной системой** живых существ. AI разделён на три уровня с разной скоростью и сложностью:

```
УРОВЕНЬ 3: BRAIN CONTROLLER (Мозг)
├── Сложные решения, диалоги, планирование
├── Скорость: 100–500 мс (медленно)
└── Затраты: Высокие (LLM или продвинутый AI)
        ▲
        │ Нервные волокна (асинхронная передача)
        │
УРОВЕНЬ 2: NEURAL ROUTER (Нервная система)
├── Маршрутизация сигналов, буферизация
├── Скорость: 10–50 мс
└── Затраты: Минимальные
        ▲
        │ Спинной мозг
        │
УРОВЕНЬ 1: SPINAL AI (Позвоночник) ← ПЕРВИЧНЫЙ
├── Рефлексы, автоматические реакции
├── Скорость: 1–10 мс (очень быстро)
└── Затраты: Минимальные
```

### 2.1. Уровень 1: Spinal AI (Рефлексы)

**Назначение:** быстрая, лёгкая система автоматических реакций («подсознание» NPC). Работает без участия высших уровней, обеспечивает мгновенный отклик на физические стимулы.

**Характеристики:**
- Скорость реакции: **1–10 мс** (1–2 кадра).
- Вычислительная сложность: O(1) – O(n).
- Память: минимальная (только текущее состояние).

**Типы входных сигналов:**

| Тип сигнала | Описание | Пример |
|-------------|----------|--------|
| `collision`      | Столкновение | Столкновение с препятствием |
| `damage`         | Получен урон | Удар противника |
| `danger_nearby`  | Опасность рядом | Приближение врага |
| `edge_detected`  | Край обнаружен | Обрыв, вода |
| `loud_sound`     | Громкий звук | Взрыв, крик |
| `temperature`    | Температура | Огонь, холод |
| `balance_lost`   | Потеря равновесия | Подножка |
| `hunger`         | Голод | Низкий уровень сытости |
| `fatigue`        | Усталость | Низкий уровень энергии |

**Типы рефлексов:**

| Рефлекс | Триггер | Действие | Приоритет |
|---------|---------|----------|-----------|
| Dodge            | Снаряд приближается | Уклонение | 100 (критический) |
| QiShield         | Атака Ци | Авто-щит | 95 |
| Flinch           | Получен урон | Отшатывание | 90 |
| StepBack         | Край обнаружен | Отойти от края | 85 |
| Stumble          | Столкновение | Пошатнуться | 80 |
| BalanceRecover   | Потеря равновесия | Восстановить баланс | 70 |
| TurnToSound      | Громкий звук | Повернуться | 30 |

**Параметры рефлексов:**
- `triggerDistance` — расстояние срабатывания;
- `reactionTime` — время реакции (мс);
- `cooldown` — перезарядка (мс);
- `qiCost` — стоимость Ци (для qi_shield);
- `priority` — приоритет (0–100);
- `canInterrupt` — можно ли прервать другой рефлекс.

### 2.2. Уровень 2: Neural Router (Нервная система)

**Назначение:** промежуточный уровень между Spinal AI и Brain Controller. Обеспечивает маршрутизацию, буферизацию и приоритизацию сигналов.

**Функции:**

| Функция | Описание |
|---------|----------|
| Буферизация | Очереди сигналов с приоритетами |
| Маршрутизация | Spinal ↔ Brain |
| Агрегация | Объединение похожих сигналов |
| Фильтрация | Отсечение шума |
| Кэширование | Кэш частых запросов |
| Внимание | Управление фокусом NPC |

**Приоритеты сигналов:**

| Приоритет | Тип сигнала | Пример |
|-----------|-------------|--------|
| `critical` | Опасность для жизни | Атака L9 практика |
| `high`     | Важные события | Появление врага |
| `medium`   | Обычные события | Звук шагов |
| `low`      | Фоновые сигналы | Погода, время суток |

### 2.3. Уровень 3: Brain Controller (Мозг)

**Назначение:** когнитивный уровень AI для сложных решений, диалогов и планирования.

**Типы запросов к Brain:**

| Тип запроса | Описание |
|-------------|----------|
| `dialogue_generate`  | Генерация реплики в диалоге |
| `decision_make`      | Принятие сложного решения |
| `plan_create`        | Создание долгосрочного плана |
| `situation_analyze`  | Анализ ситуации |
| `emotion_determine`  | Определение эмоции |
| `goal_evaluate`      | Оценка целей |

**Контекст для Brain:**

| Данные | Описание |
|--------|----------|
| `npc.identity`      | Идентичность (имя, роль, личность) |
| `npc.state`         | Текущее состояние (HP, Qi, настроение) |
| `situation.location`| Локация, время суток |
| `situation.nearby`  | Существа поблизости |
| `player.info`       | Информация об игроке |
| `player.history`    | История взаимодействий |
| `world.events`      | Глобальные события |

> **Brain Controller** может быть реализован как LLM или продвинутый AI-планировщик. На начальных этапах разработки — заглушка с шаблонными ответами; позже — интеграция с внешним AI-сервисом.

## 3. Behavior Tree (дерево поведения)

### 3.1. Типы узлов

| Тип | Описание |
|-----|----------|
| `Selector`  | Выбирает первую успешную ветку |
| `Sequence`  | Выполняет все узлы по порядку |
| `Condition` | Проверка условия |
| `Action`    | Выполнение действия |

### 3.2. Пример дерева

```
Selector
├── Sequence (Combat)
│   ├── Condition: InCombat?
│   ├── Condition: HasTarget?
│   └── Action: Attack
│
├── Sequence (Alert)
│   ├── Condition: IsAlert?
│   └── Action: SearchArea
│
├── Sequence (Patrol)
│   ├── Condition: HasPatrolRoute?
│   └── Action: Patrol
│
└── Action: Idle
```

### 3.3. Архитектура верхнего уровня

```
СИСТЕМА NPC AI
├── BEHAVIOR TREE
│   └── SELECTOR (Выбор)
│       ├── Combat Node      — В бою?
│       ├── Alert Node       — Встревожен?
│       ├── Patrol Node      — Патруль
│       └── Idle Node        — Простой
│
├── SPINAL AI (Рефлексы) ← УРОВЕНЬ 1
│   ├── Dodge / Flinch / Flee / QiShield / Alert / StepBack / TurnToSound / BalanceRecover
│
├── NEURAL ROUTER ← УРОВЕНЬ 2
│   └── Маршрутизация сигналов, буферизация
│
└── STATE MACHINE (FSM) ← 15 состояний (см. ниже)
```

## 4. Машина состояний (FSM) — 15 состояний

### 4.1. Список состояний

| # | Состояние | Описание |
|---|-----------|----------|
| 1  | `Idle`         | Простой |
| 2  | `Wandering`    | Блуждание |
| 3  | `Patrolling`   | Патруль |
| 4  | `Following`    | Следование за целью |
| 5  | `Fleeing`      | Бегство |
| 6  | `Attacking`    | Атака |
| 7  | `Defending`    | Защита |
| 8  | `Meditating`   | Медитация |
| 9  | `Cultivating`  | Культивация (восстановление Ци) |
| 10 | `Resting`      | Отдых |
| 11 | `Trading`      | Торговля |
| 12 | `Talking`      | Разговор |
| 13 | `Working`      | Работа |
| 14 | `Searching`    | Поиск |
| 15 | `Guarding`     | Охрана |

### 4.2. Переходы между состояниями (основные)

| Текущее | Условие | Следующее |
|---------|---------|-----------|
| `Idle`    | Игрок в радиусе агрессии | `Attacking` (или `Fleeing`) |
| `Idle`    | Точка патруля | `Patrolling` |
| `Patrol`  | Игрок в радиусе агрессии | `Attacking` (или `Fleeing`) |
| `Attacking` | HP < 20% | `Fleeing` |
| `Attacking` | Цель мертва | `Patrolling` |
| `Fleeing` | В безопасности | `Patrolling` |
| `Fleeing` | HP = 0 | `Dead` (внешнее состояние) |

> Полная таблица переходов — реализационная деталь; концептуально FSM описывается 15 состояниями и условиями перехода, опирающимися на:
> - радиусы (AggroRadius, AttackRadius, FleeRadius);
> - Attitude (к цели);
> - PersonalityTrait (веса);
> - систему угроз (threatLevel > ThreatThreshold).

## 5. Система угроз с затуханием

### 5.1. Принцип

- `AddThreat(sourceId, level)` — добавить угрозу.
- При получении урона: `threatLevel += damage × 0.5`.
- Затухание: `threatLevel -= ThreatDecayRate × deltaTime` (по умолчанию 2/сек).
- При `threatLevel > ThreatThreshold` (по умолчанию 50) → добавление в `knownTargets`, переход в `Attacking`.

### 5.2. Выбор между атакой и бегством

```
if (aggressiveness > cautiousness) → Attacking
else → Fleeing
```

Где:
- `aggressiveness` = сумма весов от PersonalityTrait (Aggressive, Ambitious, Vengeful).
- `cautiousness` = сумма весов от PersonalityTrait (Cautious, Pacifist).

### 5.3. Переключение цели

| Условие | Действие |
|---------|----------|
| Текущая цель мертва | Выбрать новую из knownTargets |
| Более опасная цель (более высокий threatLevel) | Переключиться |
| HP < 20% | Перейти в Fleeing |

## 6. Навигация: grid-based pathfinding

### 6.1. Принцип

> **Grid-based pathfinding: 1 тайл = 1 тик.** Никакого NavMesh, никакогоnavigation mesh.

- Мир разбит на тайлы (tile grid).
- Движение NPC — дискретное: 1 тайл за 1 тик (с учётом `DefaultMoveSpeed`).
- Алгоритм поиска пути: **A\*** на сетке тайлов.
- Стоимость пути: 1 за прямой шаг, ~1.4 за диагональ.
- Препятствия: тайлы с пометкой `blocked`.

### 6.2. Производительность

- **A\* pathfinding:** ~5–50 мс на 100 NPC (зависит от размера карты).
- Кэширование путей: одинаковые запросы — один путь.
- Re-path: при изменении окружения (препятствие появилось/исчезло) — пересчёт.

### 6.3. Движение

- `DefaultMoveSpeed = 2 ед/сек` (базовая скорость).
- `FleeSpeedMultiplier = 1.5` (множитель скорости бегства → 3 ед/сек).
- Movement обрабатывается в `NPCMovementService.ProcessMovement()` каждый тик.

> **Почему не NavMesh:** NavMesh требует предварительной генерации меша для каждой локации, что усложняет процедурную генерацию и модификацию мира. Grid-based pathfinding тривиально работает с тайловой картой и легко интегрируется с системой тиков.

## 9. Целевая система

### 9.1. Выбор цели

1. **Проверка `aggroRadius`** — кто в радиусе обнаружения?
2. **Оценка угрозы** (уровень культивации, поведение, threatLevel).
3. **Приоритеты** (класс, раса, фракция, личное отношение).
4. **Выбор основной цели** — максимальный threatLevel среди knownTargets.

### 9.2. Переключение цели

| Условие | Действие |
|---------|----------|
| Текущая цель мертва | Выбрать новую |
| Более опасная цель (более высокий threatLevel) | Переключиться |
| HP < 20% | Бегство |

## 11. Архитектурное представление

Система AI NPC реализуется как **чистый C# модуль** (без движковых зависимостей):

| Компонент | Назначение |
|-----------|------------|
| Сервис AI NPC         | Оркестрирует Behavior Tree + FSM каждый тик |
| Контроллер рефлексов (Spinal) | Быстрые автоматические реакции |
| Маршрутизатор сигналов (Neural) | Буферизация и приоритизация сигналов |
| Контроллер мозга (Brain) | Когнитивные функции (заглушка / LLM) |
| Система угроз | Учёт угроз, затухание, выбор цели |
| Сервис движения | Grid-based pathfinding + перемещение |

> **Принцип:** Все алгоритмы — pure C#. Движок используется только для:
> - рендеринга визуального представления NPC;
> - обработки ввода игрока;
> - воспроизведения звука/анимации.

Кросс-модульные взаимодействия:
- Все события — через **шину событий** (неизменяемые структуры, zero-GC).
- Запросы к боевому модулю, модулю Ци, модулю тела — через интерфейсы, не прямые ссылки.

## 12. Производительность

| Подсистема | CPU @ 100 NPC |
|------------|---------------|
| Spinal AI (1–10 мс каденция) | ~0.5 мс |
| Neural Router (10–50 мс) | ~0.3 мс |
| Brain Controller (100–500 мс) | ~0.2 мс (заглушка) / ~5–50 мс (LLM) |
| FSM + Behavior Tree | ~0.5 мс |
| A* pathfinding | ~5–50 мс (с кэшированием) |
| Система угроз | ~0.2 мс |
| **Итого** | **~7–55 мс** на 100 NPC |

Стратегия:
- **Tick batching:** не все NPC обрабатываются каждый тик. Слабые NPC (Temp) — каждые 3–5 тиков. Сильные (Unique) — каждый тик.
- **Многопоточность:** AI-расчёты на worker thread (sim-поток); рендер — на основном потоке.
- **Кэширование путей:** одинаковые запросы → один путь.
- **Zero-GC:** все события и структуры — `readonly struct`, без аллокаций в hot-path.

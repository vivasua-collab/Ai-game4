# Система групп NPC

> **Статус:** SPEC (реализовано v1, расширение для глобальной карты — планируется)
> **Зависимости:** NPC_AI_SYSTEM.md, FACTION_SYSTEM.md, NPC_ASSEMBLY_PIPELINE.md

---

## 1. Назначение

Система групп NPC — это надстройка над самостоятельным поведением NPC. Группа объединяет нескольких NPC одной фракции или вида для выполнения общей задачи. У группы есть:

- **Цель** — объект или место привязки, маршрут следования
- **Задача** — тип поведения группы (патруль, сопровождение, охрана, охота, караван)
- **Лидер** — NPC, определяющий движение группы
- **Участники** — NPC, следующие за лидером

Группа не заменяет индивидуальный AI NPC — она задаёт приоритетную цель движения. Если NPC в группе, групповая цель имеет приоритет над индивидуальным поведением (блуждание, патруль). Если NPC вне группы — работает индивидуальный AI.

---

## 2. Жизненный цикл группы

1. **Создание** — группа создаётся с типом задачи, фракцией и видом
2. **Наполнение** — участники добавляются в группу, назначается лидер
3. **Действие** — группа выполняет задачу (тик обновляет цели участников)
4. **Расформирование** — группа распускается при:
   - Смерти всех участников
   - Смерти лидера (если нет замены)
   - Достижении цели (для escort/TradeCaravan)
   - Ручном расформировании

---

## 3. Типы задач

### 3.1. Патруль (Patrol)

**Описание:** Группа перемещается по замкнутому маршруту из точек (waypoints). По достижении последней точки — возвращается к первой.

**Участники:** 2-5 NPC одной фракции (стража, дозорные).

**Параметры:**
- Маршрут: список точек (waypoints)
- Зацикливание: да (после последней → первая)

**Поведение участников:**
- Лидер движется к текущей точке маршрута
- Последователи движутся за лидером (formation offsets — в будущем)
- При достижении точки — переход к следующей

**Примеры:** Патруль стражи по периметру поселения, дозор на границе территории.

### 3.2. Сопровождение (Escort)

**Описание:** Группа сопровождает VIP-персонажа (игрок, важный NPC, транспорт). Защищает его от угроз.

**Участники:** 2-4 NPC (телохранители, охрана).

**Параметры:**
- ID сопровождаемого (EscortTargetId)

**Поведение участников:**
- Лидер следует за VIP на расстоянии 1-2 тайла
- Последователи занимают позиции вокруг VIP (formation)
- При появлении врага — переход к атаке (индивидуальный AI)
- При смерти VIP — задача провалена, группа расформирована

**Примеры:** Сопровождение торговца, охрана посланника, эскорт игрока.

### 3.3. Охрана местности (GuardArea)

**Описание:** Группа охраняет определённую зону. Патрулирует внутри радиуса, атакует нарушителей.

**Участники:** 2-5 NPC (стража, часовые).

**Параметры:**
- Центр зоны (GuardCenter)
- Радиус зоны (GuardRadius, по умолчанию 5 тайлов)

**Поведение участников:**
- Каждый участник блуждает внутри радиуса охраны
- При появлении врага в зоне — атака (индивидуальный AI)
- При выходе врага из зоны — возвращение к патрулю

**Примеры:** Охрана ворот, защита лагеря, караул у сокровищ.

### 3.4. Охота стаей (HuntingPack)

**Описание:** Группа хищников охотится на цель. Фланговая атака — участники окружают жертву с разных сторон.

**Участники:** 3-6 животных одного вида (волки, тигры).

**Параметры:**
- Цель охоты (динамически определяется по угрозе)

**Поведение участников:**
- Участники共享 информацию о цели (threat table)
- Каждый участник занимает позицию вокруг жертвы
- Атакуют поочерёдно (один отвлекает, другие атакуют с флангов)
- При смерти жертвы — поиск новой цели или возвращение к стае

**Примеры:** Волчья стая, охота тигров, набег монстров.

### 3.5. Торговый караван (TradeCaravan)

**Описание:** Группа перемещается по маршруту между точками. Торговец в центре, охрана по бокам.

**Участники:** 1 торговец + 2-4 охранника.

**Параметры:**
- Маршрут (как Patrol, но без зацикливания — от точки А к точке Б)
- Состав: торговец (лидер) + охрана (последователи)

**Поведение участников:**
- Торговец движется по маршруту
- Охрана следует за торговцем (formation offsets)
- При атаке — охрана переходит к защите торговца
- При смерти торговца — караван провален

**Примеры:** Торговый караван между городами, перевозка ресурсов, паломничество.

---

## 4. Роли в группе

### Лидер (Leader)
- Определяет движение группы
- Его позиция — точка отсчёта для formation offsets последователей
- При смерти лидера — автоматическое повышение первого последователя

### Последователь (Follower)
- Движется за лидером с заданным смещением (formation offset)
- Может временно покидать строй для аки/защиты
- Возвращается в строй после устранения угрозы

---

## 5. Формации (планируется)

В v1 все участники движутся к одной точке (групповой цели). В будущем:

| Формация | Описание | Применение |
|----------|----------|------------|
| Линия | Участники в ряд | Патруль, оборона |
| Клином | V-образный строй | Атака, наступление |
| Круг | Окружение цели | Охота, защита VIP |
| Колонна | Гуськом | Движение по узким тропам |

Formation offsets вычисляются относительно позиции лидера. Каждый последователь имеет свой offset (dx, dy в тайлах).

---

## 6. Интеграция с индивидуальным AI

Группа — **надстройка**, не замена индивидуальному AI. Приоритеты:

1. **Бой** (индивидуальный) — если NPC атакован или видит врага, бой имеет приоритет
2. **Групповая задача** — если NPC в группе и не в бою, следует групповой цели
3. **Индивидуальное поведение** — если NPC не в группе, работает индивидуальный AI (Wandering, Patrolling и т.д.)

При завершении боя NPC возвращается к групповой задаче.

---

## 7. Будущее: глобальная карта

Система групп разработана с прицелом на перемещение по глобальной карте. В будущем группы будут использоваться для:

| Сценарий | Тип задачи | Описание |
|----------|------------|----------|
| Торговые караваны | TradeCaravan | Перемещение товаров между городами |
| Атаки монстров | HuntingPack | Нашествие монстров на территорию |
| Военные кампании | Patrol → Escort | Армия фракции/секты идёт на войну |
| Исследовательские походы | Patrol | Экспедиции в неизведанные земли |
| Паломничества | Escort | Группа культиваторов идёт к святому месту |
| Миграция животных | Patrol | Сезонное перемещение стад |

Группы на глобальной карте:
- Перемещаются между локациями (не внутри одной карты)
- Встречи групп на глобальной карте → переход в тактическую сцену
- Время в пути зависит от расстояния и скорости группы
- События в пути: засады, находки, встречи с другими группами

---

## 8. Связь с фракциями

Группы могут быть привязаны к фракциям:
- **faction** — политическая принадлежность (городская стража, секта, банда)
- **species** — видовая принадлежность (волчья стая, оленье стадо)

Отношения между группами определяются отношениями их фракций (FACTION_SYSTEM.md). Враждебные фракции атакуют друг друга при встрече.

---

## 9. Генерация групп

Группы создаются при генерации мира:
- **Малая карта (50×50):** 1-2 группы (волчья стая, патруль стражи)
- **Большая карта (500×500):** 4+ группы (стая, патруль, караван, стадо)

Размещение детерминированное (SeededRandom). Каждая группа получает:
- Уникальный ID (group_1, group_2, ...)
- Маршрут или зону (в зависимости от типа задачи)
- Участников с собранными телами и экипировкой

---

## 10. Архитектура

Система групп следует Hub-and-Spoke архитектуре:
- **NPCGroupService** — управление группами (create/disband/add/remove/tick)
- **NPCMovementService** — overlay: если NPC в группе, групповая цель приоритетна
- **NPCAIService** — индивидуальный AI (бой, угрозы, диспозиции)
- События: GroupFormedEvent, GroupDisbandedEvent (планируются)

Групповой сервис не управляет движением напрямую — он только устанавливает цели. Фактическое движение выполняет NPCMovementService (как для индивидуальных NPC, так и для групповых).

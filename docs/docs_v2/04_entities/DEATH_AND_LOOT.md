# Смерть и лут (Death and Loot)

> **Назначение:** Движко-независимая спецификация механики смерти NPC, трупов-контейнеров, полного лута (full loot), смерти игрока и респавна.
>
> **Обновлено:** 2026-09-10 (R13) — случайный дроп заменён системой трупов-контейнеров (см. §1.2, §2). Причина: NPC_ASSEMBLY_PIPELINE §8.1 «Система полного лута» и прямое задание пользователя; старая схема «1–3 случайных предмета на землю» теряла реальную экипировку/инвентарь NPC (нечестный лут).
>
> **Обновлено:** 2026-09-10 (R14) — §2.4 переписан по прямому запросу пользователя: восполнение населения в рамках сессии (ReinforcementTick каждые 45 игровых секунд) ЗАПРЕЩЕНО и удалено из кода. Правило мира: пока персонаж в локации — новых NPC нет (кроме ивентов); естественное восстановление — только при отсутствии персонажа (повторная сборка локации по «таймеру памяти» TRANSITION_SYSTEM §5.3/§11.1).
>
> **Связанные документы:** [COMBAT_SYSTEM.md](../02_systems/COMBAT_SYSTEM.md), [BODY_SYSTEM.md](../02_systems/BODY_SYSTEM.md), [GROUND_ITEM_SYSTEM.md](../06_player/GROUND_ITEM_SYSTEM.md), [EQUIPMENT_SYSTEM.md](../06_player/EQUIPMENT_SYSTEM.md), [NPC.md](./NPC.md), [NPC_ASSEMBLY_PIPELINE.md](./NPC_ASSEMBLY_PIPELINE.md), [ANIMALS.md](./ANIMALS.md).

## 1. Смерть NPC

### 1.1. Условие смерти
- NPC умирает, когда `CurrentHealth ≤ 0` (HP торса или головы падает до нуля, либо останавливается сердце — см. [BODY_SYSTEM.md §5](../02_systems/BODY_SYSTEM.md)).
- Флаг `IsAlive` устанавливается в `false`.

### 1.2. Событийный поток (R13 — труп-контейнер)
```
HP ≤ 0
  → NPC.IsAlive = false
  → публикуется NPCDeathEvent (NPCId, позиция, уровень)
  → CorpseService создаёт CorpseData на месте смерти:
      снапшот экипировки + инвентаря + духовных камней (§2.2)
  → публикуется CorpseCreatedEvent (CorpseId, NpcId, DisplayName, позиция, ItemCount)
  → CorpseSpriteRenderer рисует маркер трупа (саван/крест/лут-бейдж)
  → NPCSpriteRenderer удаляет спрайт NPC из сцены
```

### 1.3. Очистка
- Спрайт NPC удаляется из сцены.
- AI-компонент деактивируется.
- Труп живёт 1440 игровых секунд (1 игровой день, TTL), затем `CorpseRemovedEvent("ttl")` и маркер удаляется.
- Если NPC был сюжетный/уникальный — помечается как «убит» в журнале (см. [JOURNAL_SYSTEM.md](../06_player/JOURNAL_SYSTEM.md)).
- Гварды: труп для живого NPC не создаётся (fake-death QA-события); повторная смерть того же NPC дедуплицируется.

## 2. Лут (full loot через труп-контейнер)

### 2.1. Принцип
- При смерти NPC его экипировка и инвентарь **не исчезают и не рандомизируются**: `CorpseService` делает снапшот содержимого (паттерн [NPC_ASSEMBLY_PIPELINE.md §8.1](./NPC_ASSEMBLY_PIPELINE.md) «Система полного лута»). В труп попадает ровно то, что было на NPC при жизни.
- Каждый предмет адресуется `SlotId` (Guid) — взятие строго слот-адресное (паттерн R10 TOCTOU: повторное взятие того же SlotId отклоняется).
- Предмет, неизвестный `ItemDatabase`, в труп не попадает (защита от «фантомных» ID, паттерн P1-5) — предупреждение в лог.

### 2.2. Состав трупа
| Источник | Что попадает | Примечание |
|---|---|---|
| Экипировка NPC | Все надетые предметы (слоты ≠ None) | Rarity резолвится через ItemDatabase |
| Инвентарь NPC | Все непустые слоты (стаками как есть) | Количество сохраняется |
| Духовные камни | Таблица 4.1 (CombatLoot, детерминированно от npcId): L1–2 → 1–3 осколка; L3–4 → 2–5 осколков; L5+ → 1–2 фрагмента | Гарантированный дроп камней поверх инвентаря |
| Негуманоиды (звери) | Только камни | Экипировки/инвентаря нет |

> Примечание: камни по таблице 4.1 — это отдельный death-drop, не путать с §8.2 NPC_ASSEMBLY_PIPELINE (генерация содержимого живого NPC при сборке: 0–1 осколок @L3+ 10%, 0–1 фрагмент @L5+ 5% — попадает в инвентарь и тоже обыскивается).

### 2.3. Обыск и взятие (E-флоу)
- Игрок подходит к трупу и нажимает **E** (труп приоритетнее живого NPC при одинаковом радиусе) → пауза тиков + модальное окно обыска (`LootWindow`).
- **ЛКМ** по строке — взять один предмет (SlotId-адресно, выдача через `ItemAddRequestEvent` — command-паттерн EVT-02; overflow инвентаря → предмет падает на землю).
- **«Забрать всё»** — полный лут всех записей трупа.
- **Esc** / «Уйти» — закрыть окно и возобновить симуляцию.
- `CorpseRemovedEvent` (TTL/опустошение) — авторитетное закрытие окна, если оно открыто.
- В лог событий пишутся подсказки «☠ Имя: можно обыскать (N поз., E)».

### 2.4. Восполнение населения (R14)
- **В присутствии персонажа — НЕ восполняется.** Пока игрок в локации, новые NPC не генерируются: убийства необратимы в рамках сессии. Полный лут остаётся добытым, население можно «выбить подчистую» (до пустой локации).
- **Исключение — ивенты.** Приход каравана, нападение на локацию, другое событийное появление ([GROUP_SYSTEM.md](./GROUP_SYSTEM.md) §3.4–3.5, будущий event-pipeline) — единственная внутрисессионная точка входа новых NPC: `NPCSpawnCompositionService.TrySpawnEventNpc(reason)` (причины: Caravan/Raid/Event; спавн на walkable-тайле ≥12 тайлов от игрока). Тиками НЕ вызывается.
- **Естественное восстановление — только при отсутствии персонажа** (он в другом поселении или на карте мира): население восполняется при следующей (пере)сборке локации через процедурную генерацию состава ([NPC.md](./NPC.md), NPCSpawnCompositionService.GenerateStartup) по правилу «таймера памяти» ([TRANSITION_SYSTEM.md §5.3, §11.1](../03_world/TRANSITION_SYSTEM.md)): NPC возвращаются через 1 игровой день после ухода игрока (механизм памяти отсутствия — с будущим travel-pipeline; сейчас состав регенерируется при сборке сцены).
- Удалено (R14): периодический `ReinforcementTick` (каждые 45 игровых секунд, порог живых < 60%) — противоречил правилу «пока персонаж в локации, новые NPC не приходят».

## 3. Смерть игрока

### 3.1. Условие смерти
- Игрок умирает, когда:
  - **Сердце (Heart) Disabled** — RedHP сердца ≤ 0.
  - **Сердце Severed** — структурно отрублено (для частей с BlackHP; сердце имеет только RedHP, поэтому для него Severed = Disabled = смерть).
  - Голова (Head) Disabled/Severed.

### 3.2. Событийный поток
```
HP сердца/головы ≤ 0
  → PlayerService.Die()
  → публикуется PlayerDeathEvent (позиция, причина)
  → UI показывает экран смерти («Вы пали в бою»)
  → предлагается выбор: Revive / Load Save / Main Menu
```

### 3.3. Причина смерти
- В `PlayerDeathEvent` сохраняется причина (какая часть тела была уничтожена, какой атакующий).
- Используется в журнале и для возможных ачивок/последствий.

## 4. Respawn (возрождение игрока)

### 4.1. Принцип
- Игрок может возродиться (`Revive`) — HP восстанавливается до максимума, состояние тела возвращается к здоровому.

### 4.2. Что восстанавливается
- `CurrentHealth` → `MaxHealth`.
- Все части тела → `Healthy` (RedHP = max, BlackHP = max).
- Ци → максимум.
- Активные баффы/DoT — снимаются.

### 4.3. Что сохраняется
- **Позиция игрока** — остаётся той же (где игрок умер). Это сознательное решение: респавн происходит на месте смерти.
- Экипировка — остаётся на игроке (не выпадает).
- Инвентарь — остаётся.
- Уровень культивации, статы — без изменений.

### 4.4. Штраф
- Текущая реализация: штраф минимальный (только снятие активных баффов/DoT).
- В будущем: возможны штрафы к Ци/прочности экипировки.

### 4.5. Событие
- При респавне публикуется `PlayerReviveEvent`.
- Симуляция возобновляется (если была на паузе из-за экрана смерти).

> Контракты — `readonly struct`. См. [DI_AND_EVENTBUS.md §2.3](../01_architecture/DI_AND_EVENTBUS.md) (PlayerContracts: PlayerDeath, PlayerRevive).

## 5. Лут с животных

- Животные (wolf, deer, rabbit) при смерти проходят через тот же `CorpseService` — труп-контейнер. Негуманоиды без экипировки/инвентаря дают только духовные камни (таблица 4.1 от уровня).
- Материалы (шкура/клыки/рога/мясо — см. [ANIMALS.md §5](./ANIMALS.md)) — **TODO**: специфичный для вида лут ещё не реализован в генераторе.
- Механизм взятия — тот же E-флоу обыска трупа (§2.3).

## 6. Сводная таблица событий

| Событие | Триггер | Реакция |
|---------|---------|---------|
| `NPCDeathEvent` | NPC HP ≤ 0 | CorpseService создаёт труп-контейнер (снапшот §2.2) |
| `CorpseCreatedEvent` | Труп создан | CorpseSpriteRenderer рисует маркер, EventLog подсказка |
| `CorpseRemovedEvent` | TTL (1 игровой день) / опустошение | Маркер удаляется, LootWindow закрывается авторитетно |
| `CorpseLootedEvent` | Игрок взял предмет(ы) | UI/EventLog обновление, труп опустошается при 0 записей |
| `PlayerDeathEvent` | Player Heart/Head ≤ 0 | UI экран смерти, пауза |
| `PlayerReviveEvent` | Игрок выбрал Revive | HP/body/Qi восстановлены, симуляция возобновлена |
| `ItemAddRequestEvent` | Взятие из трупа (command) | InventoryModule добавляет; overflow → `ItemDroppedEvent` на землю |
| `ItemDroppedEvent` | Overflow инвентаря при луте | Renderer рисует спрайт |

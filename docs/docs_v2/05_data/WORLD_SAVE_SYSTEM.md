# Сохранение мира

> **Статус:** Концепция (engine-agnostic).
> **Тайл = 2 × 2 м.** См. `WORLD_MAP_SYSTEM.md` §1.
> **Связанные документы:** `SAVE_SYSTEM.md`, `WORLD_SYSTEM.md`, `WORLD_MAP_SYSTEM.md`, `LOCATION_MAP_SYSTEM.md`, `TILE_SYSTEM.md`.

---

## 1. Обзор проблемы

### 1.1 Масштаб мира сянси

```
Обитаемая суша: 200,000 × 200,000 км (40 млрд км²)

Для сравнения:
• Земля (площадь суши): ~148,940,000 км²
• Наш мир: ~268× больше Земли

Реалии миров сянси:
• Практически нереально посетить все локации
• Многие области остаются «чёрными» и «серыми»
• Огромные расстояния между ключевыми точками
• Путешествия занимают годы игрового времени
```

### 1.2 Проблема сохранения

| Проблема | Описание |
|----------|----------|
| Размер данных | Полное сохранение всего мира невозможно |
| Неисследованные зоны | Нет смысла сохранять то, что не посещено |
| Производительность | Быстрая загрузка только нужных областей |
| Память | Нельзя держать весь мир в памяти |

### 1.3 Решение: чанковая гибридная модель

- **Мир** = 4,000,000 чанков (100 × 100 км каждый).
- **Чанк** = единица сохранения (1 файл на чанк).
- **Локация** = единица загрузки (загружается при посещении).
- **Тайлы** = НЕ сохраняются индивидуально, генерируются процедурно из seed + дельта.

## 2. Иерархия мира (5 уровней)

```
УРОВЕНЬ 0: МИР (World)
├── Размер: 200,000 × 200,000 км
├── Функция: Контейнер всего мира
└── Единиц: 4,000,000 чанков
        │
        ▼
УРОВЕНЬ 1: ЧАНК (Chunk)
├── Размер: 100 × 100 км
├── Функция: Единица СОХРАНЕНИЯ (один файл)
└── Единиц: 100 секторов (10×10)
        │
        ▼
УРОВЕНЬ 2: СЕКТОР (Sector)
├── Размер: 10 × 10 км
├── Функция: Единица КАРТЫ МИРА (ячейка на глобальной карте)
│           Навигация «путешествие во времени»
└── Содержит: 1–10 локаций (точек интереса)
        │
        ▼
УРОВЕНЬ 3: ЛОКАЦИЯ (Location)  ← КЛЮЧЕВОЙ УРОВЕНЬ
├── Размер: ПЕРЕМЕННЫЙ (100 м … 10 км)
├── Функция: Единица ЗАГРУЗКИ (загружаемая сцена)
│           Прецизионный вход в сектор
└── Одна или несколько сцен
        │
        ▼
УРОВЕНЬ 4: ТАЙЛ (Tile)
├── Размер: 2 × 2 м  ← СТАНДАРТ
├── Функция: Единица НАВИГАЦИИ внутри локации
│           Collision detection, размещение объектов
└── НЕ сохраняется индивидуально
```

### 2.1 Сводная таблица

| Уровень | Размер | Единиц внутри | Функция | Файловая единица |
|---------|--------|---------------|---------|------------------|
| **Мир** | 200,000 × 200,000 км | 4,000,000 чанков | Контейнер | — |
| **Чанк** | 100 × 100 км | 100 секторов | Сохранение | 1 файл чанка |
| **Сектор** | 10 × 10 км | 1–10 локаций | Карта мира | — |
| **Локация** | 100 м … 10 км | до 25M тайлов | Загружаемая сцена | 1+ сцен(ы) |
| **Тайл** | **2 × 2 м** | — | Навигация | — (только delta) |

## 3. Локации — переменный размер

### 3.1 Типы и размеры

| Тип | Размер | Тайлов (×250,000/км²) | Примеры |
|------|--------|------------------------|---------|
| Мегаполис | 10 × 10 км | 25,000,000 | Столица империи |
| Большой город | 3 × 3 км | 2,250,000 | Город-государство |
| Средний город | 1 × 1 км | 250,000 | Районный центр |
| Посёлок | 500 × 500 м | 62,500 | Крупное село |
| Деревня | 300 × 300 м | 22,500 | Сельское поселение |
| Хутор | 100 × 100 м | 2,500 | Одинокая ферма |
| Храм/Святилище | 200 × 200 м | 10,000 | Храмовый комплекс |
| Подземелье | переменный | до 100,000 | Пещера, катакомбы |
| Дикие земли | — | — | Процедурная генерация |

**Расчёт тайлов:** `(ширина_м / 2) × (высота_м / 2)`.

**Принцип:** размер локации определяется её контентом, а не фиксированной сеткой.

```
3. Храм «Утренней Росы» — 200×200 м (10,000 тайлов)
4. Хутор «Старого Цая» — 100×100 м (2,500 тайлов)

░░░ = «Дикие земли» — не загружаются как сцена
┌──┐ = Локация — загружается при посещении
```

## 4. Seed + delta для тайлов

> **ГЛАВНЫЙ ПРИНЦИП:** тайлы НЕ сохраняются индивидуально. Они восстанавливаются процедурно из `seed` + `delta` изменений.

### 4.1 Почему не сохранять каждый тайл?

- Мегаполис 25M тайлов × ~150 байт = 3.75 GB на одну локацию.
- 2000 локаций × 3.75 GB = 7.5 TB.
- Это нереально.

### 4.2 Решение: процедурная регенерация + delta

```
Сохранение локации = {
    locationId: "loc_city_tumanny",
    seed: 123456789,                    // seed для процедурной генерации
    baseParameters: {                   // параметры генерации
        locationType: "city_large",
        width: 1000,                    // м
        height: 1000,                   // м
        sectorData: { qiDensity: 120, ... }
    },
    modifiedTiles: [                    // ТОЛЬКО изменённые тайлы
        { x: 5, y: 3, changes: { terrain: "dirt" } },
        { x: 7, y: 2, changes: { qiDensity: 150 } },
        { x: 12, y: 8, changes: { objects: [{ type: "chest", ... }] } }
    ]
}
```

### 4.3 Алгоритм загрузки локации

```
1. Чтение seed и baseParameters из locations/loc_*.sav
2. Процедурная генерация всех тайлов по seed (детерминировано)
3. Применение modifiedTiles (delta) к сгенерированной карте
4. Загрузка NPC, объектов, точек интереса
5. Спавн игрока в точке входа
```

### 4.4 Алгоритм сохранения локации

```
1. Игрок выходит из локации (или автосохранение)
2. Сравнение текущего состояния с baseline (сгенерированным по seed)
3. Вычисление delta (modifiedTiles)
4. Запись seed + baseParameters + delta в locations/loc_*.sav
```

### 4.5 Размер delta

- Типичная локация: 0–100 изменённых тайлов (после первого посещения).
- Размер delta: 0.5–10 KB.
- Размер seed + baseParameters: ~100 байт.
- **Итоговый размер сохранения локации: 0.5–10 KB.**

## 5. Флаги состояния чанков и секторов

### 5.1 Состояния

| Флаг | Цвет | Описание | Что хранится |
|------|------|----------|--------------|
| **Hidden** | Чёрный | Не видим, не посещён | Ничего |
| **Visible** | Серый | Видим через разведку/техники (радиус ~100 км) | Базовая информация (тип местности, примерное Ци) |
| **Known** | Известный | Известен из книг/карт/разговоров | Точки интереса, неполная информация |
| **Visited** | Белый | Лично посещён | Полное или частичное сохранение |

### 5.2 Переходы состояний

```
Чёрный ──(разведка)──► Серый
Чёрный ──(карта/книга)──► Известный
Любой ──(личное посещение)──► Белый
```

### 5.3 Что сохраняется для каждого состояния

| Состояние | Сохраняется | Размер |
|-----------|-------------|--------|
| Hidden | Ничего | 0 |
| Visible | Тип местности, примерное Ци | ~25 байт |
| Known | Список POI, метаданные | ~50 байт |
| Visited | Полные метаданные + дельта | ~100–500 байт |

## 7. Структуры данных

### 7.1 Локация

```csharp
class LocationData
{
    string locationId;           // Уникальный ID
    string locationName;         // "Город Туманный"

    // Размеры (ПЕРЕМЕННЫЕ)
    int widthMeters;             // Ширина в метрах
    int heightMeters;            // Высота в метрах

    // Позиция в секторе
    string sectorId;             // ID родительского сектора
    int sectorOffsetX;           // Смещение от начала сектора (м)
    int sectorOffsetY;           // Смещение от начала сектора (м)

    // Тип и свойства
    LocationType type;           // Megapolis, City, Village, Temple, etc.
    int dangerLevel;             // Уровень опасности
    int qiDensity;               // Плотность Ци

    // Точки входа/выхода
    List<EntrancePoint> entrances;

    // Связи с другими локациями
    List<LocationConnection> connections;
}
```

### 7.2 Точка входа

```csharp
class EntrancePoint
{
    string entranceId;           // "north_gate", "south_road"
    string displayName;          // "Северные ворота"
    int tileX, tileY;            // Позиция в тайлах
    List<string> connectsTo;     // Куда ведёт (ID локаций или "wilderness")
}
```

### 7.3 Связь между локациями

```csharp
class LocationConnection
{
    string fromLocationId;
    string fromEntranceId;
    string toLocationId;
    string toEntranceId;

    // Параметры пути
    float distanceKm;            // Расстояние в км
    int travelTimeMinutes;       // Время пути в игровых минутах
    TravelType travelType;       // Walk, Ride, Fly, Teleport
    float dangerModifier;        // Модификатор случайных встреч
    RoadQuality roadQuality;     // Плохая, Обычная, Хорошая, Торговая
}
```

### 7.4 Сохранение локации

```csharp
class LocationSaveData
{
    string locationId;
    long lastVisitedTick;        // тик последнего посещения

    // Тип локации определяет объём сохранения
    LocationType type;

    // Для СЛУЧАЙНЫХ локаций (упрощённое)
    int seed;                    // Seed для генерации
    List<ModifiedObject> changes; // Только изменённые объекты

    // Для СЮЖЕТНЫХ локаций (полное)
    List<ObjectSaveData> objects;     // Все объекты
    List<NPCSaveData> npcs;           // Все NPC
    List<ContainerSaveData> containers; // Сундуки, шкафы
    List<DoorSaveData> doors;         // Двери, проходы
    Dictionary<string, bool> flags;   // Локальные флаги
}

class ModifiedObject
{
    string objectId;
    string modificationType;     // "destroyed" | "looted" | "changed"
    Dictionary<string, object> changes;
}
```

## 9. Файловая структура

```
Saves/
├── slot1/
│   ├── main.sav              # Игрок, время, квесты (~10–50 КБ)
│   │
│   ├── chunks/               # Папка чанков
│   │   ├── chunk_152_847.sav # Посещённые чанки
│   │   └── ...
│   │
│   ├── locations/            # Папка локаций
│   │   ├── loc_city_tumanny.sav
│   │   ├── loc_village_tihaya.sav
│   │   └── ...
│   │
│   └── metadata.sav          # Индекс и карта мира
│
├── autosave/                 # Автосохранение
└── quicksave/                # Быстрое сохранение
```

### 9.1 main.sav

Содержит данные, не привязанные к конкретной локации:
- персонаж игрока;
- игровое время (tickCount, gameTime);
- журнал квестов;
- инвентарь и экипировка;
- изученные техники;
- активные баффы (с tick-остатком);
- отношения фракций;
- текущая локация и точка входа.

Размер: **10–50 КБ**.

### 9.2 chunks/

Каждый файл `chunk_X_Y.sav` содержит:
- метаданные 100 секторов (10×10) внутри чанка;
- флаги видимости (Hidden/Visible/Known/Visited);
- список локаций в чанке;
- дельта изменённых объектов (если есть).

Размер: **0.5–5 КБ** на чанк (если посещён).

### 9.3 locations/

Каждый файл `loc_*.sav` содержит:
- `seed` и `baseParameters` для процедурной генерации;
- `modifiedTiles` (дельта изменённых тайлов);
- `objects` (состояние объектов, NPC, контейнеров, дверей);
- `flags` (локальные квестовые флаги).

Размер: **0.5–10 КБ** на локацию.

### 9.4 metadata.sav

- индекс всех сохранённых чанков (для быстрого поиска);
- карта мира с флагами видимости;
- список всех известных локаций;
- текущая позиция игрока на карте мира.

Размер: **5–20 КБ**.

## 10. Дельта-сжатие

### 10.1 Принцип

```
Полное состояние локации = baseline (seed) + delta (изменения)

Сохраняется только delta. baseline восстанавливается процедурно.

baseline = regenerate(seed, baseParameters)
finalState = applyDelta(baseline, modifiedTiles)
```

### 10.2 Что попадает в delta

| Тип изменения | Что сохраняется |
|---------------|-----------------|
| Изменён terrain тайла | `{x, y, changes: { terrain: "dirt" }}` |
| Изменено Ци тайла | `{x, y, changes: { qiDensity: 150 }}` |
| Добавлен объект | `{x, y, changes: { objects: [{ type: "chest", ... }] }}` |
| Удалён объект | `{x, y, changes: { objects: [] }}` |
| Изменено состояние объекта | `{x, y, changes: { objects: [{ id: "obj_123", state: "open" }] }}` |
| Изменена температура | `{x, y, changes: { temperature: 25.5 }}` |

### 10.3 Размер delta по типам локаций

| Тип локации | Типичное кол-во изменённых тайлов | Размер delta |
|-------------|------------------------------------|--------------|
| Хутор (100×100 м) | 0–10 | < 1 КБ |
| Деревня (300×300 м) | 5–50 | 1–3 КБ |
| Город (1×1 км) | 20–200 | 2–10 КБ |
| Мегаполис (10×10 км) | 100–1000 | 10–50 КБ |
| Подземелье | 10–100 | 1–5 КБ |

## 12. Принципы сохранения мира

1. **Чанковая структура:** мир = 4M чанков, чанк = 1 файл сохранения.
2. **Локации — единица загрузки:** одна локация активна за раз, не open-world streaming.
3. **Дикие земли процедурны:** пространство между локациями не сохраняется.
4. **Seed + delta для тайлов:** тайлы не сохраняются индивидуально.
5. **Переменный размер локаций:** размер диктуется контентом, не сеткой.
6. **Дельта-сжатие:** сохраняется только разница с baseline.
7. **Опциональный бинарный формат + GZIP** для дополнительного сжатия.

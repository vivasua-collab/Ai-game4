# Модели прорыва (Breakthrough Models)

> **Назначение:** Документ описывает и сравнивает три модели прорыва уровней культивации, фиксирует выбранную модель (Модель В — Растущий резервуар + Сжатие Ци) и два пути восстановления Ци после прорыва. Документ engine-agnostic: формулы, расчёты, таблицы — без привязки к движку.

**Связанные документы:** `02_systems/QI_SYSTEM.md`, `02_systems/CHARGER_SYSTEM.md`, `06_player/MORTAL_DEVELOPMENT.md`, `03_world/TIME_SYSTEM.md`, `08_content/LORE_SYSTEM.md`.

---

## 1. Обзор

Прорыв — переход практика на следующий уровень культивации. Документ сравнивает три модели прорыва (А, Б, В) и рассчитывает игровое время, необходимое для прохождения с L1 на L9 при разных методах восполнения Ци.

**Решение:** Модель В — основная по ЛОРУ (комбинация А и Б).

---

## 2. Модель А: Растущий резервуар

### 2.1. Принцип

- **Ёмкость ядра растёт** с каждым уровнем.
- **Требуемое количество Ци для прорыва** = `coreCapacity × multiplier`.
- Плотность Ци — отдельный параметр качества (влияет на урон техник, но не на требование прорыва).

### 2.2. Формула ёмкости

```
coreCapacity = 1000 × 1.1^totalSubLevels
```

### 2.3. Требования для прорыва

- **Малый прорыв (под-уровень):** `coreCapacity × 10` Ци.
- **Большой прорыв (уровень):** `coreCapacity × 100` Ци.

---

## 3. Модель Б: Сжатие в постоянном объёме

### 3.1. Принцип

- **Ёмкость ядра фиксирована** (например, 1000 единиц объёма).
- **Плотность Ци растёт** с уровнем: `qiDensity = 2^(level-1)`.
- Прорыв требует заполнения ядра Ци текущего уровня плотности.

### 3.2. Формула «количества Ци» для прорыва

```
effectiveQiRequired = baseQi × qiDensity
```

### 3.3. Интерпретация

- Ядро вмещает фиксированный объём, но Ци становится «гуще».
- Для накопления 1000 единиц Ци плотности 4 (L3) нужно поглотить в 4 раза больше «сырой Ци» из окружения.

---

## 4. Модель В: Растущий резервуар + Сжатие Ци (ВЫБРАННАЯ)

### 4.1. Принцип

- **Ёмкость ядра растёт** с каждым уровнем (как в А).
- **Плотность Ци растёт** с уровнем (как в Б).
- **Комбинация:** Эффективное количество Ци = Объём × Плотность.

### 4.2. Формулы

```
coreCapacity = 1000 × 1.1^totalSubLevels   // растущий объём (А)
qiDensity    = 2^(level-1)                  // сжатие Ци (Б)
effectiveQi  = coreCapacity × qiDensity     // эффективное Ци в ядре
conductivity = coreCapacity / 360           // проводимость (ед/сек)
```

### 4.3. Требования для прорыва

**Прорыв = расширение ядра + сжатие Ци до новой плотности.**

```
Требуемая сырая Ци = coreCapacity(nextLevel) × qiDensity(nextLevel)
После прорыва: currentQi = 0  (ядро перестраивается)
```

### 4.4. Малый и большой прорывы

- **Малый прорыв (под-уровень):** Накопить `capacity(nextSubLevel) × qiDensity(nextSubLevel)` единиц Ци.
- **Большой прорыв (уровень):** Накопить `capacity(nextLevel) × qiDensity(nextLevel)` единиц Ци.

### 4.5. Интерпретация

- Практик накапливает Ци в ядре текущей плотности.
- При прорыве ядро расширяется **И** Ци сжимается до новой плотности.
- **После прорыва `currentQi = 0`** (нужно накапливать заново).

### 4.6. Процесс прорыва

1. Глубокая медитация.
2. Концентрация Ци в ядре.
3. Преобразование структуры ядра.
4. Увеличение плотности Ци.
5. Увеличение ёмкости ядра на ~10%.

### 4.7. Время выполнения

- Малый прорыв: ~480 игровых минут (8 часов).
- Большой прорыв: ~4800 игровых минут (80 часов).

### 4.8. Пример

- **L1.0:** Ёмкость 1000, Плотность 1 → Эффективное Ци: 1000×1 = 1000.
- **L2.0:** Ёмкость 2594, Плотность 2 → Эффективное Ци: 2594×2 = 5188.
- **L3.0:** Ёмкость 6727, Плотность 4 → Эффективное Ци: 6727×4 = 26 908.

**Для прорыва L1→L2** нужно накопить сырой Ци = `2594 × 2 = 5 188`.

**Для прорыва L2→L3** нужно накопить сырой Ци = `6727 × 4 = 26 908`.

## 6. Время прорыва L1 → L9 (по Модели В)

### 6.1. Общие условия

- **Игровой день:** 24 часа = 1440 минут = 86 400 секунд.
- **Режим `ultra` (медитация):** 60 минут/тик = 1 час за 1 секунду реального времени.
- **После прорыва:** `currentQi = 0` (нужно накапливать заново).
- **Количество больших прорывов:** 8 (L1→L2, L2→L3, ..., L8→L9).

### 6.2. ДВА ПУТИ ВОССТАНОВЛЕНИЯ ЦИ

#### Путь 1: Только микроядро (пассивное восстановление)

- Генерация микроядра: **10% от `coreCapacity` в сутки** (КОНСТАНТА для всех уровней).
- Нет медитации, нет внешних источников.
- Только пассивная регенерация.

| Прорыв | Требуется Ци | Генерация/день | Дней |
|--------|--------------|----------------|------|
| L1→L2 | 5,188 | 100 | 51.9 |
| L2→L3 | 26,908 | 259.4 | 103.7 |
| L3→L4 | 139,600 | 672.7 | 207.5 |
| L4→L5 | 724,160 | 1,745 | 415.1 |
| L5→L6 | 3,756,480 | 4,526 | 830.2 |
| L6→L7 | 19,486,720 | 11,739 | 1,660.4 |
| L7→L8 | 101,088,000 | 30,448 | 3,320.8 |
| L8→L9 | 524,390,400 | 78,975 | 6,641.6 |

**Итого (Путь 1):** ~13 231 дней = **36.2 игровых лет**.

**Паттерн:** Каждый прорыв требует в 2 раза больше времени, чем предыдущий.

#### Путь 2: Медитация (активное поглощение из окружения)

**Модель поглощения из лора (без `environmentMult` как множителя!):**

- `ρ_окр` — плотность Ци в воздухе (ед/м³) — это **ЗАПАС**, не множитель.
- Практик собирает ВСЮ Ци в зоне радиуса R.
- Скорость поглощения = проводимость практика (ед/сек).
- Ци в зоне **ИСЧЕЗАЕТ** после поглощения.
- Восстановление из недр — **ОЧЕНЬ МЕДЛЕННОЕ** (G = 10 ед/ч·м² минимум).

**Плотность Ци в зонах (из лора):**

| Зона | ρ_окр (ед/м³) |
|------|---------------|
| Внутреннее кольцо | 500–1000+ |
| Среднее кольцо | 200–500 |
| Внешнее кольцо | 100–200 |
| Приграничные | 20–100 |

**Условия расчёта:**

- Стартовая локация: внешнее кольцо, ρ_окр = 150 ед/м³.
- Радиус зоны поглощения R растёт с уровнем: `R = 10 × (1 + 0.2 × (2^(level/3) - 1))`.
- Медитация: 8 часов/день = 28 800 сек.

## 9. Анализ и обоснование выбора

### 9.1. Модель А — Растущий резервуар

**Плюсы:**

- Чувство прогресса (ёмкость растёт).
- Баланс с зарядниками — нужен апгрейд снаряжения.
- Больше игрового времени = больше контента.

**Минусы:**

- Лимит запаса Ци в зоне на L4+.
- Зарядник становится узким местом на L5+.
- Требует ~130 Кристаллов для быстрого прогресса.

### 9.2. Модель Б — Сжатие в постоянном объёме

**Плюсы:**

- Быстрый прогресс.
- Проводимость практика фиксирована — нет проблем с зарядником.
- Меньше расход камней Ци.

**Минусы:**

- Нет ощущения роста ёмкости.
- Может казаться «слишком легко».
- НЕ соответствует ЛОРУ.

### 9.3. Модель В — Растущий резервуар + Сжатие (ВЫБРАННАЯ)

**Плюсы:**

- ✅ Соответствует ЛОРУ.
- ✅ Прогрессия: каждый прорыв в 2× сложнее предыдущего.
- ✅ Реалистичная экономика ресурсов.

**Минусы:**

- Самое долгое время прогресса.
- Требует много камней Ци на высоких уровнях.
- Зарядник — узкое место на L5+.
- Запас Ци в зоне — лимитирующий фактор.

> **Ключевой вывод:** Модель В создаёт реалистичную прогрессию культивации, где прорыв на каждый следующий уровень требует в 2 раза больше ресурсов.

## 10. Рекомендации для балансировки Модели В

### 10.1. Для баланса с зарядниками

- **Увеличить проводимость зарядников** (рекомендация):
  - Common: 10 ед/сек (вместо 5).
  - Refined: 25 ед/сек (вместо 10).
  - Perfect: 50 ед/сек (вместо 25).
  - Transcendent: 100 ед/сек (вместо 50).
- **Или добавить перки на проводимость.**

### 10.2. Для баланса запаса Ци в зоне

- **Радиус зоны поглощения растёт с уровнем:** `R = 10 × (1 + 0.2 × (2^(level/3) - 1))`.
- **Или «глубокое дыхание» — поглощение из недр:** доступно на L4+.

## 11. Структура данных прорыва

```
BreakthroughState:
  currentLevel:          int     // большой уровень (1..9)
  currentSubLevel:       int     // под-уровень (0..9)
  totalSubLevels:        int     // (level-1)*10 + subLevel
  coreCapacity:          long    // текущая ёмкость
  qiDensity:             int     // 2^(level-1)
  effectiveQi:           long    // coreCapacity × qiDensity
  currentQi:             long    // текущее Ци (после прорыва = 0)
  nextBreakthroughCost:  long    // coreCapacity(next) × qiDensity(next)
  isBreakthroughReady:   bool    // currentQi >= nextBreakthroughCost

BreakthroughEvent:
  type:                  BreakthroughType  // Minor / Major
  fromLevel:             int
  toLevel:               int
  fromSubLevel:          int
  toSubLevel:            int
  qiConsumed:            long             // = nextBreakthroughCost
  timestamp:             GameTime
```

> Событие прорыва публикуется через шину событий; триггерит обновление HP частей тела (если вырос `cultivationBonus`), обновление проводимости, обнуление `currentQi`.

## 12. Производительность

- Прорыв — редкое событие (раз в 1–834 дня). Накладных расходов на проверку готовности нет (выполняется только при изменении `currentQi`).
- Все формулы используют `long`-арифметику (zero-GC).
- `effectiveQi` до L9 (~524M) помещается в `int64` без переполнения.

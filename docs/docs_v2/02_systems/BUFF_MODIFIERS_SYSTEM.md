## ЧАСТЬ A. БАФФЫ И ДЕБАФФЫ

### A.1. Обзор

Система баффов и дебаффов управляет **временными эффектами**, влияющими на характеристики персонажа. Баффы — положительные эффекты, дебаффы — отрицательные.

> **Ключевой принцип:** Баффы не дают «бесплатных» постоянных улучшений — они временные и имеют свою цену.

---

### A.2. Критические правила

Эти правила **ненарушимы** и определяют баланс игры.

**Что НЕЛЬЗЯ менять баффами:**

| Параметр | Причина |
|----------|---------|
| Первичные характеристики (STR, AGI, INT, VIT) | Развиваются только физическими действиями и закрепляются при сне |
| Ёмкость ядра (`coreCapacity`) | Определяется уровнем культивации |
| Базовая регенерация Ци (`qiRegen`) | 10%/сутки от микроядра — немодифицируема |
| Плотность Ци (`qiDensity`) | Определяется уровнем культивации |

**Что МОЖНО менять баффами:**

| Параметр | Ограничения |
|----------|-------------|
| Текущее Ци | Только регенерация/расход |
| Проводимость | ⛔ ТОЛЬКО перки (постоянно) и проклятия. Баффы НЕ модифицируют! |
| Вторичные характеристики | Через мягкие капы |
| HP частей тела | Регенерация, щиты |
| Скорости | Через мягкие капы |

### A.4. Проводимость (Conductivity) — правила модификации

> **⛔ Удалено:** `ConductivityBoost` (временный бафф проводимости с откатом) — устарел и удалён. Логика концентрации окружающей Ци перенесена на **формации** и **внешние средства**. Проводимость НЕ модифицируется временными баффами.

| Источник | Тип | Эффект | Постоянство |
|----------|-----|--------|-------------|
| Перки (эластичность меридиан, увеличенный диаметр) | Развитие | +X% к базовой проводимости | Постоянно |
| Проклятия / повреждение меридиан | Штраф | −X% проводимости | Пока не вылечено |
| Формации (Круг поглощения и др.) | Внешний фактор | +X% к **концентрации окружающей Ци** (НЕ к проводимости!) | Локально, пока активна |

**Формации вместо баффа проводимости:**

```
absorbedQi = meditationTime × finalConductivity × environmentMult
```

- Проводимость (`finalConductivity`) — НЕИЗМЕННА во время медитации (только перки + проклятия).
- Формации увеличивают `environmentMult` (×1.5, ×2.0, ×3.0 и т.д.).
- Результат: практик поглощает больше Ци без изменения меридиан.

### A.5. Режимы применения и стекинг

#### Режимы применения (BuffApplication)

| Значение | Описание |
|----------|----------|
| `Instant`    | Мгновенный эффект (лечение, урон) |
| `Duration`   | Длительный эффект |
| `Permanent`  | Постоянный (пока не снят) |
| `Stacking`   | Накапливающийся |
| `Refreshing` | Обновляет длительность |

#### Поведение при повторном наложении (BuffStacking)

| Значение | Описание |
|----------|----------|
| `Replace` | Заменить предыдущий |
| `Refresh` | Обновить таймер длительности |
| `Stack`   | Добавить стек (до `maxStacks`) |
| `Ignore`  | Игнорировать повторное наложение |

#### Правила стекирования (унаследованы из системы предметов)

Эффект **можно объединить в стак** если выполняются **все** условия:
- флаг `stackable == true`;
- нет системы прочности ИЛИ прочность 100%;
- идентичный `buffId`;
- нет бонусов/модификаторов (только Common-grade источник);
- предметы-источники идентичны (для расходников).

Эффект **НЕ стакируется**, если:
- источник — экипировка (по умолчанию `stackable = false`);
- источник имеет `grade != Common` (уникальные модификаторы);
- это квестовый предмет;
- предметы имеют разное оставшееся время жизни (для системы порчи).

### A.6. Длительность и тики

- **Длительность** задаётся в игровых минутах.
- **Тик эффектов** (`hasTickEffect`): эффект срабатывает каждые `tickInterval` минут.
- **Tick-эффекты:** `tickDamage` (для DoT), `tickHealing` (для регенерации).
- **Истечение:** при `remainingDuration <= 0` эффект снимается.
- **Целочисленность:** урон/лечение — целые числа; длительность — целые минуты.

## ЧАСТЬ B. МОДИФИКАТОРЫ

### B.1. Обзор

Система модификаторов — единая система бонусов и штрафов, где **одни и те же переменные** используются для расчёта:
- **Бонусы** → положительные значения переменных.
- **Штрафы** → отрицательные значения переменных.

**Ключевые принципы:**
1. **Единые переменные** — бонус и штраф это знак (+/−) значения одной переменной.
2. **Суммирование перед применением** — сначала сумма всех модификаторов, потом применение.
3. **Мягкие капы** — защита от чрезмерного разгона.
4. **Порядок расчёта** — плоские → сумма → проценты.

> **Различие баффов и перков:** Баффы — временные эффекты с возможным откатом (ЧАСТЬ A). Перки — постоянные пассивные способности, влияющие на базовые характеристики (развитие персонажа). См. `02_systems/PERK_SYSTEM.md`.

---

### B.2. Формула расчёта

```
ШАГ 1: Сбор модификаторов
  flat_modifiers     = [+10, +5, −3, +8]      → flat_sum = 20
  percent_modifiers  = [+10%, +5%, −15%, +20%] → percent_sum = +20%

ШАГ 2: Применение (плоские → проценты)
  result = (base_value + flat_sum) × (1 + percent_sum/100)
  result = (100 + 20) × 1.20 = 144

ШАГ 3: Мягкий кап
  result = apply_soft_cap(result, base_value, variable_id)
```

**Порядок применения:** Плоские → Проценты. Проценты должны усиливать ВСЮ базу, включая плоские бонусы.

---

### B.3. Мягкие капы (Soft Caps)

#### Зачем нужны

Без капов можно получить: +200% скорости (в 3× быстрее), +150% урона (один удар = смерть), −80% стоимости Ци (техники бесплатны). Мягкие капы позволяют получать бонусы сверх лимита, но с **убывающей эффективностью**.

#### Формула диминишинга

```
effectiveBonus = cap × (1 − e^(−bonus / (cap × decayRate)))
```

Где `decayRate` — индивидуальный параметр для каждой переменной.

| Бонус | Кап | Эффективность |
|-------|-----|---------------|
| = кап    | 50% | ~63% (31.5%) |
| = 2× кап | 50% | ~86% (43%) |
| = 3× кап | 50% | ~95% (47.5%) |

#### Конфигурация капов

| Переменная | Тип капа | Значение | Decay |
|------------|----------|----------|-------|
| **Скорость** | | | |
| `speed`         | absolute | ±50%   | 1.5 |
| `attack_speed`  | positive | +75%   | 1.2 |
| **Урон** | | | |
| `damage`        | positive | +100%  | 1.0 |
| `crit_chance`   | positive | +50%   | 0.8 |
| `crit_damage`   | positive | +150%  | 1.0 |
| **Защита** | | | |
| `defense`       | positive | +80%   | 1.2 |
| `armor`         | positive | +200   | 1.5 |
| **Ци** | | | |
| `qi_cost`        | negative | −50%  | 1.0 |
| `qi_efficiency`  | positive | +50%  | 1.0 |
| **Утилити** | | | |
| `cooldown`    | negative | −60%  | 1.2 |
| `life_steal`  | positive | +30%  | 0.8 |

### B.6. Пример расчёта: Тяжёлая броня

```

От грейда:     defense +30%

От веса (25 кг, база 10 кг):
  speed         −15%
  stamina_cost  +30%
От материала (плохая проводимость Ци):
  qi_efficiency −10%

=== Итоговые модификаторы ===
defense:       +15% + 30% = +45%
speed:         −15%
stamina_cost:  +30%
qi_efficiency: −10%

=== Расчёт защиты ===
База: 100
percent_sum: +45%
result = 100 × 1.45 = 145
Кап для defense: +80%; 145 < 180 (кап), применяется полностью.
Итоговая защита: 145

=== Расчёт скорости ===
База: 100
percent_sum: −15%
result = 100 × 0.85 = 85
Кап для speed: ±50%; 85 в пределах капа.
Итоговая скорость: 85%
```

## ИНТЕГРАЦИЯ

### С техниками

При применении техники с баффами:
1. Получить `BuffManager` цели.
2. Для каждого `buffId` в технике:
   - загрузить данные баффа из базы;
   - проверить на запрещённые типы (на этапе авторинга контента);
   - вызвать `ApplyBuff(buffData, source)`.

### С предметами

При использовании расходуемого предмета:
1. Получить `BuffManager` пользователя.
2. Применить все баффы из списка предмета.

### С экипировкой

Модификаторы от:
- материала предмета;
- грейда предмета;
- зачарований;
- сетовых бонусов;
- проклятий.

### С окружением

Модификаторы от:
- местности (болото → −speed);
- погоды (дождь → −fire_damage);
- времени суток (ночь → +stealth).

## ЛОРНОЕ ОБОСНОВАНИЕ

- **Первичные характеристики:** Тело практика — результат годов тренировок. Нельзя «выпить пилюлю» и стать сильнее — мышцы требуют физических нагрузок. *«Внешнее не заменяет внутреннее».*
- **Ёмкость ядра:** Ядро — сосуд, сформированный при пробуждении. Расширение возможно только через прорыв (трансформацию). Бафф не может «растянуть» ядро без повреждений.
- **Регенерация Ци:** Микроядро работает автономно, как сердце. Нельзя «ускорить сердце» пилюлей без последствий. Можно только поглощать Ци извне (медитация, камни).
- **Проводимость:** Меридианы — каналы для Ци. Временное расширение (бафф) — удалено, поскольку растягивание сосудов создавало путаницу. Вместо баффа проводимости — формации увеличивают концентрацию Ци в области (`environmentMult`). Перки (эластичность/увеличенный диаметр) — постоянное развитие. Проклятия/повреждения — единственный источник отрицательной модификации.

## АРХИТЕКТУРНОЕ ПРЕДСТАВЛЕНИЕ

Система баффов и модификаторов реализуется как **модуль** приложения. Внутренние компоненты:

| Компонент | Назначение |
|-----------|------------|
| Менеджер баффов | Управление активными баффами/дебаффами на цели |
| Данные баффа | Ресурс данных с конфигурацией (тип, длительность, эффекты) |
| Активный бафф | Runtime-представление (источник, оставшаяся длительность, стеки) |
| Система модификаторов | Сбор и суммирование модификаторов из всех источников |
| Калькулятор | Применение формулы `(base + flat) × (1 + percent)` + мягкие капы |
| Реестр мягких капов | Конфигурация капов и decayRate по переменным |
| Реестр модификаторов | Реестр источников (экипировка, техники, состояния, окружение) |

Все конфликты и расчёты обрабатываются в одном месте — **калькуляторе модификаторов**. Никакая другая система не должна самостоятельно пересчитывать финальные значения.

Сообщения между подсистемами — неизменяемые структуры (zero-GC). Кросс-модульные взаимодействия — только через **шину событий**.

# Игровые механики (текущая реализация)

> **Статус:** V1 — реализованные механики, не вошедшие в отдельные доки
> **Назначение:** Документирование механик, добавленных после начальной миграции

## 1. Предметы на земле (Ground Items)

### Когда используются
- При переполнении инвентаря по объёму — излишек выпадает на землю рядом с игроком
- При выбрасывании предмета в корзину (🗑) в инвентаре
- При смерти NPC — лут выпадает на землю

### Механика
- Предметы на земле имеют позицию в мире (пиксельные координаты)
- Каждый предмет — спрайт (процедурный, по категории: оружие/броня/аксессуар/расходник/материал)
- Подбор: клавиша E, радиус 1.5 тайла от игрока
- При подборе предмет добавляется в инвентарь (если переполнен — снова выпадает)
- Предметы на земле не сохраняются (save отключён)

### Корзина (Trash Zone)
- Зона в инвентаре (🗑 иконка) — принимает drag&drop предметов
- При перетаскивании предмета на корзину — он выпадает на землю рядом с игроком
- Принимает только предметы из инвентаря (не экипированные)

## 2. Глобальный вес (Global Carry Weight)

### Принцип
Вес персонажа = вес предметов в инвентаре + вес надетой экипировки.

### Расчёт
- **Инвентарь:** суммарный вес всех предметов (включая стаки)
- **Экипировка:** суммарный вес всех надетых предметов (оружие, броня, аксессуары)
- **Максимум:** базовый (50 кг) + бонусы рюкзака

### Штрафы к скорости
1. **Штраф экипировки (MoveSpeedPenalty):** тяжёлая броня даёт отрицательный процент (например, -15%). Применяется всегда, даже без перевеса.
2. **Штраф перевеса:** если общий вес > максимум, скорость снижается по формуле:
   - ratio = (totalWeight - maxWeight) / maxWeight (cap 3.0)
   - speedMult *= 1.0 / (1.0 + ratio)
   - При 2× перевесе — 0.5× скорости, при 4× — 0.25×

### Объём
- Объём инвентаря ограничен (100 л по умолчанию)
- При переполнении по объёму — излишек выпадает на землю
- Вес может превышать максимум (overflow разрешён), объём — нет

## 3. Сборка тела (Body Assembly)

### Принцип
Каждая сущность (игрок, NPC, животное) имеет собранное тело из частей. Тело — данные (не визуал), управляется BodyService.

### Структура тела
- **Морфология:** гуманоид (11 частей), четвероногое (8), птица (8), змееподобное (6), членистоногое (13), аморфное (2)
- **Dual HP:** каждая часть имеет RedHP (функциональный) и BlackHP (структурный)
  - RedHP = 0 → паралич части (Disabled)
  - BlackHP = 0 → отрубание (Severed)
  - Сердце (Heart) — только RedHP (нет структурного HP)
- **Состояния:** Healthy → Bruised → Wounded → Disabled → Severed

### Сборка
1. BodyFactory.CreateBody(morphology, size, vitality) — создаёт части из шаблона
2. HP масштабируется: effectiveHP = baseHP × vitalityMultiplier × sizeMultiplier
3. Регистрация в BodyService (для игрока) или IBodyDataProvider (для NPC/животных)

### Визуализация
- BodyStatusPanel — схематический силуэт (голова, торс, конечности)
- Цвет по состоянию: зелёный/жёлтый/оранжевый/красный/серый
- HP бары: RedHP + BlackHP
- Live updates через BodyPartDamagedEvent/HealedEvent/SeveredEvent

### Character Sheet (hotkey C)
- Окно с силуэтом тела + HP + статы + культивация
- Pause при открытии

## 5. Процедурные спрайты

### Принцип
Все спрайты генерируются в рантайме через Image API (нет PNG файлов). Кэшируются после первого создания.

### Категории
| Категория | Размер | Детализация |
|-----------|--------|-------------|
| Игрок | 48×48 | Гуманоид в робе (голова, торс, руки, ноги, сапоги) |
| NPC | 48×48 | По роли: страж=синий, торговец=золотой, враг=красный + индикатор роли |
| Животные | 48×48 | По виду: волк=серый (уши+хвост), олень=коричневый (рога), кролик=белый (длинные уши) |
| Экипировка | 32×32 | По типу: меч, шлем, нагрудник, кольцо + цвет по редкости |
| Предметы на земле | 16×16 | По категории (8 типов) |

### Кэширование
- Спрайты создаются один раз и кэшируются (per species/role/category)
- Переиспользуются между всеми экземплярами

## 6. Генератор экипировки «Матрёшка»

### Принцип
Экипировка генерируется послойно (EQUIPMENT_SYSTEM.md §2):
1. **Базовый класс** — подтип оружия/брони (меч, кинжал, копьё, лук / шлем, нагрудник, поножи, ...)
2. **Материал** — тир 1-5 (железо, сталь, духовный металл, ...)
3. **Грейд** — качество (Damaged, Common, Refined, Perfect, Transcendent)
4. **Зачарование** — опциональный модификатор (T1-T5)

### Базовые классы оружия (7)
Меч, кинжал, копьё, секира, посох, лук, алебарда

### Базовые классы брони (6)
Шлем, нагрудник, поножи, сапоги, перчатки, пояс

### Детерминированность
- Все генераторы используют SeededRandom
- Одинаковый seed → одинаковый результат
- Combat использует ICombatRng (seed=12345)

## 7. Быстрые слоты пояса (Belt Quick Slots)

### Принцип
Пояс (экипированный в слот Belt) даёт 7 быстрых слотов (hotbar 1-7) для расходников.

### Механика
- Слоты пояса доступны только если экипирован пояс
- Перетаскивание расходников из инвентаря в слоты пояса
- Использование: клавиши 1-7 (на цифровой клавиатуре или верхний ряд)
- Эффекты: heal (восстановление HP), qi_restore (восстановление Ци)

## 8. Диалоги (Dialogue System)

### Принцип
При нажатии E рядом с мирным NPC открывается окно диалога. Игра ставится на паузу.

### Ролевые диалоги
- **Торговец** — предлагает товары
- **Старейшина** — даёт советы, обучение
- **Культиатор** — обсуждение практик
- **Страж** — информация о безопасности
- **Ученик** — просьбы о помощи
- **Прохожий** — светская беседа
- **Враг** — без диалога (только бой)

### UI
- DialogueWindow: текст NPC + варианты ответов
- Пауза во время диалога
- Возобновление после закрытия

## 9. Боевая диспозиция NPC

### Типы диспозиций
| Диспозиция | Цвет | Поведение |
|-----------|------|----------|
| Hostile | Красный | Атакует игрока при обнаружении (aggro radius = 5 тайлов) |
| Friendly | Зелёный | Защищает игрока, атакует врагов игрока |
| Neutral | Серый | Игнорирует игрока, атакует только при получении урона |
| Merchant | Золотой | Мирный, предлагает торговлю |

### Определение диспозиции
- По роли NPC: Enemy → Hostile, Guard → Friendly, Merchant → Merchant, Passerby → Neutral
- В будущем: по фракционным отношениям (FACTION_SYSTEM.md)

### Aggro
- Hostile NPC обнаруживает игрока в радиусе 5 тайлов
- При обнаружении — threat = 60 (выше порога 50) → переход в Attacking
- NPC движется к игроку и атакует (Space/J для игрока)

## 10. Смерть и лут

### Смерть NPC
- При CurrentHealth ≤ 0 → NPC умирает (IsAlive = false)
- Публикуется NPCDeathEvent
- Лут (экипировка) выпадает на землю рядом с трупом
- Спрайт NPC удаляется

### Смерть игрока
- При остановке сердца (Heart Disabled/Severed) → Die()
- Публикуется PlayerDeathEvent
- Игрок может возродиться (Revive) — HP восстанавливается

### Лут
- EquipmentGenerator генерирует лут на основе уровня убитого
- Лут выпадает на землю (GroundItemService.DropItem)
- Игрок может подобрать (E key)

## 11. Детерминированный бой

### Принцип
Все случайности в бою используют SeededRandom (не Random.Shared). Это обеспечивает:
- Воспроизводимость боёв (одинаковый seed → одинаковый результат)
- Корректную работу с save/load (в будущем)
- Удобство тестирования

### Реализация
- ICombatRng — интерфейс с Next/NextFloat/NextBool
- CombatRng — обёртка над SeededRandom (seed=12345)
- Injected в CombatService, DamageService, CombatAIService и др.

## 12. Защита EventBus от re-entrancy

### Проблема
Если обработчик события публикует событие того же типа → бесконечная рекурсия → StackOverflow.

### Решение
- При публикации проверяется: тип уже в активной публикации?
- Если да — событие добавляется в очередь (_pendingQueue)
- После завершения текущей публикации — очередь обрабатывается
- События не теряются, рекурсия исключена

## 13. Духовное хранилище (Spirit Storage)

### Принцип
Духовное хранилище — предметы хранятся в "духовном пространстве" культиватора. Qi cost за каждый доступ.

### Механика
- Вместимость: 20 слотов (по умолчанию)
- Стоимость доступа: 10 Qi за операцию (store/retrieve)
- Если Qi недостаточно — операция отклоняется
- Предметы в духовом хранилище не учитываются в весе инвентаря

### Отличие от кольца хранения
- **Кольцо хранения** (Storage Ring) — экипируется, N слотов, str-volume model, Qi cost
- **Духовное хранилище** (Spirit Storage) — не экипируется, unlimited, Qi cost per access

## 14. Оптимизация рендеринга

### Viewport culling
- Рендереры рисуют только видимые тайлы (в пределах экрана)
- При 500×500 (250k тайлов) — рисуется ~57-144 тайла (1736× reduction)
- Throttle: QueueRedraw каждые 100ms (10 Hz)

### NEAREST texture filter
- `textures/canvas_textures/default_texture_filter=0` (NEAREST)
- Устраняет сетку между тайлами одного типа (LINEAR bleeding)

### Большая карта (500×500)
- Все 9 биомов присутствуют (Ocean, Sea, Coast, Grassland, Steppe, Forest, Highlands, Mountains, Peak)
- Generation: ~1.4 сек (SmoothBiomes оптимизирован — 0 allocs)
- Render: viewport-culled, работает плавно

# Система тела (Body System)

> **Назначение:** Документ описывает систему конструирования тел всех сущностей мира (игроки, NPC, монстры, духи) и правила их повреждения по модели Kenshi. Документ engine-agnostic — описаны концепции, структуры данных и формулы, без привязки к движку.

**Связанные документы:** `04_entities/ENTITY_TYPES.md`, `02_systems/COMBAT_SYSTEM.md`, `02_systems/TECHNIQUE_SYSTEM.md`, `09_workflow/ALGORITHMS.md`.

---

## 1. Обзор

Система тела предназначена для конструирования тел всех сущностей мира:
- **Игроки** — при генерации персонажа
- **NPC** — неигровые персонажи
- **Монстры** — враждебные существа
- **Духи** — нематериальные сущности

### Цели системы

1. **Модульность** — сборка любого существа из компонентов (частей тела).
2. **Наследование** — свойства вида влияют на тело.
3. **Секторные повреждения** — хитбоксы частей тела (Kenshi-style).
4. **Масштабируемость** — от мыши (Tiny) до космического дракона (Colossal).

### Архитектурный принцип

Тело — это **набор данных** (`BodyData`), а не визуальный объект. Структура тела (список частей тела, их HP, материал, размер) хранится как чистые данные и используется боевой системой для расчёта урона. Визуальное представление сущности (спрайт, анимация) изолировано от данных тела и описано отдельно в `07_ui/SPRITE_CATALOG.md`.

## 2. Иерархия типов сущностей

Тип сущности вычисляется по трёхуровневой иерархии: **SoulType → Morphology → Species**.

### 2.1. Уровень 1: SoulType (Природа сущности)

Определяет фундаментальные свойства существа: наличие тела, природу Ци, тип сознания.

| SoulType | Тело | Ци | Сознание | Примеры |
|----------|------|-----|----------|---------|
| Character | Органическое | Ядро | Полное | Человек, Эльф, Демон |
| Creature | Органическое/Чешуя | Ядро | Инстинкты | Волк, Тигр, Дракон |
| Spirit | Эфирное | Резервуар | Полное | Призрак, Элементаль |

| Construct | Конструкция/Минеральное | Резервуар | Простое | Голем |

|------------|----------|------------|---------|
| Humanoid | Двурукое двуногое | 11 + сердце | Человек, Эльф, Демон |
| Quadruped | Четвероногое | 8 + сердце | Волк, Тигр, Медведь |
| Bird | Крылатое | 6–7 + сердце | Орёл, Феникс |

## 5. Система двойной HP (Kenshi-style)

### 5.1. Концепция

Каждая часть тела имеет **два типа HP**:
- **Функциональная HP (красная)** — работоспособность части.
- **Структурная HP (чёрная)** — целостность части.

```
┌─────────────────────────────────────────────────────────────────┐
│                HP КОНЕЧНОСТИ (пример: рука)                      │
├─────────────────────────────────────────────────────────────────┤
│  ████████████████████░░░░░░░░░░░░░░░░░░░░  Красная HP (40)     │
│  │←── Функциональная HP ──→│                (паралич при 0)    │
│                                                                  │
│  ████████████████████████████████████████░░░░░░░░░░░░░░░░░░░░ │
│  │←────────── Структурная HP (80) ──────────────→│ (отрубание) │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2. Правило соотношения

**Структурная HP = Функциональная HP × 2.**

**Исключение:** Сердце имеет только функциональную HP (нет структурной).

### 5.3. Механика повреждения

Урон распределяется **одновременно** (не последовательно!):

```
redHP   -= damage × 0.7     // 70% в функциональную HP
blackHP -= damage × 0.3     // 30% в структурную HP
```

- При `redHP ≤ 0` → **паралич** части тела (Crippled).
- При `blackHP ≤ 0` → **отрубание** части тела (Severed).

### 5.4. Состояния части тела

| Состояние | Условие |
|-----------|---------|
| Healthy | Оба типа HP полны |
| Damaged | Функциональная HP снижена |
| Crippled | Функциональная HP = 0, часть парализована |
| Severed | Структурная HP = 0, часть отрублена |

## 6. Body Templates (10 шаблонов тел)

Шаблоны тела (Body Templates) — заранее определённые структуры для каждой морфологии, содержащие список частей тела с базовыми HP. Реестр шаблонов (BodyTemplateProvider) содержит **10 базовых шаблонов**:

### 6.1. Humanoid (гуманоид, 11 + сердце)

| Часть | Функц. HP | Струк. HP | Функции |
|-------|-----------|-----------|---------|
| Head | 50 | 100 | Сенсорика, дыхание |
| Torso | 100 | 200 | Кровообращение, пищеварение |
| Heart | 80 | — | Только функциональная HP |
| Arm ×2 | 40 | 80 | Манипуляция, атака |
| Hand ×2 | 20 | 40 | Манипуляция |
| Leg ×2 | 50 | 100 | Передвижение |
| Foot ×2 | 25 | 50 | Передвижение |

**Итого:** 500 функциональной + 820 структурной HP (без сердца).

**Иерархия зависимостей:**

```
torso
├── head
├── left_arm → left_hand
├── right_arm → right_hand
├── left_leg → left_foot
└── right_leg → right_foot
```

> При потере родительской части все дочерние теряются (например, при отрубании `left_arm` автоматически теряется `left_hand`).

## 7. Живучесть (Vitality) и масштабирование HP

### 7.1. Формула множителя

```
hpMultiplier = 1.0 + (vitality - 10) × 0.05
effectiveHP = baseHP × hpMultiplier × sizeMultiplier × cultivationBonus
```

Где:
- `baseHP` — базовое HP части тела (из шаблона).
- `vitality` — характеристика живучести.
- `sizeMultiplier` — множитель класса размера.
- `cultivationBonus = 1 + (cultivationLevel - 1) × 0.1`.

### 7.2. Таблица множителей Vitality

| Vitality | HP множитель | Регенерация | Сопротивление шоку |
|----------|--------------|-------------|---------------------|
| 10 | ×1.0 | 0% | 0% |
| 20 | ×1.5 | +10% | +5% |
| 30 | ×2.0 | +20% | +10% |
| 50 | ×3.0 | +40% | +20% |
| 75 | ×4.25 | +65% | +35% |
| 100 | ×5.5 | +90% | +50% |

### 7.3. Пересчёт HP при изменении Vitality

При изменении Vitality все HP частей тела пересчитываются. **Текущий урон сохраняется пропорционально** (`damage_ratio = currentDamage / maxHP`).

### 7.4. Развитие живучести

| Источник | Прирост | Примечание |
|----------|---------|------------|
| Получение урона + восстановление | +0.005 | Медленное лечение |
| Техники закалки тела | +0.02–0.05 | Специальные методы |
| Лекарственные ванны | +0.01–0.03 | Алхимия |

## 8. Кровотечение (5 уровней)

При получении значительного урона начинается кровотечение. Уровень определяется величиной урона относительно `maxHP` поражённой части.

| Уровень | HP/тик | Цвет |
|---------|--------|------|
| 0 — Нет | 0 | — |
| 1 — Лёгкое | 1 | Жёлтый |
| 2 — Среднее | 3 | Оранжевый |
| 3 — Тяжёлое | 5 | Красный |
| 4 — Критическое | 10 | Тёмно-красный |

> 1 тик = 1 игровая минута (см. `03_world/TIME_SYSTEM.md`).

## 9. Регенерация

**Базовая скорость:** `0.1 HP/тик` для органического материала.

**Порядок восстановления:**
1. Сначала структурная HP (целостность).
2. Затем функциональная HP (работоспособность).

**Факторы ускорения:**
- Высокая живучесть (см. таблицу в §7.2: +10%..+90% регенерации).
- Лекарственные средства.
- Техники исцеления (`neutral`-стихия).
- Отдых.

## 10. Приживление конечностей

### 10.1. Условия

1. **Совместимость по размеру** — в пределах одного класса (Tiny–Medium, Medium–Huge и т.д.).
2. **Совместимость по материалу** — organic → organic.
3. **Хирургическая операция** — требуется врач (NPC с навыком).
4. **Время приживления** — зависит от качества операции.

### 10.2. Риски

| Риск | Вероятность / Условие |
|------|------------------------|
| Отторжение | Несовместимость по виду |
| Инфекция | Плохая стерильность |
| Нервное несоответствие | Снижение ловкости (AGI) |

## 11. Привязка характеристик к телу и душе

| Характеристика | Привязка | Обоснование |
|----------------|----------|-------------|
| **Сила (STR)** | Тело | Физическая мощь мышц и скелета |
| **Ловкость (AGI)** | Тело | Координация и рефлексы тела |
| **Живучесть (VIT)** | Тело | Выносливость и плотность тела |
| **Интеллект (INT)** | Душа | Ментальная сила и духовное развитие |

### Следствия привязки

- **Тело (STR/AGI/VIT):** Развиваются через физические действия. При потере/замене части тела могут временно снижаться. Восстанавливаются тренировками.
- **Душа (INT):** Развивается через медитацию и использование техник. НЕ зависит от состояния тела — практик без рук сохраняет интеллект.
- **Смертный → Практик:** При пробуждении ядра INT получает бонус от духовного прозрения; тело остаётся прежним.
- **Сохранение:** STR/AGI/VIT привязаны к телу (сохраняются в `BodyData`). INT привязан к душе (сохраняется в `CultivationData`).

> См. также `06_player/MORTAL_DEVELOPMENT.md` — этапы пробуждения.

## 12. Развитие физических характеристик

### 12.1. Принцип линейного развития

Из лора: «нет стадии куколки, чтобы резко делать скачки». Развитие:
1. **Постепенное** — прирост 0.001 за действие.
2. **Накопительное** — виртуальная дельта накапливается.
3. **Закрепляемое** — сон конвертирует виртуальную дельту в реальную.
4. **С порогами** — чем выше стат, тем больше дельты нужно.

### 12.2. Виртуальная дельта

```
Физическая нагрузка (тренировка/бой)
    │
    ▼
┌──────────────────────────────────────────┐
│ ВИРТУАЛЬНАЯ ДЕЛЬТА (временная)            │
│                                            │
│ virtualStrengthDelta: +0.047               │
│ virtualAgilityDelta: +0.023                │
│                                            │
│ НЕ влияет на боевые характеристики!        │
│ НЕ теряется без сна (кап на дельту)        │
└──────────────────────────────────────────┘
    │
    │ Минимум 4 часа сна
    ▼
┌──────────────────────────────────────────┐
│ ЗАКРЕПЛЕНИЕ (конвертация)                 │
│                                            │
│ Сон 4+ часов:                              │
│ - Максимум за сон: +0.20 (8 часов)        │
│ - Остаток сохраняется в виртуальной дельте │
└──────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────┐
│ РЕАЛЬНАЯ ХАРАКТЕРИСТИКА                   │
│                                            │
│ strength: 12.047 → 12.067 (закреплено +0.02)│
└──────────────────────────────────────────┘
```

### 12.3. Источники прироста

| Действие | Прирост | Характеристика |
|----------|---------|----------------|
| Удар в бою | +0.001 | Сила |
| Уклонение/блок | +0.001 | Ловкость |
| Физическая тренировка | +0.002/мин | По выбору |
| Использование техники | +0.0005 | Интеллект |
| Получение урона + лечение | +0.005 | Живучесть |
| Медитация | +0.01/мин | Интеллект |

### 12.4. Система порогов

| Текущий стат | Порог повышения | Дельта для +1 |
|--------------|-----------------|---------------|
| 10 → 11 | базовый | 1.0 |
| 20 → 21 | ×2 | 2.0 |
| 50 → 51 | ×5 | 5.0 |
| 100 → 101 | ×10 | 10.0 |

### 12.5. Закрепление при сне

- Минимум 4 часа сна для закрепления.
- Максимум закрепления за сон: +0.20 (при 8 часах).
- 4 часа = +0.067, 6 часов = +0.133, 8 часов = +0.20.

### 12.6. Достижимость за периоды

| Период | Достижимый стат | Время на +1 |
|--------|-----------------|-------------|
| 1000 дней | ~55 | 21–28 дней |
| 3000 дней | ~80 | 42–56 дней |
| 10000 дней | ~125 | 70+ дней |

## 14. Структура данных тела

Тело сущности хранится как **чистые данные** (без привязки к движку). Примерная логическая структура:

```
BodyData:
  species:           SpeciesId          // ссылка на реестр видов
  morphology:        Morphology         // enum
  material:          BodyMaterial       // enum
  sizeClass:         SizeClass          // enum (Tiny..Colossal)
  vitality:          int                // текущая живучесть
  parts:             List<BodyPartData> // части тела

BodyPartData:
  partId:            string             // "head", "left_arm", ...
  parentId:          string?            // иерархия
  functionalHP:      int                // красная HP (max)
  structuralHP:      int                // чёрная HP (max)
  currentDamageRed:  int                // текущий урон функциональной
  currentDamageBlack:int                // текущий урон структурной
  state:             PartState          // Healthy/Damaged/Crippled/Severed
  bleeding:          BleedLevel         // 0..4
  attached:          bool               // false если отрублена
```

> Все операции над телом (нанесение урона, регенерация, приживление) работают через эти структуры данных, а не через визуальные узлы. Это позволяет battle-логике выполняться в pure-C# модулях (см. `01_architecture/MODULE_STRUCTURE.md`).

---

## 15. Производительность

- **BodyData ≈ 1.9 KB на сущность** (11+1 частей × ~150 байт на часть + метаданные).
- Все операции модифицируются в tick-batch режиме: кровотечение и регенерация обрабатываются пакетно каждые 10 тиков.
- При `MaxActiveNPCs = 100` суммарный overhead системы тела < 0.5 ms / tick.

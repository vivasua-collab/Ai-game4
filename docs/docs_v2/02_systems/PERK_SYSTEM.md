# Система перков (особенностей)

> **Раздел:** Игровые системы — механики
> **Статус:** Концептуальная спецификация (дизайн-документ, вдохновлён Eastern Era)
> **Самостоятельный документ:** не требует иных файлов для понимания.

---

## 1. Назначение

Перк (Perk / Feature / Trait) — **постоянная пассивная способность** персонажа. В отличие от баффов (временные эффекты) и навыков (развиваются тренировкой), перки:
- постоянны (действуют, пока не сняты);
- уникальны (каждый перк — особенный эффект, не просто +X%);
- ограничены (количество слотов ограничено);
- занимают ровно 1 слот каждый;
- зарабатываются действиями, событиями, выборами.

> **Принцип:** Перк = «Твоя уникальная особенность». Бафф = «Временное усиление». Навык = «Развитая способность».

## 2. Ключевые принципы

| Принцип | Описание |
|---------|----------|
| **Перманентность** | Перк действует постоянно, пока не удалён |
| **Уникальность** | Каждый перк — особенный эффект, не просто +X% |
| **Ограниченность** | Ограниченное количество слотов для перков |
| **1 перк = 1 слот** | Каждый перк занимает ровно один слот |
| **Получение через игру** | Зарабатываются действиями, событиями, выборами |

## 3. Система слотов

### 3.1. Типы слотов

| Тип слота | Описание | Количество |
|-----------|----------|------------|
| 🌟 **Врождённые (Innate)** | Фиксированы при рождении/пробуждении. Нельзя удалить, изменить или получить новые. | 2 (фиксировано) |
| 🎯 **Приобретённые (Acquired)** | Основные слоты. Заполняются действиями в игре. Можно заменить. | 5 + уровень_культивации |
| 💀 **Проклятые (Cursed)** | Отдельный лимит. Навязанные перки с +/- эффектами. Снимаются ритуалом очищения. | до 3 |

> **Врождённые перки НЕ используют слоты.** Они находятся вне системы слотов и не мешают заполнять приобретённые.

### 3.2. Количество слотов

| Тип слотов | Базовое | Прирост | Максимум |
|------------|---------|---------|----------|
| Врождённые     | 2 | — | 2 (фиксировано) |
| Приобретённые  | 5 | +1 за уровень культивации | 5 + 9 = 14 (на L9) |
| Проклятые      | 0 | — | 3 |

## 4. Категории перков

### 4.1. По происхождению

| Категория | Описание | Слоты |
|-----------|----------|-------|

| 🎯 Приобретённые | Через игру, можно заменить | Основные слоты |

### 4.2. По эффекту

| Категория | Описание | Примеры |
|-----------|----------|---------|
| **Боевые**       | Влияют на бой | +урон, +крит, новые атаки |
| **Выживание**    | Защита и регенерация | HP, сопротивления, иммунитеты |
| **Культивация**  | Ци и развитие | Поглощение Ци, прорывы |
| **Социальные**   | Взаимодействие с NPC | Торговля, репутация, диалоги |
| **Исследование** | Мир и путешествия | Скорость, видение, поиск |
| **Крафт**        | Создание предметов | Качество, скорость, рецепты |

## 5. Перковые эффекты и Ци

### 5.1. Что НЕ зависит от перков

> **Регенерация Ци зависит ТОЛЬКО от ядра.**

- Микроядро генерирует 10% от ёмкости ядра в сутки.
- Это базовая характеристика ядра, не зависящая от перков.
- Ядро — физический орган с фиксированной производительностью; генерация Ци — естественный процесс, как дыхание.

### 5.2. Что можно и нельзя усилить перками

| Можно усилить перками | Нельзя усилить |
|-----------------------|----------------|
| Скорость ПОГЛОЩЕНИЯ Ци из среды | Регенерация Ци (микроядро) |
| Эффективность медитации | Ёмкость ядра |
| Проводимость меридиан (бонус) | Плотность Ци |
| Скорость вывода Ци для техник | |

## 6. Проводимость меридиан и перки

### 6.1. Базовая формула

```
conductivity = coreCapacity / 360 секунд
```

Примеры:
- L1.0: 1 000 / 360 ≈ 2.78 Ци/сек
- L5.0: 45 260 / 360 ≈ 125.7 Ци/сек

### 6.2. Развитие проводимости через перки

```
finalConductivity = baseConductivity × (1 + conductivityBonus)
```

Источники бонуса:
- Врождённый перк «Золотое качество тела» — +30%
- Приобретённый перк «Закалка меридиан» — +15% (требует 100 часов медитации)
- Приобретённый перк «Небесные каналы» — +20%

> ⛔ Временные баффы проводимости (`ConductivityBoost`) — **УДАЛЕНЫ**. См. `02_systems/BUFF_MODIFIERS_SYSTEM.md`.
> Формации увеличивают `environmentMult`, а не проводимость.

### 6.3. Ограничение поглощения

```
absorbedQi = min(
    meditationTime × conductivity × environmentMult,
    availableQiInEnvironment
)
```

Поглощение **не может превышать** проводимость меридиан.

## 9. Структура данных (концептуальная)

Ключевые поля ресурса данных перка:
- **Identity:** `id`, `displayName`, `description`, `icon`.
- **Category:** `Innate` / `Acquired` / `Cursed`.
- **Effects:** список эффектов перка (применяются к модификаторам/поведению).
- **isPermanent:** `true` для врождённых и проклятых.

Ключевая логика контроллера перков:
- `innatePerks` — список врождённых (фиксирован, не использует слоты).
- `acquiredPerks` — список приобретённых; `MaxAcquiredSlots = 5 + cultivationLevel`.
- `cursedPerks` — список проклятых; `MaxCursedSlots = 3`.
- `GetConductivityBonus()` — сумма бонусов проводимости от всех перков.

> **Интеграция с системой Ци:** При пересчёте статов (`RecalculateStats`) итоговая проводимость вычисляется как:
> ```
> finalConductivity = baseConductivity × (1 + perkConductivityBonus)
> ```

## 10. Архитектурное представление

Система перков реализуется как часть **модуля развития персонажа**:
- точка входа модуля регистрируется в DI-контейнере;
- изменения публикуются через **шину событий** (`PerkAcquired`, `PerkRemoved`);
- сохранение: список ID перков и состояние слотов — `ISaveable`.

Производительность:
- `GetConductivityBonus()` — O(N) по числу перков (N ≤ ~20), вызывается при пересчёте статов (редко).
- Никаких hot-path вычислений: бонусы кэшируются при изменении набора перков.

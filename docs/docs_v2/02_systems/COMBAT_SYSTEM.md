# Боевая система (Combat System)

> **Назначение:** Документ описывает механику сражений: real-time-with-pause, tick-based симуляцию, 11-слойный конвейер прохождения урона, типы атак, эффекты стихий, оглушение/кровотечение/смерть. Документ engine-agnostic: описаны только концепции, формулы и данные — без привязки к движку.

**Связанные документы:** `02_systems/BODY_SYSTEM.md`, `02_systems/QI_SYSTEM.md`, `02_systems/TECHNIQUE_SYSTEM.md`, `02_systems/ELEMENTS_SYSTEM.md`, `02_systems/FORMATION_SYSTEM.md`, `09_workflow/ALGORITHMS.md`.

---

## 1. Обзор и принципы

### 1.1. Принципы боя

1. **Игровое состояние — источник истины.** Игра полностью однопользовательская, все боевые расчёты выполняются локально.
2. **Действия измеряются в тиках.** 1 тик = 1 игровая минута. Бой ведётся в реальном времени с возможностью паузы.
3. **Порядок применения защит важен.** Защиты применяются строго в определённой последовательности.
4. **Ци — первый уровень защиты от ЛЮБОГО урона** (даже во сне).

### 1.2. Real-time with pause

- Бой происходит в реальном времени; игрок может поставить паузу в любой момент.
- При начале боя автоматически включается режим `superSuperSlow` (очень медленная скорость симуляции, ~0.25 минут/тик).
- Скорости симуляции: pause=0, normal=1 tps, fast=5 tps, quick=15 tps.
- См. `03_world/TIME_SYSTEM.md` для деталей системы тиков.

### 1.3. Tick-based, а не physics-driven

Бой НЕ использует физический движок (нет rigidbody-солвера). Все попадания, движение снарядов, AoE рассчитываются формульно через тайлы и тики. Это обеспечивает:
- Детерминизм симуляции.
- Низкие накладные расходы (battle logic работает в pure-C# модулях, тестируется через `dotnet test`).
- Простоту AI (decision per tick, а не per frame).

## 2. 11-слойный конвейер прохождения урона

Любая атака (техника или обычный удар) проходит через **11 слоёв обработки**, прежде чем привести к фактическому урону HP части тела. Порядок слоёв строго фиксирован.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                  КОНВЕЙЕР ПРОХОЖДЕНИЯ УРОНА (11 СЛОЁВ)                       │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                               │
│  СЛОЙ 1 — ИСХОДНЫЙ УРОН (RAW DAMAGE)                                          │
│  ├── capacity = baseCapacity(type) × 2^(techniqueLevel-1) × (1 + mastery/100 × 0.5) │
│  ├── rawDamage = capacity × gradeMultiplier × ultimateMultiplier              │
│  ├── (+ бонус урона оружия для melee_weapon: bonusDamage = weaponDamage × statScaling) │
│  └── gradeMultiplier: common=1.0, refined=1.3, perfect=1.6, transcendent=2.0  │
│      ultimateMultiplier: isUltimate ? 2.0 : 1.0                               │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 2 — ПОДАВЛЕНИЕ УРОВНЕМ (LEVEL SUPPRESSION)                              │
│  ├── suppressionMult = getSuppression(attackerLevel, targetLevel, attackType) │
│  └── damage ×= suppressionMult                                                │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 3 — ОПРЕДЕЛЕНИЕ ЧАСТИ ТЕЛА (BODY PART ROLL)                             │
│  ├── hitPart = rollBodyPart(attacker, target, weapon)                         │
│  ├── head: 5%, torso: 40%, heart: 2%, arm: 20%, leg: 24%, hands: 8%, feet: 1% │
│  └── (+ бафф/дебафф активных формаций: damage ×= formationBuffMultiplier)     │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 4 — АКТИВНАЯ ЗАЩИТА (ACTIVE DEFENSE, выбор игрока)                      │
│  ├── Уклонение: dodgeChance = 5% + (AGI-10) × 0.5% - armorDodgePenalty        │
│  │   └── успех → damage = 0, END                                              │
│  ├── Парирование: parryChance = weaponParryBonus + (AGI-10) × 0.3%             │
│  │   └── успех → damage ×= (1 - blockEffectiveness), durability--             │
│  └── Блок щитом: blockChance = shieldBlock + (STR-10) × 0.2%                   │
│      └── успех → damage ×= (1 - shieldEffectiveness), shieldDurability--      │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 5 — БУФЕР ЦИ (QI BUFFER, для ЛЮБОГО урона)                              │
│  ├── Если currentQi > minQiForBuffer:                                         │
│  │   ├── Qi-техника + щит: 100% погл., 1:1, 0% пробитие                       │
│  │   ├── Qi-техника + сырая Ци: 90% погл., 3:1, 10% пробитие                  │
│  │   ├── Физ. урон + щит: 100% погл., 2:1, 0% пробитие                        │
│  │   └── Физ. урон + сырая Ци: 80% погл., 5:1, 20% пробитие                   │
│  └── Если Ци недостаточно → урон идёт дальше без поглощения                   │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 6 — БРОНЯ ЧАСТИ ТЕЛА: ПОКРЫТИЕ                                          │
│  ├── armor = getEquippedArmorForPart(hitPart)                                 │
│  └── if (random() < armor.coverage) → переход к СЛОЮ 7                        │
│      else → урон идёт напрямую в СЛОЙ 8 (минуя снижение брони)                │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 7 — СНИЖЕНИЕ УРОНА БРОНЁЙ                                              │
│  ├── Процентное снижение: damageReduction = min(0.8, armor.damageReduction    │
│  │                       + materialBonus + gradeBonus)  // кап 80%            │
│  ├── damage ×= (1 - damageReduction)                                          │
│  ├── Плоское вычитание (пробитие):                                            │
│  │   penetration = weapon.penetration + attackerSTR × 0.5 + techniquePenetration │
│  │   effectiveArmor = max(0, armor.armor - penetration)                       │
│  │   damage = max(1, damage - effectiveArmor × 0.5)                           │
│  └── Износ брони: armor.durability.current -= damage × 0.1 / hardness        │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 8 — МАТЕРИАЛ ТЕЛА ЦЕЛИ                                                  │
│  ├── materialReduction = getMaterialReduction(target.bodyMaterial)             │
│  └── damage ×= (1 - materialReduction)                                        │
│      (organic 0%, scaled 30%, chitin 20%, ethereal 70% физ., mineral 50%)    │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 9 — РАСПРЕДЕЛЕНИЕ ПО HP (одновременный split 0.7/0.3)                   │
│  ├── redHP   -= damage × 0.7   // 70% в функциональную HP                      │
│  ├── blackHP -= damage × 0.3   // 30% в структурную HP                         │
│  ├── При redHP ≤ 0 → паралич части тела                                       │
│  └── При blackHP ≤ 0 → отрубание части тела                                   │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 10 — ПОСЛЕДСТВИЯ (CONSEQUENCES)                                         │
│  ├── Кровотечение: если damage > threshold → bleedDamage per tick (1..10 HP)  │
│  ├── Шок: если redHP < 30% maxHP → штрафы к действиям                         │
│  ├── Оглушение: шанс = damage / maxHP × 10%                                   │
│  ├── Смерть: если heart HP ≤ 0 ИЛИ head HP ≤ 0                                │
│  └── DoT-эффекты стихий (burn, poison, freeze)                                │
│                                                                               │
│       ↓                                                                       │
│  СЛОЙ 11 — ЛУТ-ГЕНЕРАЦИЯ (ЗАПЛАНИРОВАН)                                       │
│  └── Генерация дропа на основе уровня, стихии, вида — будущая задача          │
│                                                                               │
└──────────────────────────────────────────────────────────────────────────────┘
```

> Слои 1–10 реализованы; слой 11 (loot generation) помечен как будущая задача. Под-опции (1b weapon bonus, 3b formation buff, 10b loot) входят в основные слои как под-этапы.

## 3. Авторитетная формула урона

```
finalDamage = capacity × gradeMultiplier × ultimateMultiplier
```

Где:
- `capacity = baseCapacity(type) × 2^(techniqueLevel-1) × (1 + mastery/100 × 0.5)`.
- `gradeMultiplier`: common=1.0, refined=1.3, perfect=1.6, transcendent=2.0.
- `ultimateMultiplier`: `isUltimate ? 2.0 : 1.0`.

> **Внимание:** Любые формулы, использующие `qiDensity × statMultiplier × masteryBonus` или `qiInvested` как базу, считаются устаревшими. Единственная правильная формула использует `capacity`.

### 3.1. Плотность Ци (qiDensity)

```
qiDensity = 2^(cultivationLevel - 1)
```

Геометрический рост ×2 за каждый уровень культивации. `qiDensity` встроена в формулу `capacity` как `2^(techniqueLevel-1)` и отдельно в расчёте урона не фигурирует.

## 4. Типы атак (5 подтипов)

Все атаки делятся на 2 группы (Melee и Ranged) и 5 подтипов. Каждый подтип имеет базовую ёмкость (`baseCapacity`), определяющую максимально обрабатываемое техникой Ци.

### 4.1. Ближний бой (Melee)

| Подтип | Описание | baseCapacity | Бонус STR | Бонус AGI |
|--------|----------|--------------|-----------|-----------|
| `melee_strike` | Удар телом (без оружия) | 64 | 5% | 2.5% |
| `melee_weapon` | Удар с оружием | 48 | 2.5% | 5% |

### 4.2. Дальний бой (Ranged)

| Подтип | Описание | baseCapacity | Бонус AGI | Бонус INT |
|--------|----------|--------------|-----------|-----------|
| `ranged_projectile` | Снаряд | 32 | 2.5% | 5% |
| `ranged_beam` | Луч | 32 | 2.5% | 5% |
| `ranged_aoe` | Область | 32 | 2.5% | 5% |

### 4.3. Бонус урона оружия (для melee_weapon)

Для атак с оружием поверх raw damage добавляется бонус:

```
baseDamage = max(handDamage, weaponDamage × 0.5)
bonusDamage = weaponDamage × statScaling
rawDamage += bonusDamage
```

См. `05_data/CONFIGURATIONS.md` и `06_player/EQUIPMENT_SYSTEM.md` для деталей.

## 6. Подавление уровнем (Level Suppression)

**Проблема:** Qi-буфер с поглощением 90% позволяет практике L1 наносить урон практике L8.

**Решение:** Множитель подавления на основе разницы уровней (`attackerLevel − targetLevel`).

| Разница уровней | Normal | Technique | Ultimate |
|-----------------|--------|-----------|----------|
| 0 | ×1.0 | ×1.0 | ×1.0 |
| 1 | ×0.5 | ×0.75 | ×1.0 |
| 2 | ×0.1 | ×0.25 | ×0.5 |
| 3 | ×0.0 | ×0.05 | ×0.25 |
| 4 | ×0.0 | ×0.0 | ×0.1 |
| 5+ | ×0.0 | ×0.0 | ×0.0 |

## 7. Система попадания

### 7.1. Уклонение (Dodge)

```
dodgeChance = 5% + (AGI - 10) × 0.5% - armorDodgePenalty
```

При успехе → `damage = 0`, атака завершается.

### 7.2. Парирование (Parry)

**Требования:** имеется оружие или щит, цель в пределах досягаемости.

```
parryChance = weaponParryBonus + (AGI - 10) × 0.3%
```

При успехе → `damage ×= (1 - blockEffectiveness)`, прочность оружия снижается.

### 7.3. Блок щитом (Block)

```
blockChance = shieldBlock + (STR - 10) × 0.2%
```

При успехе → `damage ×= (1 - shieldEffectiveness)`, прочность щита снижается.

## 11. Специальные механики

### 11.1. DoT (Damage-over-Time)

- **Burn (горение):** 5% от исходного урона за тик в течение 3 тиков.
- **Bleed (кровотечение):** 1–10 HP/тик в зависимости от уровня (5 уровней).
- **Poison (отравление):** прогрессирует по стадиям (onset → progression → critical), зависит от Grade техники яда.

### 11.2. AoE (Area of Effect)

- Формации (магические массивы) создают AoE-зоны размером от **3×3 м** (Small) до **300×300 м** (Heavy).
- Эффект формации действует в радиусе 50 м – 5 км.
- `ranged_aoe` техники создают AoE через эффекты `ExpandingEffect` (см. `02_systems/TECHNIQUE_EFFECTS.md`).

### 11.3. Chain Lightning

Молниевые техники (`lightning`) при попадании по цели наносят **50% урона по 2 соседним целям**. Transcendent-версия: `+25% урона каждой следующей цели` (chain_scaling).

### 11.4. Knockback (отброс)

Воздушные техники (`air`) отбрасывают цель на **3 клетки**. Не зависит от размера цели (но цели `Huge+` иммунны).

### 11.5. Pierce (пробитие)

- Пустота (`void`): +30% пробития брони.
- Transcendent Нейтральный: +10% пробития брони (`armor_pierce`).
- Пробитие оружия: `weapon.penetration + attackerSTR × 0.5 + techniquePenetration`.

## 12. Применение урона к телу (split 0.7/0.3)

Урон распределяется **одновременно** (не последовательно!):

```
redHP   -= damage × 0.7     // 70% в функциональную HP
blackHP -= damage × 0.3     // 30% в структурную HP
```

- При `redHP ≤ 0` → паралич части тела (Crippled).
- При `blackHP ≤ 0` → отрубание части тела (Severed).
- При `heart HP ≤ 0` или `head HP ≤ 0` → смерть.

> См. `02_systems/BODY_SYSTEM.md` §5 для деталей о двойной HP.

### 12.1. Кровотечение

| Степень | HP/тик |
|---------|--------|
| Лёгкое | 1 |
| Среднее | 3 |
| Тяжёлое | 5 |
| Критическое | 10 |

## 13. Пример полного расчёта

**Сценарий:**
- Атакующий: L3, Combat-Melee L2, Refined, Mastery 50%.
- Защищающийся: L4, Qi 5000, защита Raw Qi.

**Расчёт:**

```
1. baseCapacity (melee_strike) = 64
2. qiCost = 64 × 2^1 = 128

3. capacity = 64 × 2^1 × (1 + 50 × 0.005)
            = 64 × 2 × 1.25
            = 160

4. rawDamage = 160 × 1.3 (Refined)
             = 208

5. Level Suppression:
   diff = 4 - 3 = 1
   multiplier = 0.75 (Technique)
   damage = 208 × 0.75 = 156

6. Qi Buffer (Qi-техника vs Raw Qi):
   absorbed = 156 × 0.9 = 140.4
   qiNeeded = 140.4 × 3 = 421.2
   piercing = 156 × 0.1 = 15.6

7. (Пропускаем СЛОИ 6–8 — допустим, без брони и материала)
8. Final damage = 15.6
9. redHP   -= 15.6 × 0.7 = 10.92
10. blackHP -= 15.6 × 0.3 = 4.68
```

## 14. Структура данных боя

Боевая логика выполняется в **pure-C# модулях** (без зависимости от движка). Примерная структура данных:

```
DamageInfo:
  amount:        int            // итоговый урон (после всех слоёв)
  element:       Element        // стихия
  source:        EntityId       // атакующий
  hitPart:       BodyPartId     // поражённая часть тела
  hitPoint:      Position2D     // точка попадания
  isCritical:    bool
  isUltimate:    bool

DamageResult:
  rawDamage:          int       // после СЛОЯ 1
  postSuppression:    int       // после СЛОЯ 2
  postQiBuffer:       int       // после СЛОЯ 5
  postArmor:          int       // после СЛОЯ 7
  postMaterial:       int       // после СЛОЯ 8
  redHPDamage:        int       // 70%
  blackHPDamage:      int       // 30%
  isFatal:            bool      // смерть
  consequences:       List<Consequence>  // bleed, stun, shock
```

> События боя публикуются через шину событий как `readonly struct` (zero-GC). См. `01_architecture/DI_AND_EVENTBUS.md`.

## 15. Производительность

- Battle tick обрабатывается в одном проходе по всем активным участникам боя.
- При `MaxActiveNPCs = 100` и типичном бое 10×10: ~5 ms на полный battle tick.
- Pooling объектов `DamageInfo`/`DamageResult` — обязателен (zero-GC policy).
- Слои 1–8 выполняются синхронно в одном вызове; слои 9–10 могут эмитить события для других систем (анимация, звук, UI).

## Детерминированность (Q5)

Все случайности в бою используют `ICombatRng` (обёртка над `SeededRandom`, seed=12345). Это обеспечивает:
- **Воспроизводимость боёв** — одинаковый seed → одинаковый результат (полезно для отладки и тестов).
- **Корректную работу с save/load** в будущем — состояние генератора сериализуется, бой продолжается детерминированно после загрузки.
- **Удобство тестирования** — фиксированный seed даёт стабильные кейсы в unit-тестах.

### Принцип
- `ICombatRng` — интерфейс с методами `Next(int)`, `NextFloat()`, `NextBool(double)`.
- `CombatRng` — реализация-обёртка над `SeededRandom` (seed=12345 по умолчанию).
- НЕ использует `Random.Shared` или `System.Random()` (недетерминированно).

### Где внедряется
`ICombatRng` инжектится через DI в следующие сервисы:
- `CombatService` — основной оркестратор боя (выбор цели, ход).
- `DamageService` — расчёт урона, криты, проки эффектов.
- `CombatAIService` — решения NPC (атака/перемещение/defense).
- `ElementalEffectService` — шанс наложения стихийных эффектов (burn, slow, stun, chain...).
- `CombatConsequencesService` — кровотечение, оглушение, шок (слой 10).
- `CombatLootService` — генерация лута с убитого NPC (см. [DEATH_AND_LOOT.md §2](../04_entities/DEATH_AND_LOOT.md)).

> См. также [DI_AND_EVENTBUS.md §1](../01_architecture/DI_AND_EVENTBUS.md) — общие принципы DI.

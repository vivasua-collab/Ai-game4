# Тайловая система

> **Статус:** Концепция (engine-agnostic).
> **Размер тайла = 2 × 2 м** — единый стандарт проекта. См. `WORLD_MAP_SYSTEM.md` §1.
> **Связанные документы:** `WORLD_MAP_SYSTEM.md`, `LOCATION_MAP_SYSTEM.md`, `WORLD_SAVE_SYSTEM.md`.

---

## 1. Обзор

Тайловая система — основа локальных карт, на которых происходит основной геймплей. Каждый тайл — ячейка **2 × 2 м**, содержащая данные о проходимости, объектах, субъектах и параметрах окружения.

Тайловая система описана здесь как **игровая концепция**, без привязки к конкретному движку или тайловому компоненту. Реализация может использовать любой 2D-движок с поддержкой сетки ячеек (координатная сетка); выбор движка влияет только на способ хранения и рендеринга тайлов, не на сами данные.

## 2. Структура тайла

### 2.1 Базовая концепция

```
Тайл 2×2 м
┌───────────────────────────────────────────────────────────────────────────┐
│                                                                            │
│   СЛОЙ 4: СУБЪЕКТЫ (динамический)                                          │
│   ┌─────────────────────────────────────────────────────────────────┐    │
│   │  👤 Игрок    🐺 NPC    🐺 NPC                                     │    │
│   └─────────────────────────────────────────────────────────────────┘    │
│                              ↑                                            │
│   СЛОЙ 3: ОБЪЕКТЫ (полустатический)                                       │
│   ┌─────────────────────────────────────────────────────────────────┐    │
│   │  🌲 Дерево    🪨 Камень    🌾 Куст                                │    │
│   └─────────────────────────────────────────────────────────────────┘    │
│                              ↑                                            │
│   СЛОЙ 2: ПОВЕРХНОСТЬ (статический)                                       │
│   ┌─────────────────────────────────────────────────────────────────┐    │
│   │  🟩 Трава    🟫 Земля    🟦 Вода    ⬜ Камень                    │    │
│   └─────────────────────────────────────────────────────────────────┘    │
│                              ↑                                            │
│   СЛОЙ 1: БАЗОВЫЕ ПАРАМЕТРЫ (неизменный)                                  │
│   ┌─────────────────────────────────────────────────────────────────┐    │
│   │  Высота: 0    Ци: 100    Температура: 20°C                      │    │
│   └─────────────────────────────────────────────────────────────────┘    │
│                                                                            │
└───────────────────────────────────────────────────────────────────────────┘
```

### 2.2 Иерархия слоёв

| Слой | Название | Изменяемость | Примеры |
|------|----------|--------------|---------|
| **1** | Базовые параметры (Ци/температура/высота) | Редко (события) | Высота, базовое Ци, климат |
| **2** | Поверхность | Редко | Трава, земля, вода, камень |
| **3** | Объекты | При взаимодействии | Деревья, камни, здания |
| **4** | Субъекты | Постоянно | Игрок, NPC, монстры |

Каждый слой — это **отдельная логическая сущность**. Слои не рендерятся как один тайл; они хранятся независимо и накладываются друг на друга при отображении. В движке это может быть реализовано как несколько параллельных тайловых слоёв (tile layers), либо как один тайл с агрегированными данными и отрисовкой по приоритету слоёв — это решение реализации, не концепции.

## 3. Система координат

### 3.1 Координатная сетка

```
2D проекция (X, Y):

   Y
   ▲
   │    ┌────┬────┬────┬────┬────┐
   │    │    │    │    │    │    │  Тайл: (0,0) → (width-1, height-1)
   │    ├────┼────┼────┼────┼────┤  Размер: 2×2 м
   │    │    │    │ 👤 │    │    │  Игрок на тайле (2, 3)
   │    ├────┼────┼────┼────┼────┤
   │    │    │ 🌲 │    │ 🌲 │    │
   │    ├────┼────┼────┼────┼────┤
   │    │    │    │    │    │    │
   │    └────┴────┴────┴────┴────┘
   └──────────────────────────────────▶ X
```

### 3.2 Z-уровень (логическая высота)

```
Z = +5  ████████████  Пики гор, небесные острова
Z = +3  ████████████  Высокая точка (вершины холмов, башни)
Z = +2  ████████████  Средний уровень
Z = +1  ████████████  Нижний склон
Z =  0  ────────────  Базовый уровень (равнина, пол)
Z = -1  ▓▓▓▓▓▓▓▓▓▓▓▓  Подвал, пещера
Z = -2  ▓▓▓▓▓▓▓▓▓▓▓▓  Глубокие пещеры
Z = -3  ▓▓▓▓▓▓▓▓▓▓▓▓  Пропасти, глубокие пещеры
Z = -5  ▓▓▓▓▓▓▓▓▓▓▓▓  Экстремальная глубина
```

**Z — это НЕ третье измерение в 3D, а ЛОГИЧЕСКИЙ уровень.** Используется для:
- определения перепада высот для падений;
- влияния на скорость передвижения;
- бонусов/штрафтов в бою (выше = преимущество);
- ограничения видимости.

**Диапазон Z: −5 … +5.**

### 3.3 Влияние высоты на геймплей

| Разница Z | Эффект | Механика |
|-----------|--------|----------|
| **+2 и выше** | Падение | Урон = (Z_diff − 1) × 20 |
| **+1** | Преимущество | +10% к урону, +5% к уклонению |
| **0** | Нейтрально | Без бонусов |
| **−1** | Невыгодно | −5% к урону, +5% получить крит |
| **−2 и ниже** | Серьёзный минус | −15% урон, −10% уклонение |

### 3.4 Проекция

Используется **orthographic top-down** (вид строго сверху). Это НЕ изометрия.

- Спрайты рисуются на 2D-плоскости без перспективных искажений.
- Y-сортировка обеспечивает корректное перекрытие объектов по глубине (ближе к низу экрана — выше в Z-order).
- Высота Z — это логическое значение, влияющее на механику, но не на геометрию.

> Архитектурный принцип: координатный/тайловый слой проекционно-агностичен. При переходе на 2.5D меняется только renderer, не логика.

## 4. Объекты на тайле

### 4.1 Категории объектов

**Непроходимые (impassable):**
- Деревья (tree) — укрытие, можно рубить
- Камни (rock) — укрытие, можно ломать
- Стены (wall) — полная блокировка
- Здания (building) — вход через дверь
- Глубокая вода (deep_water) — требует плавание/лодку
- Пропасти (chasm) — нельзя пройти, падение

**Проходимые (passable):**
- Кусты (bush) — замедление, скрытность
- Высокая трава (tall_grass) — скрытность
- Мелкая вода (shallow_water) — замедление
- Дорога (road) — ускорение
- Развалины (ruins) — частичная проходимость

**Интерактивные (interactive):**
- Сундуки (chest) — открыть/взломать
- Двери (door) — открыть/закрыть
- Рудные жилы (ore_vein) — добывать
- Травы (herb) — собирать
- Места силы (shrine) — молиться/медитировать

### 4.2 Многоячеечные объекты

> Размер тайла = 2 × 2 м.

| Размер в тайлах | Физический размер | Примеры |
|-----------------|-------------------|---------|
| **1×1** (1 тайл) | 2×2 м | Игрок, NPC, дерево, куст, камень, сундук, дверь |
| **2×1** (2 тайла) | 4×2 м | Лошадь, повозка, узкий стол |
| **1×2** (2 тайла) | 2×4 м | Столб, флагшток, высокая статуя |
| **2×2** (4 тайла) | 4×4 м | Небольшой дом, большой дракон, алтарь |
| **3×3** (9 тайлов) | 6×6 м | Средний дом, гигантский монстр |
| **4×4+** (16+ тайлов) | 8×8+ м | Храм, дворец, гигантский босс, формация |

### 4.3 Структура данных многоячеечного объекта

| Поле | Тип | Описание |
|------|-----|----------|
| `objectId` | string | Уникальный ID объекта |
| `objectType` | enum | Тип объекта (tree, rock, chest...) |
| `width` | int | Ширина в тайлах (1, 2, 3...) |
| `height` | int | Высота в тайлах (1, 2, 3...) |
| `origin` | (int, int) | Левый верхний угол (якорь) |
| `isPassable` | bool | Можно ли пройти |
| `moveCost` | float | Множитель стоимости движения (0 = непроходимо) |
| `blocksVision` | bool | Блокирует ли линию видимости |
| `coverBonus` | int | Бонус укрытия (0–100%) |
| `durability` | int | Прочность (если разрушаемое) |
| `interactable` | bool | Можно ли взаимодействовать |
| `interactionType` | enum | Тип взаимодействия |
| `spriteRef` | string | Ссылка на спрайт-ассет |

### 4.4 Множители стоимости движения

| Тип объекта | Move Cost | Примечание |
|-------------|-----------|------------|
| Пустой тайл | 1.0 | Базовая скорость |
| Дорога | 0.7 | Ускорение на 30% |
| Трава | 1.0 | Без изменений |
| Кусты | 1.5 | Замедление 50% |
| Высокая трава | 1.2 | Небольшое замедление |

## 5. Субъекты на тайле

### 5.1 Типы субъектов

**Игрок (Player):** всегда 1 на карте, управляется игроком, может взаимодействовать с любыми объектами.

**NPC (не враждебные):** жители городов, торговцы, стража, мирные странники.

**Монстры (Hostile):** агрессивные к игроку, патрулируют территорию, дропают ресурсы.

**Другие субъекты:** призванные существа, эффекты техник (турели, ловушки), транспортные средства.

### 5.2 Ограничения

- 1 субъект = 1 тайл (по умолчанию)
- Мелкие субъекты (крысы, птицы) — до 4 на тайл
- Крупные субъекты (драконы) — занимают 4+ тайлов (см. §4.2)
- Летающие — могут быть над любым тайлом

### 5.3 Структура данных субъекта

| Поле | Тип | Описание |
|------|-----|----------|
| `entityId` | string | Уникальный ID сущности |
| `soulType` | SoulType | Тип души (character, creature, spirit, artifact, construct) |
| `position` | (int, int) | Координаты тайла (origin для крупных) |
| `width` | int | Ширина в тайлах |
| `height` | int | Высота в тайлах |
| `isFlying` | bool | Летающий (игнорирует поверхность) |
| `faction` | enum | Фракция (player, neutral, hostile, faction_X) |
| `behavior` | enum | Текущее поведение |
| `statsRef` | string | Ссылка на данные характеристик |

## 6. Плотность Ци на тайле

### 6.1 Базовые значения

- 100 — стандартная плотность (равнина)
- < 50 — низкое Ци (пустыня, проклятые места)
- > 200 — высокое Ци (места силы, храмы)

### 6.2 Модификаторы Ци

| Источник | Радиус | Модификатор |
|----------|--------|-------------|
| Святилище | 50–500 м | ×3–10 |
| Духовный источник | 10–100 м | ×2–5 |
| Алтарь | 5–50 м | ×5–15 |
| Лей-линия | 10–30 м | ×2 (вдоль линии) |
| Проклятое место | 20–200 м | ×0.2–0.5 |
| Формация | Радиус | Зависит от типа |

### 6.3 Формула итоговой плотности Ци

```
finalQiDensity = baseQiDensity
               × terrainModifier
               × climateModifier
               × localSourceModifier
               × formationModifier
               × eventModifier
```

### 6.4 Таблица модификаторов местности

| Местность | Модификатор | Базовое Ци |
|-----------|-------------|------------|
| Равнина | ×1.0 | 100 |
| Лес | ×1.0–1.5 | 100–150 |
| Горы (низ) | ×0.8 | 80 |
| Горы (вершина) | ×2.0 | 200 |
| Пустыня | ×0.2–0.4 | 20–40 |
| Болото | ×0.6–1.2 | 60–120 |
| Тундра | ×0.4–0.6 | 40–60 |
| Вулкан | ×1.5–3.0 | 150–300 |
| Священное место | ×3.0–10.0 | 300–1000 |
| Проклятое место | ×0.1–0.5 | 10–50 |
| Подземелье | ×0.5–2.0 | 50–200 |

### 6.5 Регенерация Ци на поверхности тайла

> **⚠️ Теоретический раздел** — требует доработки при реализации.

Тайл хранит `currentQiDensity` — текущую концентрацию Ци в окружающей среде. Эта Ци — ресурс для поглощения практиками через медитацию.

**Две разные модели регенерации Ци:**
1. **Практик (субъект):** `qiRegen = 10% coreCapacity/сутки` — от микроядра (НЕ модифицируется баффами). См. `02_systems/QI_SYSTEM.md`.
2. **Тайл (поверхность):** Ци-фон в окружающей среде. Восстанавливается со временем; скорость зависит от биома, лей-линий, формаций.

**Ключевое различие:** регенерация Ци практика (микроядро) ≠ регенерация Ци на тайле (окружающая среда).

**Открытые вопросы:**
- Как восстанавливается `currentQiDensity` тайла после поглощения практика?
- Скорость восстановления: зависит от биома, лей-линий, формаций?
- Взаимосвязь с `environmentMult` (см. `02_systems/QI_SYSTEM.md`)?
- Баланс: сколько практиков могут медитировать в одном месте, прежде чем Ци иссякнет?

### 7.2 Влияние на геймплей

| Температура | Эффект | Механика |
|-------------|--------|----------|
| < −20°C | Обморожение | Урон/тик без защиты |
| −20..0°C | Холод | Замедление без одежды |
| 0..25°C | Комфорт | Нет эффектов |
| 25..35°C | Тепло | Повышенная жажда |

- Время суток (день/ночь)
- Сезон (тёплый/холодный) — `Season = warm | cold`
- Погода (туман, дождь)
- Техники (огонь, лёд)
- Здания (печь, камин)
- Магические аномалии

## 8. Вода

### 8.1 Типы воды

| Тип | Глубина | Проходимость | Особенности |
|-----|---------|--------------|-------------|
| Мелководье | 0–1 м | Да (×0.5) | Можно пить |

### 8.2 Параметры воды на тайле

- `hasWater`: bool — наличие воды
- `waterType`: enum — тип воды
- `waterDepth`: float — глубина в метрах

- `waterPurity`: float — чистота (0–1, влияет на питьё)
- `waterQiModifier`: float — модификатор Ци воды

## 9. Сводная структура данных тайла

> **TileData — ~20 полей.**

```
TileData
{
    // === КООРДИНАТЫ (3) ===
    int x;                    // 0..width-1
    int y;                    // 0..height-1
    int z;                    // Логический уровень высоты (−5..+5)

    // === ПОВЕРХНОСТЬ (2) ===
    TerrainType terrain;      // grass, dirt, stone, water, ...
    float moveCost;           // 0.0 = непроходимо, 1.0 = норма

    // === ОБЪЕКТЫ (3) ===
    List<TileObject> objects; // Объекты на тайле
    bool hasImpassableObject; // Быстрая проверка
    bool blocksVision;        // Блокировка видимости

    // === СУБЪЕКТЫ (2) ===
    List<EntityRef> entities; // Ссылки на субъекты
    int entityCount;          // Количество субъектов

    // === ЦИ (3) ===
    int baseQiDensity;        // Базовая плотность
    int currentQiDensity;     // Текущая (с модификаторами)
    float qiModifier;         // Активный модификатор

    // === ТЕМПЕРАТУРА (3) ===
    float baseTemperature;    // Базовая температура
    float currentTemperature; // Текущая (с модификаторами)
    float tempModifier;       // Временный модификатор

    // === ВОДА (4) ===
    bool hasWater;            // Наличие воды
    WaterType waterType;      // Тип воды
    float waterDepth;         // Глубина
    float waterPurity;        // Чистота

    // === ФЛАГИ (4) ===
    bool isExplored;          // Исследован игроком
    bool isVisible;           // Сейчас в поле зрения
    bool hasPOI;              // Точка интереса
    bool isDangerZone;        // Зона опасности
}
```

Всего ~24 поля. Часть из них (флаги, импассабельность, видимость) — вычисляемые или кэшируемые для производительности. Атомарные данные для сохранения — координаты, surface, Ци/температура, объекты (только дельта).

## 10. Генерация тайлов локации

### 10.1 Алгоритм

```
ВХОДНЫЕ ДАННЫЕ:
├── seed: int — сид генерации
├── sectorData: SectorData — данные сектора с карты мира
├── locationType: LocationType — тип локации
└── playerLevel: int — уровень игрока

ШАГ 1: Инициализация
├── Создать сетку тайлов (ширина/2 × высота/2)
│   // Размер локации в метрах / 2 = количество тайлов
├── Установить базовые параметры из sectorData
└── Инициализировать все тайлы как «пустые»

ШАГ 2: Генерация ландшафта
├── Применить Perlin Noise для высот
```

### 10.2 Детерминированность

Генерация детерминирована: один и тот же `seed` + те же входные параметры всегда дают одинаковый результат. Это позволяет не сохранять тайлы индивидуально — достаточно хранить `seed` + дельту изменений (см. `WORLD_SAVE_SYSTEM.md`).

## 11. Взаимодействие с тайлами

### 11.1 События тайла

| Событие | Описание | Обработчик |
|---------|----------|------------|
| `OnEnter` | Сущность входит в тайл | Проверка ловушек, триггеров |
| `OnExit` | Сущность выходит из тайла | Отмена эффектов |
| `OnChange` | Изменение тайла | Обновление навигации |
| `OnInteract` | Взаимодействие | Открытие, сбор, активация |

### 11.2 Действия игрока

- **Перемещение:** проверка проходимости → расчёт стоимости движения → обновление позиции.
- **Взаимодействие:** клик на тайл → показ доступных действий → проверка дистанции → выполнение.
- **Инспекция:** показ информации о тайле (Ци, температура), подсветка объектов и субъектов.

### 11.3 Движение и тики

Перемещение на 1 клетку занимает **1 тик** (= 1 игровую минуту). Подробнее — в `TIME_SYSTEM.md`.

## 12. Сохранение тайлов

> Подробнее — в `WORLD_SAVE_SYSTEM.md`.

**Принципы:**
- сохраняются только **изменённые** тайлы (delta);
- стандартные тайлы генерируются из seed;
- сжатие повторяющихся паттернов;
- только уникальные данные.

**Формат (JSON):**
```json
{
  "locationId": "loc_001",
  "seed": 123456789,
  "modifiedTiles": [
    { "x": 5, "y": 3, "changes": { "terrain": "dirt" } },
    { "x": 7, "y": 2, "changes": { "qiDensity": 150 } }
  ]
}
```

### 12.1 Техники оптимизации

| Техника | Описание | Применение |
|---------|----------|------------|
| **Delta Compression** | Сохранение только изменений | Уменьшение размера |
| **LOD (Level of Detail)** | Упрощение далёких тайлов | Визуализация |
| **Chunking** | Группировка тайлов в чанки | Загрузка/выгрузка |
| **Pooling** | Переиспользование объектов | Производительность |

## 13. Система свободного строительства

> **Концепция:** дома собираются из отдельных элементов (стены, окна, двери) и являются частью основной локации, а не отдельными подлокациями.

### 13.1 Подход

**Традиционный (НЕ используется):** дом = отдельная локация → вход → загрузка новой сцены.

**Используемый подход:** дом = набор строительных элементов в основной локации.
- Стены, окна, двери — объекты на тайлах.
- Мебель, декор — объекты на тайлах.
- Без загрузочных экранов.
- Виден извне, можно заглянуть в окно.

## 14. Принципы тайловой системы

1. **Тайл = 2 × 2 м.** Единый стандарт проекта. Не меняется.
2. **4 логических слоя** на каждом тайле. Слои независимы, агрегируются при отображении.
3. **Z — логический уровень, не 3D-координата.** Диапазон −5 … +5.
4. **Orthographic top-down** (НЕ изометрия). Y-сортировка для перекрытия.
5. **Многоячеечные объекты** — от 1×1 до 4×4+ тайлов. Игрок = 1 тайл, дракон = 4+ тайлов.
6. **Генерация детерминирована** (seed + параметры). Тайлы не сохраняются индивидуально — только дельта.
7. **Свободное строительство** — дома собираются из элементов прямо в локации, без подлокаций.

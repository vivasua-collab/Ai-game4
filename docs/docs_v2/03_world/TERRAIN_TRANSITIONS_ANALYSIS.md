# Анализ: плавные переходы ландшафта — выбор направления

> **Дата:** 2026-08-16
> **Статус:** Решение принято
> **Источники:** Heroes 3 screenshot, Habr article, Unity code2d series, Godot docs

---

## 1. Постановка проблемы

Текущее состояние:
- **Страта 0 (биом):** квадратные цветные тайлы (MultiMesh)
- **Страта 1 (поверхность):** отключена (transition tiles давали артефакты)
- **Переходы:** резкие квадратные границы между типами

Цель: **плавные переходы** как в Heroes 3 (pre-rendered edge sprites).

---

## 2. Анализ подходов

### Подход A: Программная генерация переходов (текущий — ОТКЛОНЁН)

Что пробовали:
- `TransitionTileRenderer` — quarter-circle overlays через `_Draw()` → `DrawColoredPolygon`
- `TransitionSpriteGenerator` — quarter-circle PNG через `Image.SetPixel`

**Проблемы:**
- Артефакты рендеринга (неправильные углы, повороты)
- Сложность отладки — код рисования в рантайме
- Нет поддержки 3-биомных пересечений
- Невозможно создать качественные текстуры программно

**Вердикт:** ❌ Отклонён. Не делаем одно и то же множество раз.

### Подход B: Godot TileSet Terrains (нативный autotiling)

**Как работает:**
- Godot 4.7 имеет встроенную систему TileSet Terrains
- Connect mode — для переходов между типами
- Автоматический подбор тайлов по соседям (peering masks)
- 47 уникальных тайлов на terrain тип (полный autotile набор)

**Плюсы:**
- Нативная интеграция с Godot
- Визуальный редактор TileSet в Godot Editor
- Автоматический autotiling — не нужно писать код переходов
- Поддержка collision, navigation, custom data

**Минусы:**
- Требует создания/импорта текстур тайлов (PNG)
- TileSet настраивается в Godot Editor (не через код)
- Нужно создать TileSet ресурс вручную

**Вердикт:** ✅ Правильный конечный путь, но требует текстуры.

### Подход C: Готовые спрайты переходов на страте 1 (ВЫБРАН)

**Как работает:**
- Страта 0 (биом) — остаётся квадратной (MultiMesh с цветами)
- Страта 1 (поверхность) — тайлы с pre-made transition спрайтами
- 8 направлений перехода на пару биомов (4 прямых + 4 диагональных)
- Приоритет наложения: на тайле "низшего" биома рисуется спрайт "высшего"

**Плюсы:**
- Простота: страта 0 не трогается
- Гибкость: спрайты можно заменять на качественные позже
- Контроль: явные правила приоритета для каждой пары
- Совместимость с автогенерацией: избежать 4+ биомов в одной клетке

**Минусы:**
- Нужно создать/сгенерировать спрайты (пока процедурные)
- 8 спрайтов × N пар = много файлов
- 3-биомные пересечения требуют специальных спрайтов

**Вердикт:** ✅ **ВЫБРАН.** Лучший баланс простоты и качества.

## 3. Решение

### Принцип

```
Страта 0 (биом):     квадратные цвета, БЕЗ переходов
Страта 1 (поверхность): transition спрайты, 8 направлений
```

### 3.1. 8 направлений перехода

Для каждой пары биомов (A → B) нужно 8 спрайтов:

| # | Направление | Описание | Тип |
|---|-------------|----------|-----|
| 1 | N (север) | B сверху, A снизу | Прямой |
| 2 | S (юг) | B снизу, A сверху | Прямой |
| 3 | E (восток) | B справа, A слева | Прямой |
| 4 | W (запад) | B слева, A справа | Прямой |
| 5 | NW (с-з) | B в верх-левом углу | Диагональ |
| 6 | NE (с-в) | B в верх-правом углу | Диагональ |
| 7 | SW (ю-з) | B в ниж-левом углу | Диагональ |
| 8 | SE (ю-в) | B в ниж-правом углу | Диагональ |

### 3.2. Приоритет наложения

**Правило:** спрайт перехода рисуется на тайле **низшего** биома.

**Иерархия биомов (от высшего к низшему):**
```
Peak > Mountains > Highlands > Forest > Grassland > Steppe > Coast > Sea > Ocean
```

**Пример:** граница Grassland и Sea:
- Sea ниже Grassland → спрайт перехода рисуется на тайле Sea
- На тайле Sea будет "береговой" спрайт с краем травы

**Пример:** граница Mountains и Grassland:
- Grassland ниже Mountains → спрайт на тайле Grassland
- На тайле Grassland будет "подножие горы" спрайт

### 3.3. Пары биомов (обновлённый список)

10 приоритетных пар, 8 спрайтов на пару = **80 спрайтов**:

| # | Биом A (base) | Биом B (overlay) | Приоритет | Описание |
|---|---------------|-------------------|-----------|----------|
| 1 | Ocean | Sea | Sea → Ocean | Глубина |
| 2 | Sea | Coast | Coast → Sea | Отмель |
| 3 | Coast | Grassland | Grassland → Coast | Берег |
| 4 | Grassland | Steppe | Steppe → Grassland | Степь |
| 5 | Grassland | Forest | Forest → Grassland | Лес |
| 6 | Grassland | Highlands | Highlands → Grassland | Нагорье |
| 7 | Highlands | Mountains | Mountains → Highlands | Горы |
| 8 | Mountains | Peak | Peak → Mountains | Вершины |
| 9 | Steppe | Highlands | Highlands → Steppe | Степь→горы |
| 10 | Forest | Highlands | Highlands → Forest | Лес→горы |

### 3.4. 3-биомные пересечения

**Правило:** при генерации избегать 4+ биомов в одной клетке.

**3-биомный угол:** если 3 биома встречаются в одном тайле:
- Использовать спрайт "тройного перехода" (комбинация 2-х диагональных)
- Или: рисовать спрайт высшего биома поверх (упрощение)
- Пока: **избегать через cellular automata smoothing** (уже делаем)

### 3.5. Алгоритм "посадки" спрайта

Для каждого тайла (x, y) на страте 1:
1. Определить биом текущего тайла (Biome)
2. Для каждого из 8 соседей:
   - Если биом соседа отличается → это граница
   - Определить пару (current, neighbor)
   - Определить приоритет: чей спрайт рисовать
3. Если приоритет у текущего тайла → загрузить спрайт перехода
4. Отрисовать спрайт на текущем тайле

## 5. План реализации

### Фаза 1: Обновить генерацию (сейчас)
- Cellular automata smoothing для избегания 3+ биомных пересечений
- Добавить проверку: если 4+ биома в тайле → упростить до 2-х

### Фаза 2: Создать transition спрайты
- 80 спрайтов (10 пар × 8 направлений)
- Пока процедурные (через Image), потом — качественные PNG
- Структура: `resources/tile_transitions/{pair}_{direction}.png`

### Фаза 3: Transition renderer для страты 1
- Новый `SurfaceTransitionRenderer` (Node2D с `_Draw()`)
- Читает страту 1 (surface) из TileService
- Для каждого тайла проверяет 8 соседей
- Загружает и отрисовывает transition спрайты по приоритету

### Фаза 4: Будущее — Godot TileSet Terrains
- Когда будут качественные текстуры тайлов
- Создать TileSet ресурс в Godot Editor
- Настроить TerrainSet с peering masks
- Заменить MultiMesh + Sprite renderer на TileMapLayer.set_cell()

## 6. Вывод

**Выбран подход C:** готовые спрайты переходов на страте 1, страта 0 остаётся квадратной.

**Причины:**
1. Heroes 3 использует тот же подход (проверен временем)
2. Habr статья подтверждает: программные переходы сложны
3. Unity series использует rule tiles (аналог спрайтов переходов)
4. Проще реализовать, отладить и заменить на качественные текстуры позже
5. Совместимо с автогенерацией локаций
